## 학습 목표

- 양쪽 눈의 :용어[특징점]을 기준으로 중앙 좌표를 계산하고, 이를 전체 화면 좌표로 변환하는 매핑 시스템을 구현할 수 있다.
- 웃음이나 입 벌림과 같은 표정을 조건으로 감지할 수 있다.
- PyAutoGUI :용어[라이브러리]를 활용하여 계산된 좌표를 바탕으로 마우스 커서를 실시간으로 이동시킬 수 있다.

## 1 시선으로 제어하는 커서

사용자가 모니터 화면을 바라보았을 때 해당 위치로 마우스가 이동할 수 있도록 만들기 위해 사람의 얼굴이 움직일 수 있는 범위와 모니터의 화면 크기 간의 비율을 맞추는 과정이 필요하다. 이때 기준이 되는 얼굴의 특정 부위를 선택해야 하며, 보통은 양쪽 눈의 중앙값이나 코의 위치를 기준으로 삼는다.

여기서 사용자의 얼굴 이동 범위에 맞추어 민감도를 조절하는 과정도 중요하다. 만약 얼굴을 조금만 움직여도 마우스가 화면 끝까지 가는 상황이 발생한다면, 사용자는 마우스를 정밀하게 조작하기 어려워진다. 이런 상황에서는 마우스의 이동을 일시적으로 제한하거나 정지시키는 기능을 추가해 사용자의 얼굴이 화면을 바라보고 있는 범위 내에서만 마우스가 반응하도록 설정하여 안정적인 제어를 할 수 있다.

이 기능은 PyAutoGUI 라이브러리를 사용하여 구현할 수 있어 이를 통해 얼굴의 위치 정보를 기반으로 마우스 커서를 실제 화면의 좌표로 이동시킬 수 있다.

## 2 시선으로 제어하는 커서 프로그램 개요

이 활동에서는 이전 차시의 최종 프로그램을 기반으로 기능을 확장한다. 얼굴 인식 기능이 포함된 웹캠 화면에서 사용자의 좌우 시선 이동 범위를 측정하고, 사용 중인 모니터의 :용어[해상도](가로·세로 크기)를 추출한다.

측정된 시선 이동 범위와 모니터 크기를 매핑(Mapping)하여, 얼굴을 움직이는 정도에 따라 마우스 커서가 화면 전체를 이동할 수 있도록 한다.

:::용어풀이[매핑(Mapping)]
두 개의 서로 다른 범위나 좌표계를 연결하여, 하나의 값을 다른 값으로 변환해 주는 과정을 말한다.
:::

얼굴의 움직임 범위는 작고, 모니터 화면은 상대적으로 크기 때문에 조금만 얼굴을 움직여도 커서가 과도하게 이동하는 문제가 발생할 수 있다. 이로 인해 사용자가 원하는 위치를 정확히 클릭하기 어려워지므로, 커서 이동 속도를 조절하거나 필터링을 적용해 움직임을 부드럽게 만들어야 한다.

## 4 시선으로 제어하는 커서 프로그램 기능과 사용자 인터페이스

화면 상단에는 얼굴의 각 부위 좌표 정보가 출력된다. 양쪽 눈(eye_L, eye_R)과 콧등(Nose)의 x, y 좌표가 실시간으로 갱신되며, 이를 기반으로 중앙 기준점(Nose_Control)이 계산되어 녹색 점으로 표시된다. 기준선(Pole)은 파란색 십자선으로 표시되어 현재 얼굴 위치와 기준 위치를 시각적으로 비교할 수 있다.

![프로그램 창 안에 안경을 쓴 사람이 정면을 보는 작은 웹캠 화면. 왼쪽 위에 눈과 코의 좌표를 알리는 글자가 보이고, 두 눈 사이에 초록 점과 파란 십자선이 그려져 있다](/images/lessons/4-1-2/ui-screen.webp "교과서 224쪽")

얼굴의 이동 범위와 모니터 화면 크기를 고려하여 마우스 커서가 매핑되며, 움직임은 너무 빠르거나 튀지 않도록 부드럽게 조정되어 사용자가 원하는 위치를 보다 정밀하게 선택할 수 있도록 한다. 사용자의 얼굴이 중앙을 기준으로 좌우로 움직이면 마우스 커서가 자연스럽게 화면 전체를 따라다닌다.

## 심화 실습 | 시선으로 제어하는 커서 프로그램 만들기

사용자의 얼굴에서 눈과 콧등의 위치를 실시간으로 추적하여, 마치 시선이 가는 방향으로 마우스 커서가 자동으로 따라다니는 기능을 구현해 보자.

얼굴의 정중앙에 가까운 콧등과 양쪽 눈 사이의 중간 지점을 기준 좌표로 삼고, 이 좌표를 사용 중인 컴퓨터 화면의 마우스 위치와 연결(Mapping)하여 동작한다.

초기 실행 시 일정 시간 동안 얼굴 위치 정보를 수집하여 기준점을 설정하고, 이 기준점에서 좌우로 이동한 정도에 따라 마우스가 화면 안에서 이동하도록 한다. 이때 사용자의 얼굴 이동 범위는 작지만, 화면 전체를 마우스가 움직일 수 있도록 비율을 조정해 주어야 한다. 또한 화면 끝까지 고개를 돌리는 상황에서는 사용자가 화면을 주시하지 못하기 때문에, 얼굴이 화면 밖을 벗어나지 않도록 제어 범위를 제한하는 기능도 함께 적용된다.

**마우스 커서 제어를 위한 좌표 매핑 알고리즘**

**❶ 중앙 좌표 계산**

- 양쪽 눈(예: 468번, 473번) 위치의 평균값과 콧등(6번) 좌표를 활용하여 기준점 계산
- :용어[정규화된 좌표](x, y)를 이미지 크기(px)로 변환하여 사용

**❷ 모니터 크기와 매핑**

- 사용자의 얼굴 이동 범위를 기준으로 마우스가 이동할 수 있는 화면 비율 계산
- 사용 중인 PC의 해상도(모니터 너비·높이)를 자동 감지하여 적용

**❸ 민감도 및 범위 제한 설정**

- 얼굴의 작은 움직임에도 마우스가 화면 전체를 이동할 수 있도록 민감도 조절
- 일정 각도 이상 고개가 돌아갔을 때는 마우스 이동을 제한하여 오작동 방지

:::학습활동[시선으로 제어하는 커서 프로그램 확장하기]
완성한 시선으로 제어하는 커서 프로그램을 기반으로, 마우스 제어의 정확성·안정성·활용성을 높이기 위해 프로그램을 확장해 보자.

1. 기준점 설정이 없는 경우 마우스 커서가 어떻게 반응하는지 살펴보고, 기준점의 역할을 설명해 보자.

   예 기준점이 없으면 초기 얼굴 위치가 화면 중심이 아닌 방향으로 치우침

2. 데드존(Deadzone)을 적용해 작은 얼굴 움직임은 무시되도록 설정하고, 적용 전과 후의 마우스 움직임을 비교해 보자. 여기서 데드존은 센서나 입력 장치에서 감지되는 아주 작은 움직임이나 노이즈를 무시하기 위해 설정되는 범위로 이 영역 안의 움직임은 변화로 인식되지 않는다.

   예 3픽셀 이하 움직임 무시

3. 이전 좌표와 현재 좌표를 혼합해 커서가 부드럽게 이동하도록 스무딩(Smoothing) 알고리즘을 적용해 보자. 여기서 스무딩은 급격한 마우스의 움직임을 부드럽게 만드는 기능을 말한다.

   예 새 위치 = 이전 위치 × 0.7 + 현재 위치 × 0.3

4. 데드존과 스무딩을 동시에 적용한 경우, 커서 움직임이 어떻게 달라지는지 분석해 보자.

   예 민감도, 부드러움, 반응성 측면에서 각각 비교한다.
:::
