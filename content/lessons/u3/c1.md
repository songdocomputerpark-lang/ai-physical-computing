## 학습목표

- 보드가 와이파이로 인터넷에 붙어, 중계 서버를 거쳐 멀리 있는 기기와 메시지를 주고받는 방법을 설명할 수 있어요.
- 토픽을 정해 메시지를 보내고(발행) 받는(구독) MQTT 코드를 읽고 실행할 수 있어요.
- 공개 중계 서버를 쓸 때 지킬 안전 규칙(개인정보 금지, 통신 접두어, 허용 목록)을 말할 수 있어요.

## 왜 배울까

3-1-2의 시리얼 통신은 선이 닿는 곳까지, 3-1-3의 블루투스는 가까운 거리에서만 통해요. 옆 교실 친구의 보드나 집에 있는 스마트 전구처럼 멀리 있는 기기와 주고받으려면 인터넷을 거쳐야 해요. MQTT는 작은 기기들이 인터넷에서 짧은 메시지를 주고받도록 정한 약속이에요.

## 핵심 개념

### 와이파이 — 보드를 인터넷에 붙이기

보드가 인터넷을 쓰려면 먼저 교실의 와이파이 공유기에 붙어야 해요. MicroPython에서는 `network` 모듈로 이렇게 해요.

| 코드 | 하는 일 |
| --- | --- |
| `wlan = network.WLAN(network.STA_IF)` | 보드의 와이파이를 준비해요. `STA_IF`는 "공유기에 붙는 쪽"이라는 뜻이에요. |
| `wlan.active(True)` | 와이파이를 켜요. |
| `wlan.connect("이름", "비밀번호")` | 공유기에 연결을 시작해요. 곧바로 붙지는 않아요. |
| `wlan.isconnected()` | 연결이 끝났으면 `True`를 돌려줘요. 그래서 `True`가 될 때까지 기다린 뒤 다음 일을 해요. |

가상 보드는 와이파이 이름과 비밀번호가 무엇이든 0.5초쯤 기다리면 연결돼요. 실제 보드는 교실 와이파이의 이름과 비밀번호가 맞아야 해요. 편집칸의 코드는 이 컴퓨터에 저절로 저장되니, 실제 비밀번호를 적었으면 수업이 끝날 때 [이 컴퓨터에서 내 기록 지우기]를 눌러요.

### MQTT — 중계 서버, 토픽, 발행과 구독

:용어[MQTT]는 기기끼리 선을 직접 잇지 않고, 가운데의 :용어[중계 서버](브로커, broker)를 거쳐 메시지를 주고받는 방법이에요. 메시지에는 :용어[토픽](topic)이라는 이름표를 붙여요. 토픽은 `esp32-01/tx`처럼 빗금(`/`)으로 나눠 적는, 주소 같은 이름이에요.

- :용어[발행](publish): 토픽을 붙여 중계 서버로 메시지를 보내는 일이에요.
- :용어[구독](subscribe): 중계 서버에 "이 토픽의 메시지를 나에게 전해 줘"라고 알려 두는 일이에요.

좋아하는 동영상 채널을 구독해 두면 새 영상이 올라올 때마다 알림이 오는 것과 비슷해요. 채널 이름이 토픽이고, 영상을 올리는 쪽이 발행하는 쪽이에요.

<figure>
<img src="/images/lessons/c1/pubsub.svg" alt="보드 A가 esp32-01/tx 토픽으로 1, 2, 3을 보내면(발행) 가운데 중계 서버가 그 토픽을 구독한 보드 B와 대시보드에만 전하고, esp32-05/tx만 구독한 보드 C에는 오지 않는 그림" width="640" height="390">
<figcaption>보내는 쪽은 받는 쪽이 누구인지 몰라도 돼요. 토픽만 맞으면 중계 서버가 전해 줘요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

보드에서는 `umqtt.simple` 모듈의 `MQTTClient`를 써요.

| 코드 | 하는 일 |
| --- | --- |
| `client = MQTTClient("esp32-01", 중계 서버 주소)` | 이 보드의 이름으로 중계 서버와 이야기할 준비를 해요. |
| `client.set_callback(on_message)` | 메시지가 오면 부를 함수를 정해요. |
| `client.connect()` | 중계 서버에 연결해요. |
| `client.subscribe(토픽)` | 이 토픽의 메시지를 받기로 해요(구독). |
| `client.publish(토픽, 글)` | 이 토픽으로 글을 보내요(발행). |
| `client.check_msg()` | 온 메시지가 있으면 정해 둔 함수를 불러요. 없으면 그냥 지나가요. |

### 토픽 이름과 통신 접두어

토픽은 보내는 쪽과 받는 쪽이 정한 약속이라, 한 글자라도 다르면 메시지가 닿지 않아요. 이 사이트는 `esp32-01/tx`(보드가 보냄), `esp32-01/rx`(보드가 받음)처럼 보드 번호와 방향으로 이름을 지어요. 보드 번호에는 이름이나 학번 대신 자리 번호를 써요. `esp32-01/#`처럼 `#`을 쓰면 `esp32-01/` 아래의 토픽을 모두 받아요.

공개 중계 서버는 온 세상이 함께 쓰는 곳이라, 다른 학교도 `esp32-01/tx`를 쓸 수 있어요. 그래서 토픽 앞에 무작위 12글자로 된 :용어[통신 접두어]를 붙여 우리 반 메시지를 가려요.

<figure>
<img src="/images/lessons/c1/topic-prefix.svg" alt="토픽 7kq2m9xd4hpt/esp32-01/tx를 세 부분으로 나눈 그림. 7kq2m9xd4hpt는 통신 접두어(무작위 12글자), esp32-01은 보드 번호(이름이나 학번 대신), tx는 보드가 보냄이고 rx는 보드가 받음이다. 코드에는 esp32-01/tx처럼 짧게 적고, 가상 보드는 사이트가 접두어를 앞에 붙여 주며, 실제 보드는 코드의 PREFIX 줄에 직접 적는다" width="640" height="246">
<figcaption>접두어는 우연히 섞이지 않게 할 뿐 비밀번호가 아니에요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

코드에는 `esp32-01/tx`처럼 짧게 적어요. 가상 보드는 ESP32 실습실의 MQTT 칸에 보이는 접두어를 사이트가 앞에 붙여 줘요. 실제 보드는 스스로 붙이지 못하니, MQTT 칸의 [코드에 접두어 적기]를 눌러 코드의 `PREFIX = ""` 줄을 채워요. 접두어가 비어 있는 MQTT 코드는 사이트가 실제 보드로 보내지 않아요.

### 공개 중계 서버를 쓰는 규칙

:::주의[공개 중계 서버는 누구나 보고, 누구나 보낼 수 있어요]
- 이름, 연락처, 사진 같은 개인정보를 보내지 않아요.
- 받은 명령으로는 LED, LCD 같은 표시 장치만 움직여요. 레이저나 모터처럼 움직이는 장치는 잇지 않아요.
- 받는 쪽은 길이와 허용 목록을 먼저 확인하고, 약속하지 않은 메시지는 무시해요.
:::

공개 중계 서버는 비밀번호 없이 누구나 붙을 수 있어서, 우리 토픽 이름을 아는 사람이면 누구든 메시지를 보낼 수 있어요. 그래서 받는 쪽 코드가 먼저 걸러야 해요. 보드 A 코드의 `command_of()` 함수가 이 일을 해요.

<img src="/images/lessons/c1/safety-gate.svg" alt="on, laser-on, 21바이트가 넘는 긴 글 세 메시지가 받는 쪽 검사 상자로 들어가, 1 길이 20바이트 이하인지, 2 글자로 바꿀 수 있는지, 3 허용 목록(on, off, blink)에 있는지를 차례로 본 뒤, 모두 통과한 on만 LED를 켜고 끄고 나머지는 무시하고 콘솔에 적는 그림. 아래에 레이저, 모터처럼 움직이는 장치는 공개 중계 서버에서 받는 코드에 잇지 않는다고 적혀 있다" width="640" height="316">
<figcaption>받는 쪽의 세 가지 검사예요. 하나라도 걸리면 무시해요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

ESP32 실습실의 MQTT 칸에서 통로를 골라요. 학교망이 공개 중계 서버를 막아도 같은 컴퓨터 탭 통로로는 실습을 끝까지 할 수 있어요.

| 통로 | 뜻 | 언제 쓸까 |
| --- | --- | --- |
| 같은 컴퓨터 탭(기본) | 이 컴퓨터의 다른 탭과 같은 페이지 안의 실습실끼리만 통해요. 인터넷이 없어도 되고, 주고받는 글이 컴퓨터 밖으로 나가지 않아요. | 수업에서 먼저 써요. 학교망이 막혀도 돼요. |
| 공개 중계 서버 | 인터넷의 공개 중계 서버(예: EMQX)를 거쳐요. 다른 컴퓨터와도 통해요. | 선생님과 함께 친구 컴퓨터와 이어 볼 때 써요. |
| 중계 서버 먼저, 안 되면 탭 | 공개 중계 서버에 먼저 붙어 보고, 막히면 같은 컴퓨터 탭으로 바꾸고 알려 줘요. | 학교망이 되는지 모를 때 써요. |

### 코드 읽기 — 보드 A(통신 템플릿 3)

- 5\~8번 줄: 와이파이(`network`), MQTT(`MQTTClient`), 핀(`Pin`), 기다리기(`sleep`)를 불러와요.
- 10\~23번 줄: 설정이에요. 보드 번호 `DEVICE`는 `esp32-01`이고, 받는 토픽은 `esp32-01/rx`, 보내는 토픽은 `esp32-01/tx`예요. `ALLOW`는 받아 줄 명령 목록(`on`, `off`, `blink`)이에요.
- 29\~39번 줄: `command_of()`가 받은 메시지를 검사해요. 20바이트보다 길거나, 글자로 바꿀 수 없거나, 허용 목록에 없으면 빈 글자를 돌려줘요.
- 42\~50번 줄: `on_message()`는 구독한 토픽에 메시지가 오면 불려요. 검사를 통과한 명령만 `command`에 담아요.
- 53\~66번 줄: 와이파이에 연결하고 최대 10초 기다려요.
- 68\~72번 줄: 중계 서버에 연결하고, 메시지가 오면 부를 함수를 정하고, `esp32-01/rx`를 구독해요.
- 75\~85번 줄: 반복하며 온 메시지를 확인하고, 명령대로 LED(GPIO2)를 켜거나 끄거나 깜빡이고, 센 숫자를 `esp32-01/tx`로 보낸 뒤 1초 쉬어요.

### 코드 읽기 — 보드 B(친구 보드)

- 14\~19번 줄: 내 보드 번호는 `esp32-02`, 친구 보드는 `esp32-01`이에요. 친구 보드가 명령을 받는 토픽(`esp32-01/rx`)으로 보내고, 친구 보드가 값을 보내는 토픽(`esp32-01/tx`)을 받아요.
- 21번 줄: GPIO17의 터치 센서예요. 누르고 있는 동안 1이에요.
- 26\~28번 줄: 구독한 토픽에 메시지가 오면 받은 값을 콘솔에 적어요. 받은 값은 바이트라서 `decode()`로 글자로 바꿔요.
- 31\~36번 줄: 와이파이에 연결될 때까지 기다려요.
- 38\~42번 줄: 중계 서버에 연결하고 `esp32-01/tx`를 구독해요.
- 44\~53번 줄: 손가락이 닿는 순간에만 `on`과 `off`를 번갈아 친구 보드에 보내요(발행).

::예제

### 실행하고 결과 보기

1. 두 예제의 [이 자리에서 실습실 열기]를 모두 눌러요. 한 페이지 안에 연 두 실습실은 통신 접두어가 저절로 같아요. 두 실습실의 MQTT 칸에 보이는 "통신 접두어"가 같은지 확인해요.
2. 보드 A(첫째 예제)의 [실행]을 눌러요. 콘솔에 `와이파이 연결: True`, `MQTT 연결됨: esp32-01/tx`가 나오고, MQTT 칸의 "주고받은 기록"에 `보냄 …/esp32-01/tx ← 1`처럼 1초마다 한 줄씩 늘어나요.
3. 보드 B(둘째 예제)의 [실행]을 눌러요. 콘솔에 친구 보드가 보낸 숫자가 1초마다 찍혀요.
4. 보드 B의 보드 그림 아래 터치 센서를 한 번 눌러요. 보드 A의 LED(IO2)가 켜지고, 한 번 더 누르면 꺼져요.

보드 B의 콘솔에는 이렇게 나와요(숫자는 보드 A를 실행한 때에 따라 달라요).

```text
와이파이 연결: True
받기로 한 토픽: esp32-01/tx
친구 보드가 보낸 값: 4
친구 보드가 보낸 값: 5
보냄: esp32-01/rx on
친구 보드가 보낸 값: 6
보냄: esp32-01/rx off
```

보드 A의 콘솔에는 `받음: on`, `받음: off`가 나와요. 새 탭에서 따로 열었다면 한 탭의 MQTT 칸에서 통신 접두어를 [복사]하고, 다른 탭의 [친구 접두어]에 붙여 넣은 뒤 [맞추기]를 눌러요.

:::확인
- 두 실습실의 통신 접두어가 같아요.
- 보드 B의 콘솔에 `친구 보드가 보낸 값`이 1초마다 늘어나요.
- 보드 B의 터치 센서를 누를 때마다 보드 A의 LED가 켜졌다 꺼져요.
:::

:::왜그럴까
두 보드는 서로 직접 잇지 않았어요. 보드 A는 `esp32-01/tx`로 보내고 `esp32-01/rx`를 구독했고, 보드 B는 `esp32-01/tx`를 구독하고 `esp32-01/rx`로 보냈어요. 중계 서버(여기서는 같은 컴퓨터 탭 통로)는 토픽이 맞는 쪽에만 전해 주므로, 보드 A의 숫자는 보드 B로, 보드 B의 명령은 보드 A로 가요.
:::

:::왜그럴까[보드 B는 왜 누르는 순간에만 보낼까?]
47번 줄의 조건은 "지금은 눌렀고, 바로 앞 차례에는 안 눌렀다"예요. 손가락을 대고 있는 동안에는 `was_pressed`가 이미 참이라 다시 보내지 않아요. 이 조건이 없으면 누르고 있는 0.05초마다 명령을 보내서 LED가 켜졌다 꺼졌다를 되풀이하고, 공개 중계 서버에도 쓸데없는 메시지가 쌓여요.
:::

## 바꿔보기

:::바꿔보기
1. 보드 A 22번 줄의 `ALLOW`에서 `"on"`을 빼고 [실행]한 뒤, 보드 B의 터치 센서를 눌러 보세요. 보드 A의 콘솔에 무엇이 나오나요?
2. 보드 B 16번 줄의 `FRIEND`를 `"esp32-03"`으로 바꿔 [실행]해 보세요. 숫자가 오나요? 터치 센서를 누르면 보드 A의 LED가 켜지나요?
3. 보드 B 19번 줄을 `TOPIC_VALUE = BASE + "/#"`로 바꿔 [실행]하고 터치 센서를 눌러 보세요. 보드 B의 콘솔에 무엇이 더 나오나요?
:::

:::왜그럴까[허용 목록에서 빠진 명령은 왜 무시될까?]
`on`이 허용 목록에 없으면 `command_of()`가 빈 글자를 돌려줘요. 그래서 보드 A는 `무시했어요(허용 목록에 없거나 너무 긴 메시지): b'on'`만 적고 LED를 켜지 않아요. 토픽을 아는 누군가가 엉뚱한 명령을 보내도 보드가 움직이지 않게 하는 장치예요.
:::

:::왜그럴까[esp32-03으로 바꾸면 왜 아무것도 오지 않을까?]
보드 B가 `esp32-03/tx`를 구독하고 `esp32-03/rx`로 보내게 되었어요. 그 토픽을 쓰는 보드가 없으니 숫자가 오지 않고, 보드 A는 `esp32-03/rx`를 구독하지 않았으니 명령도 받지 못해요. 토픽이 한 글자라도 다르면 메시지가 닿지 않아요.
:::

:::왜그럴까[#을 쓰면 왜 내가 보낸 명령까지 보일까?]
`esp32-01/#`는 `esp32-01/` 아래의 토픽을 모두 받는다는 뜻이에요. 보드 B가 `esp32-01/rx`로 보낸 `on`, `off`도 그 아래에 있으니, 보드 B가 자기가 보낸 명령까지 받아서 `친구 보드가 보낸 값: on`처럼 찍어요.
:::

:::오류
- 보드 B의 39번 줄 `client.set_callback(on_message)`를 지우고 실행하면, 구독하는 줄(`client.subscribe(TOPIC_VALUE)`)에서 `AssertionError: Subscribe callback is not set`이 나요. 받을 함수를 정하기 전에 구독했기 때문이에요([오류 사전](/help/errors/#comm-mqtt-callback-missing)).
- 보드 B의 34\~35번 줄(와이파이 기다리기)을 지우면 `와이파이 연결: False`가 찍히고, 중계 서버에 붙는 줄(`client.connect()`)에서 `OSError`가 나요. 와이파이가 연결되기 전에 중계 서버에 붙으려 했기 때문이에요([오류 사전](/help/errors/#comm-wifi-not-connected-yet)).
- 통로를 "공개 중계 서버"로 골랐는데 연결하지 못했다고 나오면 학교망이 막았을 수 있어요. 통로를 "같은 컴퓨터 탭"으로 바꾸거나, [학교 네트워크 점검](/start/check/)에서 확인해요([오류 사전](/help/errors/#comm-mqtt-connect-failed)).
:::

## 도전 과제

::::도전[도전 과제 1: 서로의 LED를 켜는 두 보드]
지금은 보드 B만 보드 A에 명령을 보내요. 보드 A에도 터치 센서를 달아, 두 보드가 서로의 LED를 켜고 끄게 만들어 보세요. 친구와 짝을 지어 한 사람은 보드 A, 한 사람은 보드 B를 맡아도 좋아요.

| 정할 것 | 생각할 내용 |
| --- | --- |
| 보드 B가 받을 토픽 | 보드 A가 보드 B에 보낼 명령의 토픽은 무엇으로 할까요? |
| 보드 B의 LED | 받은 명령으로 켤 보드 B의 LED는 몇 번 핀일까요? |
| 허용 목록 | 보드 B는 어떤 명령만 받아 줄까요? |

:::힌트
보드 B도 `esp32-02/rx`를 구독하고, 보드 A는 터치하면 `esp32-02/rx`로 `on`, `off`를 보내게 해요. 보드 B의 `on_message()`에 보드 A 코드의 `command_of()`와 같은 검사를 넣고, 통과한 명령으로 `Pin(2, Pin.OUT)`의 LED를 켜고 꺼요. 보드 A에 터치 센서를 쓰려면 코드 맨 위에 `# @part touch-digital 17`을 적고, 보드 B의 44\~53번 줄처럼 누르는 순간을 찾아요.
:::
::::

::::도전[도전 과제 2: 공개 중계 서버로 친구 컴퓨터와 잇기]
선생님과 함께, 옆자리 친구의 컴퓨터와 공개 중계 서버로 이어 보세요. 두 컴퓨터 모두 MQTT 칸의 통로를 "공개 중계 서버"로 고르고, 한 사람의 통신 접두어를 다른 사람의 [친구 접두어]에 넣어 맞춘 뒤 각자 보드 A와 보드 B를 실행해요.

:::힌트
통로를 "공개 중계 서버"로 고르면 MQTT 칸에 "누구나 보고 보낼 수 있어요" 경고가 늘 보여요. 이름이나 연락처는 절대 보내지 않고, LED만 켜고 꺼요. 연결하지 못하면 학교망이 막은 것일 수 있으니 [학교 네트워크 점검](/start/check/)에서 확인하고, 안 되면 같은 컴퓨터 탭 통로로 돌아와요. 다 하면 [새로 만들기]로 접두어를 바꿔 두어요.
:::

## 교사용

:::교사용
### 지도안 요약(50분, 사이트가 제안하는 흐름)

1. 도입(5분): "왜 배울까" 그림으로 시리얼, 블루투스와 달리 멀리 있는 기기를 잇는 방법이 필요하다는 것을 짚어요.
2. 전개 1(12분): 와이파이 연결 코드, 중계 서버와 토픽, 발행과 구독을 그림으로 설명하고, 통신 접두어와 공개 중계 서버 규칙(주의 상자)을 함께 읽어요.
3. 전개 2(18분): 두 예제를 한 페이지에서 열어 보드 A → 보드 B 차례로 실행하고, 터치 센서로 보드 A의 LED를 켜 봐요.
4. 전개 3(10분): 바꿔보기 1\~3을 하며 허용 목록, 토픽 이름, `#`의 뜻을 확인해요.
5. 정리(5분): 확인 퀴즈를 풀고, 도전 과제 1을 짝 활동으로 안내해요.

### 평가 포인트

보충 차시라 원고의 자기 평가 문항이 없어요. 학습 목표를 자기 평가 문항으로 바꿔 쓸 수 있어요(사이트가 만든 문항).

- 와이파이와 MQTT로 멀리 있는 기기와 메시지를 주고받는 과정을 설명할 수 있는가?
- 토픽을 정해 발행하고 구독하는 코드를 읽고, 토픽이 맞아야 메시지가 닿는다는 것을 설명할 수 있는가?
- 공개 중계 서버에서 지킬 규칙(개인정보 금지, 표시 장치만, 허용 목록)을 말할 수 있는가?

관찰할 곳: 바꿔보기 2에서 "토픽이 달라서 안 온다"를 스스로 말하는지, 도전 과제 1에서 두 보드의 토픽을 겹치지 않게 짓는지 봐요. 과목 교육과정의 내용 요소 "와이파이 통신"과 이어져요(성취기준 연결은 PLAN §2.2).

### 자주 막히는 곳

- 두 탭에서 따로 열면 통신 접두어가 달라서 이어지지 않아요. 한 페이지의 [이 자리에서 실습실 열기] 두 개로 열거나, [친구 접두어]로 맞추게 해요.
- 보드 B만 먼저 실행하면 숫자가 오지 않아요. MQTT는 보낸 순간에 구독하고 있는 쪽에만 전해요(이 사이트는 지난 메시지를 남겨 두는 `retain`을 쓰지 않아요). 보드 A를 먼저 실행해요.
- 같은 컴퓨터 탭 통로는 같은 브라우저 안에서만 통해요. 다른 컴퓨터와 하려면 공개 중계 서버를 골라야 하고, 학교망이 막을 수 있어요(시작하기의 점검 페이지에서 확인).
- 실제 보드로 할 때는 코드의 `PREFIX` 줄을 MQTT 칸의 [코드에 접두어 적기]로 채워야 [실제 보드]에서 실행돼요. 와이파이 이름과 비밀번호도 교실 것으로 바꾸고, 수업 뒤 [이 컴퓨터에서 내 기록 지우기]를 누르게 해요.
- 실제 보드는 같은 컴퓨터 탭 통로를 쓰지 못하고, 코드에 적은 공개 중계 서버(`BROKER`)에 교실 와이파이로 직접 붙어요. 그래서 학교망이 그 중계 서버를 막으면 실제 보드끼리는 주고받지 못해요. 점검 페이지의 MQTT 항목은 브라우저가 붙는지만 보니, 보드가 붙는지는 수업 전에 실제 보드로 한 번 확인해 두세요(사이트는 실물로 아직 확인하지 않았어요).
- 공개 중계 서버로 받는 실제 보드에는 레이저, 팬, 서보처럼 움직이는 장치를 잇지 않아요. 누구나 메시지를 보낼 수 있기 때문이에요(PLAN §7.4).
- 보드 B 콘솔의 숫자가 1부터 시작하지 않아요. 보드 A가 먼저 보낸 숫자는 보드 B가 구독하기 전이라 받지 못해요.

### 이 차시를 둔 까닭

- 교과서와 수업 교안의 통신은 시리얼과 블루투스까지이고, 와이파이와 MQTT 코드는 자료에 없어요. 과목 교육과정의 내용 요소 "와이파이 통신"과 사이트의 통신 실습실(유선 → 블루투스 → 와이파이와 MQTT → 대시보드)을 잇기 위해 사이트가 새로 쓴 보충 차시예요.
- 보드 A는 통신 템플릿 3을 그대로 쓰고, 보드 B(친구 보드)는 이 차시를 위해 사이트가 새로 만든 예제예요.
:::
