## 학습목표

- 대시보드와 위젯(실시간 그래프, 게이지, 스위치, 텍스트 로그)이 무엇을 보여 주는지 설명할 수 있어요.
- 보드가 보낸 값을 대시보드에서 그래프로 보고, 스위치로 보드의 LED를 켜고 끌 수 있어요.
- 위젯의 토픽과 "값 번호"를 바꿔 원하는 값을 보이게 할 수 있어요.

## 왜 배울까

스마트 홈 앱에서는 방 온도를 그래프로 보고, 화면의 스위치를 눌러 멀리 있는 전등을 켤 수 있어요. 이렇게 여러 기기의 상태를 한 화면에 모아 보여 주고, 누르기 한 번으로 조종하게 해 주는 화면이 :용어[대시보드]예요. C1에서 배운 MQTT로 보드와 대시보드를 이어, 보드의 값을 보고 스위치로 보드를 움직여 봐요.

## 핵심 개념

### 대시보드와 위젯

대시보드는 :용어[위젯]이라는 작은 칸들로 이루어져요. 위젯마다 한 가지 일을 맡아요. 이 사이트의 [대시보드](/labs/iot/dashboard/)에는 위젯이 네 가지 있어요.

<figure>
<img src="/images/lessons/c2/widgets.svg" alt="위젯 카드 네 장. 실시간 그래프는 오르내리는 꺾은선으로 시간에 따른 값의 변화를, 게이지는 반달 눈금에 지금 값 80을 크게, 스위치는 켜짐 상태로 누르면 보드에 on, off를 보내고, 텍스트 로그는 tx → 75, rx ← on처럼 오고 간 글을 그대로 쌓는다. 아래에 그래프와 게이지는 받을 토픽 esp32-01/tx, 스위치는 보낼 토픽 esp32-01/rx, 텍스트 로그는 모든 토픽을 쓴다고 적혀 있다" width="640" height="294">
<figcaption>처음 대시보드에는 네 위젯이 하나씩 놓여 있어요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

| 위젯 | 하는 일 | 처음 정해진 토픽 |
| --- | --- | --- |
| 실시간 그래프 | 받은 숫자를 시간 차례대로 선으로 그려요. | 받을 토픽 `esp32-01/tx` |
| 게이지 | 지금 값 하나를 반달 눈금에 크게 보여 줘요. | 받을 토픽 `esp32-01/tx` |
| 스위치 | 누르면 보드에 켜기(`on`), 끄기(`off`) 명령을 보내요. | 보낼 토픽 `esp32-01/rx` |
| 텍스트 로그 | 오고 간 메시지를 글자 그대로 쌓아요. | 모든 토픽(`#`) |

위젯은 제목(손잡이)을 끌어서 옮기고 크기를 바꿀 수 있어요. 키보드로는 손잡이에서 방향키로 옮기고, Shift와 방향키로 크기를 바꿔요. 배치는 이 컴퓨터에만 저장돼요.

### 두 방향 — tx로 보고, rx로 조종해요

대시보드는 C1의 토픽 약속을 그대로 써요. 보드는 `esp32-01/tx`로 값을 보내고(발행), 그래프와 게이지가 그 토픽을 받아요(구독). 거꾸로 스위치가 `esp32-01/rx`로 `on`, `off`를 보내면, 그 토픽을 구독한 보드가 받아 LED를 켜고 꺼요.

<figure>
<img src="/images/lessons/c2/two-way.svg" alt="왼쪽 보드(esp32-01)와 오른쪽 대시보드 사이에 화살표 두 개가 있다. 위쪽 파란 화살표 1 esp32-01/tx는 보드에서 대시보드로 0.3초마다 5씩 오르내리는 값을 나르고, 아래쪽 초록 화살표 2 esp32-01/rx는 대시보드에서 스위치를 누르면 보드로 on 또는 off를 날라 보드의 LED가 켜진다" width="640" height="280">
<figcaption>보드는 tx로 보내고 rx를 받아요. 대시보드는 그 반대예요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

### 위젯 설정 — 토픽과 값 번호

위젯마다 [설정]을 누르면 무엇을 보이고 무엇을 보낼지 바꿀 수 있어요.

| 설정 칸 | 뜻 |
| --- | --- |
| 받을 토픽(스위치는 보낼 토픽) | 어느 토픽의 값을 보일지(스위치는 어느 토픽으로 보낼지) 정해요. `esp32-01/tx`처럼 짧게 적으면 통신 접두어는 사이트가 붙여요. |
| 눈금 아래, 눈금 위 | 그래프와 게이지가 그리는 가장 작은 값과 가장 큰 값이에요. 처음은 0과 100이에요. |
| 값 번호 | 한 메시지에 값이 여러 개일 때 몇 번 값을 쓸지 정해요. 첫 값이 0번이에요. |
| 켤 때 보낼 말, 끌 때 보낼 말 | 스위치가 보낼 글이에요. 처음은 `on`과 `off`예요. |

값이 여러 개인 메시지는 3-1-3처럼 쉼표로 나눠 보내요. 맨 앞이 `DATA`처럼 숫자가 아닌 말이면 머리말로 보고 세지 않아요.

<figure>
<img src="/images/lessons/c2/field-index.svg" alt="세 줄의 예. 3은 3이 0번 값이고, 355,152는 355가 0번, 152가 1번 값이며, DATA,120,80은 맨 앞 DATA가 머리말이라 세지 않고 120이 0번, 80이 1번 값이다. 아래에 쉼표로 나눈 뒤 맨 앞이 숫자가 아니면 머리말로 보고 건너뛰며, 값 번호는 0부터 센다고 적혀 있다" width="640" height="318">
<figcaption>값 번호는 첫 값이 0번이고, 머리말은 세지 않아요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

### 통로와 안전 규칙

대시보드도 ESP32 실습실의 MQTT 칸과 같은 통로를 써요. 기본은 **같은 컴퓨터 탭**이라 인터넷이 없어도 되고, 학교망이 공개 중계 서버를 막아도 실습을 끝까지 할 수 있어요.

:::주의[공개 중계 서버는 누구나 보고, 누구나 보낼 수 있어요]
통로를 "공개 중계 서버"로 고르면 같은 접두어를 쓰는 다른 컴퓨터의 값도 들어오고, 누구든 우리 토픽으로 보낼 수 있어요. 이름, 연락처, 사진 같은 개인정보를 보내지 않고, 스위치로는 LED 같은 표시 장치만 움직여요. 레이저나 모터처럼 움직이는 장치는 잇지 않아요.
:::

## 따라하기

대시보드와 가상 보드를 한 화면에서 이어요. 대시보드 안에서 가상 보드를 열면 통신 접두어가 저절로 같아져요.

### 코드 읽기

아래 예제는 대시보드의 가상 보드에서 돌아가는 코드예요(통신 템플릿 4).

- 12\~15번 줄: 통신 접두어(`PREFIX`), 보드 번호(`esp32-01`), 허용 목록(`on`, `off`)을 정해요.
- 17\~23번 줄: 와이파이에 연결될 때까지 기다려요.
- 28\~41번 줄: `on_message()`가 받은 메시지를 검사해요. 20바이트보다 길거나, 글자로 바꿀 수 없거나, 허용 목록에 없으면 무시해요. 통과하면 `on`일 때 LED를 켜고, `off`일 때 꺼요.
- 44\~48번 줄: 중계 서버에 연결하고 `esp32-01/rx`를 구독해요.
- 50\~58번 줄: `value`를 5씩 바꾸다가 100이나 0에 닿으면 방향을 바꿔요. 0.3초마다 `esp32-01/tx`로 값을 보내고(발행) 온 메시지를 확인해요.

::예제

### 실행하고 결과 보기

1. [대시보드](/labs/iot/dashboard/)를 새 탭에서 열어요. "1. 통로를 고르고 연결해요"의 통로가 [같은 컴퓨터 탭(인터넷 없이)]인지 봐요.
2. "3. 값을 보내는 보드를 열어요"에서 [이 자리에서 가상 보드 열기]를 눌러요. 같은 컴퓨터 탭이면 [연결]도 저절로 돼요.
3. 아래에 열린 ESP32 실습실에서 [실행]을 눌러요. 그래프와 게이지에 0\~100 사이 값이 들어오고, 텍스트 로그에 `esp32-01/tx → 5` 같은 줄이 쌓여요.
4. LED 스위치를 눌러요. 가상 보드의 LED(IO2)가 켜지고, 스위치 아래에 "아래 가상 보드가 받았어요 — LED 켜짐"이 나와요. 다시 누르면 꺼져요.

가상 보드의 콘솔에는 이렇게 나와요.

```text
준비 끝
받음: on
받음: off
```

이 차시 안에서 연 실습실로 하려면, 위 예제의 [이 자리에서 실습실 열기]로 연 실습실의 MQTT 칸에서 "대시보드를 새 탭에서 열어요"를 눌러요. 새 탭의 대시보드가 같은 통신 접두어로 열리니, 거기서 [연결]을 누르고 실습실의 [실행]을 눌러요.

:::확인
- 그래프에 오르내리는 선이 그려지고, 게이지의 숫자가 5씩 바뀌어요.
- 텍스트 로그에 `esp32-01/tx`로 온 값이 쌓여요.
- 스위치를 누를 때마다 가상 보드의 LED가 켜졌다 꺼지고, 보드 콘솔에 `받음: on`, `받음: off`가 나와요.
:::

:::왜그럴까
보드는 0.3초마다 `esp32-01/tx`로 값을 보내고, 그래프, 게이지, 텍스트 로그가 그 토픽을 구독하고 있어서 같은 값을 저마다의 모양으로 보여 줘요. 스위치는 `esp32-01/rx`로 `on`, `off`를 보내고, 보드는 그 토픽을 구독하고 있다가 허용 목록에 있는 말이면 LED를 바꿔요. 대시보드와 보드는 서로를 모르고, 토픽만 맞춰 두었어요.
:::

## 바꿔보기

:::바꿔보기
1. 보드 코드 51번 줄의 `step = 5`를 `step = 10`으로 바꿔 [실행]해 보세요. 그래프와 게이지가 어떻게 달라지나요?
2. 58번 줄의 `time.sleep(0.3)`을 `time.sleep(1)`로 바꿔 [실행]해 보세요. 그래프에 점이 쌓이는 빠르기가 어떻게 달라지나요?
3. 15번 줄의 `ALLOW`를 `("on",)`으로 바꿔 `off`를 빼고 [실행]한 뒤, 스위치를 켰다가 꺼 보세요. 보드 콘솔에 무엇이 나오나요?
:::

:::왜그럴까[off를 빼면 왜 LED가 꺼지지 않을까?]
스위치는 여전히 `off`를 보내지만, 보드의 허용 목록에 `off`가 없어서 `무시했어요(허용 목록에 없어요): off`만 적고 LED를 그대로 둬요. 대시보드의 스위치 모양은 꺼짐으로 바뀌어도 실제 보드는 켜진 채라, 잠시 뒤 스위치 아래에 "아래 가상 보드의 LED가 바뀌지 않았어요"가 나와요. 화면의 스위치 모양만 믿지 말고 보드 쪽 결과를 함께 봐야 하는 까닭이에요.
:::

:::오류
- 스위치를 눌렀는데 "먼저 위쪽 [연결]을 눌러요"가 나오면 대시보드가 아직 연결되지 않은 거예요. "1. 통로를 고르고 연결해요"의 [연결]을 눌러요.
- 대시보드와 보드를 따로 열었더니 값이 들어오지 않으면, 두 화면의 통신 접두어가 같은지 봐요. 다르면 한쪽의 접두어를 [복사]해 다른 쪽의 [친구 접두어]에 붙여 넣고 [맞추기]를 눌러요.
- "공개 중계 서버"를 골랐는데 연결하지 못했다고 나오면 학교망이 막았을 수 있어요. 통로를 [같은 컴퓨터 탭]으로 바꾸거나, [학교 네트워크 점검](/start/check/)에서 확인해요([오류 사전](/help/errors/#comm-mqtt-connect-failed)).
:::

## 도전 과제

::::도전[도전 과제 1: 값 두 개를 보내고 따로 보기]
보드가 값 하나 대신 `DATA,값,반대 값` 모양으로 두 값을 보내게 고치고, 그래프에는 첫째 값을, 게이지에는 둘째 값을 보이게 해 보세요. 반대 값은 `100 - value`예요.

:::힌트
56번 줄을 `client.publish(BASE + "/tx", "DATA," + str(value) + "," + str(100 - value))`로 바꿔요. 그다음 게이지의 [설정]에서 "값 번호"를 1로, 제목을 "반대 값"으로 바꿔요. 머리말 `DATA`는 세지 않으니 그래프(0번 값)는 `value`를, 게이지(1번 값)는 `100 - value`를 보여요.
:::
::::

::::도전[도전 과제 2: 깜빡이 스위치 더하기]
대시보드에 [+ 스위치]로 스위치를 하나 더 놓고, 켜면 보드의 LED가 깜빡이고 끄면 꺼지게 만들어 보세요.

:::힌트
새 스위치의 [설정]에서 "켤 때 보낼 말"을 `blink`로 바꿔요. 보드 코드는 받은 명령을 바로 LED에 쓰지 않고 기억해 두었다가, 반복문에서 명령대로 LED를 움직이게 고쳐요.

```python
ALLOW = ("on", "off", "blink")   # 15번 줄: blink를 더해요.
mode = "off"                     # 25번 줄 아래: 마지막으로 받은 명령을 기억해요.

def on_message(topic, msg):
    global mode                  # 함수 안에서 바깥의 mode를 바꾸려면 필요해요.
    # ... 길이, 글자, 허용 목록 검사는 그대로 ...
    mode = text                  # 40번 줄의 led.value(...) 대신
    print("받음:", text)

# 반복문 안 client.check_msg() 아래
    if mode == "blink":
        led.value(not led.value())   # 0.3초마다 켜짐과 꺼짐을 바꿔요.
    else:
        led.value(1 if mode == "on" else 0)
```
:::

### 자주 막히는 곳

- 대시보드와 ESP32 실습실을 따로 열면 통신 접두어가 달라요. 대시보드 안의 [이 자리에서 가상 보드 열기]로 열거나, ESP32 실습실 MQTT 칸의 "대시보드를 새 탭에서 열어요" 링크로 열면 접두어가 저절로 같아요.
- 통로가 "공개 중계 서버"면 가상 보드를 열어도 [연결]이 저절로 되지 않아요. 1단계의 [연결]을 누르게 해요.
- 스위치가 보내지 못하면 모양을 바꾸지 않고 "보내지 못해서 스위치를 그대로 뒀어요"를 보여요. 연결 상태부터 봐요.
- 위젯 배치는 이 컴퓨터에 저장돼요. 공용 컴퓨터에서는 수업 뒤 [이 컴퓨터에서 내 기록 지우기]를 누르게 해요.
- 그래프 값은 이 컴퓨터 밖으로 나가지 않지만(같은 컴퓨터 탭), 공개 중계 서버를 고르면 누구나 볼 수 있어요.
- 실제 보드로 할 때는 코드의 `PREFIX` 줄을 채우고(MQTT 칸의 [코드에 접두어 적기]) 와이파이 이름과 비밀번호를 바꿔요. 실제 보드는 코드에 적은 공개 중계 서버에 직접 붙으니, 대시보드도 "공개 중계 서버"로 연결해야 값이 와요.

### 이 차시를 둔 까닭

- 교과서와 수업 교안에는 대시보드가 없어요. 사이트의 통신 실습실 마지막 계단(브라우저 대시보드)과 시나리오 D를 수업에서 쓰도록 사이트가 새로 쓴 보충 차시예요.
- 예제는 대시보드의 [이 자리에서 가상 보드 열기]가 여는 통신 템플릿 4를 그대로 써요.
