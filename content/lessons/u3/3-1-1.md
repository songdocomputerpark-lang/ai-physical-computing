## 핵심 개념

### 비트와 바이트 — 글자도 숫자로 저장돼요

우리가 스마트폰으로 문자를 보내고 컴퓨터에서 센서 정보를 볼 수 있는 까닭은, 기기끼리 정해진 규칙에 따라 데이터를 주고받기 때문이에요. 컴퓨터와 전자 기기 안에서 데이터는 0과 1로 이루어진 전기 신호로 바뀌어 전달돼요.

- :용어[비트](bit)는 데이터를 이루는 가장 작은 단위로, 0 또는 1 가운데 하나의 값을 가져요.
- :용어[바이트](byte)는 비트 8개를 묶은 단위예요. 영어 글자 하나나 0\~255 사이의 수 하나를 담을 수 있어요.
- :용어[아스키코드](ASCII)는 영어 글자, 숫자, 기호를 번호로 정해 둔 표준이에요. 컴퓨터는 글자를 이 번호로 바꿔 저장해요.

그래서 화면에서는 똑같이 1로 보여도 **문자 '1'과 숫자 1**은 컴퓨터 안에서 서로 다른 바이트예요.

| 구분 | 예시 | 컴퓨터 안에 저장되는 값 |
| --- | --- | --- |
| 문자 '1' | 화면에 보이는 글자 | 0x31 (10진수 49) |
| 숫자 1 | 실제 정숫값 | 0x01 (10진수 1) |

0x31처럼 앞에 0x를 붙인 수는 :용어[16진수]로 적은 수예요. 16진수 31은 10진수로 3×16 + 1 = 49예요.

### 결과가 보드까지 가는 다섯 단계

인공지능 프로그램이 얻은 값은 그대로 ESP32에서 쓸 수 없어요. 보내기 위해 다음 다섯 단계를 거쳐요.

<figure>
<img src="/images/lessons/3-1-1/data-flow.svg" alt="다섯 단계 흐름도. 컴퓨터에서 ① 영상 처리로 결과를 글자 c로 준비하고 ② 글자를 바이트 99로 바꾼 뒤(인코딩), ③ 선이나 전파로 보내요. 보드에서 ④ 바이트를 다시 글자 c로 되돌리고(디코딩) ⑤ 조건문으로 LED를 켜요" width="640" height="430">
<figcaption>위의 두 단계는 컴퓨터(파이썬), 아래 두 단계는 보드(ESP32)에서 일어나요. 사이트가 원고 185쪽 흐름도를 다시 그린 그림이에요.</figcaption>
</figure>

| 단계 | 하는 일 |
| --- | --- |
| ① 영상 처리 | 보낼 결과를 'c' 같은 글자(문자열)로 준비해요. |
| ② 데이터 변환 | 글자를 바이트로 바꿔요. 이 일을 :용어[인코딩]이라고 해요(파이썬 `encode()`). |
| ③ 전송 | 바꾼 바이트를 선(시리얼)이나 전파(블루투스)로 보내요. |
| ④ 수신 | ESP32가 받은 바이트를 아스키코드로 읽어 다시 글자로 바꿔요. 이 일을 :용어[디코딩]이라고 해요(`decode()`). |
| ⑤ 제어 | 되돌린 글자를 조건문으로 판단해 LED나 모터를 실제로 움직여요. |

데이터가 USB 선으로 가든 블루투스 전파로 가든, 보낼 때는 글자를 바이트로 바꾸고 받을 때는 바이트를 글자로 되돌리는 원리는 같아요.

### 보내는 약속 — 결괏값만 보낼까, 값을 그대로 보낼까

인공지능 프로그램은 손가락 끝 같은 :용어[특징점]의 좌표(x, y)로 하드웨어를 제어할 수 있어요. 이때 보내는 방법이 두 가지 있어요.

- **결괏값만 보내기:** 컴퓨터가 먼저 판단하고 'a', 'b', 'c' 같은 결과 글자 하나만 보내요. 받는 보드는 조건문 하나로 간단히 움직여요.
- **변수로 보내기:** 좌표 같은 값을 그대로 보내고 보드가 판단해요. 값을 여러 개 보낼 때는 "쉼표로 나누고, 끝에 줄바꿈을 붙인다"처럼 보내는 쪽과 받는 쪽이 모양을 미리 약속해야 해요. 이런 약속을 :용어[프로토콜]이라고 해요.

```python
# 결괏값만 보내기: 검지 끝 x 좌표에 따라 글자 하나를 골라 보내요.
if finger_x < 100:
    b.send('a')
elif finger_x > 500:
    b.send('b')
else:
    b.send('c')

# 변수로 보내기: 두 값을 쉼표로 잇고 끝에 줄바꿈 문자(\n)를 붙여요.
b.send(f"{finger_x},{finger_y}\n")
```

`\n`은 **줄바꿈 문자**예요. 화면에는 두 글자처럼 보이지만 바이트 하나(10)이고, "메시지가 여기서 끝나요"라는 표시예요. 예를 들어 `120,250\n124,278\n`이 도착하면 보드는 `\n` 앞까지를 한 메시지 `120,250`으로 읽어요.

### 받는 약속 — 한 줄로 자르고 쉼표로 나눠요

파이썬에서 보낸 데이터는 바이트 모양 그대로 ESP32에 도착해요. 처음 받은 값은 손대지 않은 **원시값**(raw data)이라서, x와 y가 한 글자 묶음으로 붙어 있는 채로는 쓸 수 없어요. 약속한 프로토콜대로 쉼표를 기준으로 나누고, 정수로 바꿔 변수에 넣은 다음 조건에 따라 써요. 이렇게 받은 글자를 약속에 따라 나누고 바꾸는 일을 :용어[파싱]이라고 해요.

| 처리 단계 | 코드 예시 | 설명 |
| --- | --- | --- |
| 문자열 나누기 | `values = data.split(',')` | 쉼표를 기준으로 값을 나눠요. |
| 변수에 넣기 | `x = int(values[0])`<br>`y = int(values[1])` | 글자('120')를 정수(120)로 바꿔요. |
| 값 쓰기 | `print(x, y)` | 좌표를 하드웨어 제어에 써요. |

아래 조각은 3-1-3 보드 코드처럼 블루투스로 받는 경우예요. `ESP32BLE` 라이브러리의 `read()`는 받은 바이트를 글자로 되돌리고(디코딩) 끝의 줄바꿈을 떼어서 돌려줘요. 그래서 이 조각에는 `decode()`와 `strip()` 줄이 없어요. UART로 받을 때는 따라하기 예제의 ③처럼 직접 `decode()`와 `strip()`을 해요.

```python
import ESP32BLE               # 블루투스 라이브러리(3-1-3)
ble = ESP32BLE.init("ESP32")  # "ESP32"라는 이름으로 블루투스 켜기
data = ble.read()             # 받은 글자 읽기 — 글자로 되돌리고 줄바꿈을 뗀 것(없으면 None)
if data:
    values = data.split(',')  # 쉼표로 나누기
    x = int(values[0])        # 첫 번째 값을 정수로
    y = int(values[1])        # 두 번째 값을 정수로
    print(x, y)               # 바꾼 값 확인
```

### 얼마나 자주 보낼까

영상 처리 프로그램은 보통 무한 반복으로 값을 계속 보내요. 보드가 받은 데이터는 꺼내 쓰기 전까지 :용어[버퍼]라는 기억 공간에 쌓이는데, 여기에 너무 많이 쌓이면 실제 동작이 1초 넘게 늦어지는 **지연**이 생길 수 있어요. 이를 막는 방법이 두 가지 있어요.

- 앞에 보낸 값과 지금 값을 견줘 **값이 달라질 때만** 보내요.
- **1초에 10번**처럼 보내는 횟수를 줄여요.

| 보내는 방식 | 특징 | 좋은 점과 나쁜 점 |
| --- | --- | --- |
| 무한 반복 전송 | 모든 프레임마다 보내요. | 데이터가 쌓여 반응이 늦어져요. |
| 바뀔 때만 전송 | 값이 달라질 때만 보내요. | 쓸데없는 데이터가 줄고 반응이 빨라져요. |

그리고 파이썬에서 보낼 때는 메시지 끝에 줄바꿈 문자(`\n`)를 붙여요. 그래야 ESP32가 메시지를 한 줄씩 구분해 읽을 수 있어서, LED, LCD, 서보모터 같은 출력 장치를 안정적으로 제어할 수 있어요.

### 통신 방식마다 다른 연결 모양

데이터가 건너가는 길(통신 방식)은 여러 가지예요. 이 단원과 보충 차시에서 쓰는 세 가지는 연결 모양(네트워크 구조)이 달라요.

- **:용어[시리얼 통신](UART):** 두 기기를 선으로 직접 이어요(1:1). 예: 3-1-2 얼굴이 보이면 레이저 켜기
- **:용어[블루투스]{항목=ble}(BLE):** 가까운 기기끼리 선 없이 이어요. 예: 3-1-3 손끝 좌표로 RGB LED, 무선 이어폰
- **와이파이와 MQTT:** 인터넷에 붙은 여러 기기가 가운데의 중계 서버를 거쳐 주고받아요. 예: [보충 C1](/learn/u3/c1/), 스마트 홈 기기

| 시리얼 통신(UART) | 두 기기를 선으로 직접 이어요(1:1). 한쪽의 TX(보내기) 선을 다른 쪽의 RX(받기)에 엇갈려 이어요. | 구조가 간단하고, 두 기기의 통신 속도를 똑같이 맞춰야 해요. | 3-1-2 얼굴이 보이면 레이저 켜기, MP3 모듈 |
| 블루투스(BLE) | 보드가 자기 이름을 주변에 알리면(광고), 컴퓨터나 스마트폰이 골라서 선 없이 이어요. | 가까운 거리에서 전기를 적게 쓰며 짧은 메시지를 보내요(한 번에 20바이트 정도). | 3-1-3 손끝 좌표로 RGB LED, 무선 이어폰 |
| 와이파이와 MQTT | 기기들이 인터넷에 붙고, 가운데의 중계 서버가 메시지를 받아 원하는 기기들에 나눠 줘요. | 멀리 떨어진 여러 기기가 함께 주고받아요. | [보충 C1](/learn/u3/c1/), 스마트 홈 기기 |
:::

영상 처리는 컴퓨터의 파이썬에서, 하드웨어 쪽은 ESP32의 :용어[MicroPython]에서 돌아가요. ESP32에는 시리얼(UART)과 블루투스 기능이 이미 들어 있어서 따로 설치하지 않고 바로 불러 써요. 이 사이트에서는 컴퓨터 쪽도 설치가 필요 없어요. 브라우저가 USB 포트와 블루투스를 대신 열어 줘요.

## 따라하기

카메라와 보드 없이, 컴퓨터가 보내고 보드가 받는 과정을 한 프로그램에서 한 단계씩 확인해요. 실제로 선과 전파로 보내는 실습은 3-1-2(시리얼)와 3-1-3(블루투스)에서 해요.

### 코드 읽기

코드는 주석의 동그라미 번호로 네 부분으로 나뉘어요. 7\~9번 줄의 값은 실습실 오른쪽 아래 **조절 패널**에 나와서, 막대와 고르기 상자로 바꿀 수 있어요.

- ① 11\~17번 줄: `"1".encode("utf-8")`은 문자 '1'을 바이트로 바꿔요(인코딩). `bytes([1])`은 숫자 1을 바이트 하나로 만들어요. `list()`로 감싸면 바이트를 0\~255 숫자 목록으로 보여 줘요.
- ② 19\~26번 줄: 보내는 쪽(컴퓨터)이에요. `f"{finger_x},{finger_y}\n"`로 약속한 모양의 글자 한 줄을 만들고, `encode`로 바이트로 바꿔요. 24\~25번 줄은 글자마다 어떤 바이트가 되는지 보여 줘요.
- ③ 28\~36번 줄: 받는 쪽(보드)이에요. `decode`로 글자로 되돌리고(디코딩), `strip()`으로 끝의 줄바꿈을 떼고, `split(",")`로 나누고, `int()`로 정수를 만들어요.
- ④ 38\~44번 줄: 3-1-3의 보드 코드와 같은 조건으로 켤 LED를 정해요.

::예제

### 실행하고 결과 보기

[이 자리에서 실습실 열기]를 누르고, 실습실이 열리면 [실행]을 눌러요. 이 예제는 카메라를 쓰지 않아서 OpenCV를 기다리지 않고 바로 돌아가요. 콘솔에 이렇게 나와요.

```text
① 글자 하나
  문자 '1' → 바이트 [49] (16진수 0x31)
  숫자 1   → 바이트 [1] (16진수 0x01)
  결과 글자 'c' → 바이트 [99]
② 보내는 쪽(컴퓨터)
  보낼 글자 한 줄: '120,250\n'
  한 글자씩: '1'→49  '2'→50  '0'→48  ','→44  '2'→50  '5'→53  '0'→48  '\n'→10
  모두 8바이트: [49, 50, 48, 44, 50, 53, 48, 10]
③ 받는 쪽(보드)
  글자로 되돌리고 줄바꿈 떼기: '120,250'
  쉼표로 나누기: ['120', '250']
  정수로 바꾸기: x = 120 / y = 250
④ 할 일: 파란 LED를 켜요
```

:::확인
- ①에서 문자 '1'은 49, 숫자 1은 1로 서로 다른 바이트예요.
- ②에서 쉼표는 44, 줄바꿈 `\n`은 10이라는 바이트 하나예요. 모두 8바이트예요.
- ③에서 글자 조각 `['120', '250']`이 정수 x = 120, y = 250으로 바뀌어요.
:::

:::왜그럴까
컴퓨터는 글자를 아스키코드 번호로 저장해요. 그래서 문자 '1'은 49, 쉼표는 44, 줄바꿈은 10이라는 바이트가 돼요. 보내는 쪽은 이 바이트를 차례로 보내고, 받는 쪽은 그 바이트를 다시 글자로 되돌려요.

되돌린 글자 `'120,250'`을 쉼표에서 나누면 `'120'`과 `'250'`이라는 **글자** 조각이 나와요. 글자로는 크기를 견줄 수 없어서 `int()`로 정수로 바꾼 뒤에야 `x < 100` 같은 조건을 쓸 수 있어요. x도 y도 100보다 크니 ④에서 파란 LED를 골랐어요.
:::

## 바꿔보기

:::바꿔보기
1. 조절 패널에서 `finger_x`를 80으로 옮기고 다시 [실행]해 보세요. ④의 결과는 어떻게 바뀔까요? ②의 바이트 수도 달라질까요?
2. 20번 줄의 쉼표를 빗금으로 바꿔 `message = f"{finger_x}/{finger_y}\n"`로 실행해 보세요. 어느 줄에서 어떤 오류가 날까요?
3. 조절 패널의 "보낼 결과 글자"에서 `가`를 고르고 다시 [실행]해 보세요. 글자 하나인데 바이트가 몇 개 나올까요?
:::

:::왜그럴까[왜 빗금으로 바꾸면 31번 줄에서 멈출까?]
받는 쪽(30번 줄)은 여전히 쉼표로 나누기로 약속하고 있어요. 쉼표가 없으니 `'120/250'`이 나뉘지 않은 채 한 조각으로 남고, 31번 줄의 `int('120/250')`은 숫자 모양이 아니라서 `ValueError`가 나요. 원고의 말처럼 프로토콜을 바꾸면 **보내는 쪽과 받는 쪽 코드를 함께** 고쳐야 해요.
:::

:::왜그럴까[왜 '가'는 바이트가 3개일까?]
아스키코드에는 영어 글자, 숫자, 기호 128개만 있어요. 한글은 아스키코드에 없어서 UTF-8이라는 규칙으로 한 글자를 바이트 3개(234, 176, 128)로 나타내요. 블루투스는 한 번에 20바이트 정도만 보내므로 한글 메시지는 금방 넘쳐요. 그래서 통신 메시지는 영어와 숫자로 짧게 만들어요.
:::

:::오류
`ValueError: invalid literal for int() with base 10`이 나오면 `int()`에 숫자 모양이 아닌 글자가 들어간 거예요. 보내는 모양(쉼표, 줄바꿈)과 받는 쪽의 나누기가 같은지 확인해요. 자세한 풀이는 [오류 사전의 이 항목](/help/errors/#value-error-int)에 있어요.
:::

### 평가 포인트

3단원 원고에는 차시별 자기 평가 표가 없어요. 원고 184쪽의 **단원 성취 계획**(단원을 시작할 때 학생이 0\~100%로 적는 네 문항)을 이 차시에서 처음 세우게 하고, 단원 끝(대단원 마무리)에서 다시 보게 해요.

- 다양한 출력 장치를 연결할 수 있는가?
- 프로그래밍을 통해 출력 장치를 제어할 수 있는가?
- 시리얼 통신의 개념을 설명할 수 있는가?
- 블루투스를 활용해 출력 장치를 제어할 수 있는가?

이 차시의 학습 목표를 자기 평가 문항으로 바꿔 쓸 수도 있어요(사이트가 만든 문항): "데이터의 기본 단위와 표현 방식을 설명할 수 있는가?", "통신 방식별 네트워크 구조와 예시를 설명할 수 있는가?"

관찰할 곳: 도전 과제 1에서 아스키코드, 16진수, 2진수를 서로 맞게 채웠는지(자리값 계산을 쓸 수 있는지) 봐요. 도전 과제 2에서 모양(프로토콜), 끝 표시, 보내는 횟수, 길이, 통로, 개인정보 가운데 세 가지 이상을 근거와 함께 적었는지 봐요.

### 자주 막히는 곳

- `print("1")`과 `print(1)`은 화면에 똑같이 보여서 차이를 느끼기 어려워요. 따라하기 ①처럼 `list(...encode())`로 바이트를 직접 보게 해요.
- 0x31을 "31"로 읽어요. 16진수는 한 자리가 16배씩 커진다는 것만 짚어 주면 돼요(3×16 + 1 = 49).
- `split()`으로 나눈 조각이 아직 글자라는 것을 놓쳐요. `'120' + 1`을 실행해 `TypeError`를 보여 주면 `int()`가 왜 필요한지 바로 알아요.
- `\n`을 두 글자로 생각해요. 따라하기 ②의 "한 글자씩" 줄에서 `'\n'→10` 하나로 나오는 것을 짚어 주세요.
- 이 예제는 반복하지 않고 한 번 돌고 끝나요. 조절 패널의 값을 바꾼 뒤에는 [실행]을 다시 눌러야 결과가 바뀌어요.

### 원고에서 바꾼 곳

- 원고 185\~188쪽(학습 목표, 본문, 표, 코드 조각, 해 보기)을 차시 틀에 맞게 옮기고 문장을 다듬었어요. 해 보기 1·2는 도전 과제 1·2로 옮겼어요. 학습 목표는 원고의 두 개에 본문(데이터 흐름 정리)을 목표 하나로 더했어요.
- 185쪽 표의 "숫자 '1'"은 따옴표 때문에 글자처럼 읽혀서 "숫자 1"로 바꿨어요. 아스키코드 설명의 "국제 표준"은 "표준"으로 적었어요(ASCII는 미국 표준에서 나온 이름이에요).
- 186쪽 코드 `b. send ('f{finger_x}, {finger_y}\n')`는 f가 따옴표 안에 들어가 좌표 대신 글자 그대로 보내지므로, `b.send(f"{finger_x},{finger_y}\n")`로 바로잡았어요.
- 188쪽의 "시리얼 통신 | bleak 라이브러리 사용"은 실제 코드(3-1-2)가 pyserial(`import serial`)을 쓰므로 바로잡았어요. 라이브러리를 설치하는 부분은 브라우저 실습실 흐름으로 바꾸고, 원래 설치 절차는 교사용 자료실의 ["진짜 PC에서 돌리기"](/teacher/real-pc/#2-라이브러리-설치하기)로 옮겼어요.
- 학습 목표 "통신 방식별 네트워크 구조와 예시"에 맞는 본문이 원고에 거의 없어서, 시리얼, 블루투스, 와이파이와 MQTT를 견준 표와 그림을 사이트가 새로 썼어요(와이파이와 MQTT는 과목 교육과정의 내용 요소 "와이파이 통신"과 [보충 C1](/learn/u3/c1/)로 이어져요).
- 원고의 흐름도와 로봇 말풍선 그림은 사이트가 다시 그린 그림과 본문 문장으로 옮겼어요. 따라하기 예제(변환기)는 원고에 없어서 사이트가 새로 만든 체험이에요.
