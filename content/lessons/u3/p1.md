## 학습목표

- 화면 좌표(왼쪽 위가 (0, 0))를 이해하고, PyAutoGUI로 마우스 커서를 옮기고 누를 수 있어요.
- PyAutoGUI로 글자를 치고 단축키를 누르는 자동화 코드를 만들 수 있어요.
- 화면을 캡처해 파일로 저장하고, 자동화 프로그램을 멈추는 안전장치를 설명할 수 있어요.

## 왜 배울까

매일 같은 자리를 누르고 같은 글을 치는 일은 지루하고 실수하기 쉬워요. PyAutoGUI를 쓰면 사람이 마우스와 키보드로 하던 조작을 코드로 적어 두고, 컴퓨터가 그대로 대신하게 할 수 있어요. 다음 차시(3-1-4)에서 손가락으로 마우스 커서를 움직일 때도, 커서를 실제로 옮기는 일은 PyAutoGUI가 해요.

## 핵심 개념

### PyAutoGUI — 코드로 움직이는 마우스와 키보드

PyAutoGUI는 파이썬 코드로 마우스와 키보드를 움직이는 :용어[라이브러리]예요. 조작을 차례대로 적어 두면, 여러 조작을 묶어 한 번에 해 주는 매크로처럼 컴퓨터가 대신 해 줘요. 진짜 PC에서는 PyAutoGUI를 먼저 설치해야 하지만, 이 사이트는 설치 없이 영상처리 실습실의 **가상 데스크톱**에서 돌려요.

가상 데스크톱은 실습실 안에 그린 가로 1920, 세로 1080의 가상 모니터예요. 코드가 움직이는 것은 진짜 마우스가 아니라 이 가상 모니터의 커서예요. 같은 코드를 진짜 PC에서 돌리면 진짜 마우스가 움직여요.

| 가상 데스크톱에 있는 것 | 하는 일 |
| --- | --- |
| 그림판 | 처음부터 열려 있어요. 마우스 왼쪽 버튼을 누른 채 끌면 선이 그려져요. |
| 메모장 | 코드가 글자를 치면 열려서 글자가 들어가요. Ctrl+S로 저장하면 가상 파일로 남아요. |
| 웹 브라우저 | `webbrowser.open(주소)`로 열려요. 진짜 인터넷에는 가지 않고 이 사이트 안의 쪽만 보여 줘요([웹 페이지 열기 예제](/labs/vision/?example=desktop%2F07-open-webpage.py)). |
| 내 파일 | 코드가 저장한 그림과 글이 모여요. [내려받기]로 내 컴퓨터에 가져갈 수 있어요. |

### 화면 좌표 — 왼쪽 위가 (0, 0)

화면의 한 점은 (x, y) 두 수로 가리켜요. 왼쪽 위 모서리가 (0, 0)이고, x는 오른쪽으로, y는 아래로 갈수록 커져요. 수학 시간의 좌표와 달리 y가 아래로 커진다는 점을 조심해요. 1단원에서 사진의 픽셀 자리를 가리킬 때와 같은 방법이에요.

<figure>
<img src="/images/lessons/p1/screen-coords.svg" alt="가로 1920, 세로 1080 화면을 줄여 그린 네모. 왼쪽 위 모서리가 (0, 0), 오른쪽 아래 끝이 (1919, 1079)이고, x는 오른쪽으로 y는 아래로 갈수록 커진다. 빨간 점 moveTo(600, 400)은 왼쪽 끝에서 600, 위 끝에서 400 떨어진 자리이고, 거기서 파란 점선 화살표 moveRel(500, 200)이 오른쪽 500, 아래 200을 더 가서 (1100, 600)에 닿는다" width="640" height="400">
<figcaption>moveTo는 (0, 0)에서 잰 자리로, moveRel은 지금 자리에서 더 가는 거리로 옮겨요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

| 함수 | 하는 일 | 돌려주는 값이나 예 |
| --- | --- | --- |
| `pyautogui.size()` | 화면의 가로, 세로 크기를 알려 줘요. | `Size(width=1920, height=1080)` |
| `pyautogui.position()` | 지금 커서 자리를 알려 줘요. | `Point(x=960, y=540)` |
| `pyautogui.moveTo(x, y, duration=1)` | (0, 0)에서 잰 자리 (x, y)로 커서를 옮겨요. `duration`에 적은 초만큼 천천히 옮겨요. | `moveTo(600, 400)` |
| `pyautogui.moveRel(dx, dy)` | 지금 자리에서 오른쪽으로 dx, 아래로 dy만큼 더 옮겨요. | `moveRel(500, 200)` |

### 마우스 조작 — 옮기기, 누르기, 끌기

마우스로 하는 일은 커서 옮기기, 버튼 누르기, 버튼을 누른 채 끌기(드래그) 세 가지로 나뉘어요. 버튼을 누르고 있는지에 따라 결과가 달라져요.

<figure>
<img src="/images/lessons/p1/move-drag-click.svg" alt="세 칸 비교 그림. moveTo는 마우스 버튼을 뗀 채 커서만 점선을 따라 옮겨 선이 남지 않고, dragTo는 왼쪽 버튼을 누른 채 옮겨 그림판에 파란 선이 남고, click은 그 자리에서 왼쪽 버튼을 눌렀다 떼서 단추나 아이콘이 눌린다" width="640" height="282">
<figcaption>그림판에 선을 그리려면 버튼을 누른 채 옮겨야 해요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

| 함수 | 하는 일 |
| --- | --- |
| `pyautogui.click(x, y)` | (x, y)로 옮겨 왼쪽 버튼을 한 번 눌렀다 떼요. 자리를 적지 않으면 지금 자리에서 눌러요. |
| `pyautogui.click(clicks=3, interval=0.5)` | 0.5초 간격으로 세 번 눌러요. |
| `pyautogui.doubleClick(x, y)` | 두 번 빠르게 눌러요(더블 클릭). |
| `pyautogui.rightClick(x, y)` | 오른쪽 버튼을 눌러요. 가상 데스크톱에서는 바탕 화면 메뉴가 열려요. |
| `pyautogui.dragTo(x, y, duration=2)` | 왼쪽 버튼을 누른 채 (x, y)까지 끌어요. |
| `pyautogui.dragRel(dx, dy, duration=0.5)` | 버튼을 누른 채 지금 자리에서 dx, dy만큼 끌어요. |

PyAutoGUI 함수는 부를 때마다 0.1초씩 쉬어요(`pyautogui.PAUSE`). 사람이 따라 보고 멈출 수 있게 너무 빨리 움직이지 않도록 한 거예요.

### 키보드 조작 — 글자 치기와 단축키

키보드로 하는 일은 글자를 차례로 치는 것과, 여러 키를 함께 누르는 단축키로 나뉘어요.

<figure>
<img src="/images/lessons/p1/keyboard.svg" alt="위 칸은 typewrite(hi와 줄바꿈, interval=0.1)이 h, i, Enter 키를 0.1초 간격으로 차례로 눌러 메모장에 hi를 치고 줄을 바꾸는 모습이고, 아래 칸은 hotkey(ctrl, s)가 1 Ctrl 누름, 2 S 누름, 3 S 뗌, 4 Ctrl 뗌 차례로 움직여 Ctrl+S를 함께 누른 것과 같아져 저장 창이 열리는 모습" width="640" height="316">
<figcaption>단축키는 적은 차례대로 누르고, 거꾸로 떼요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

| 함수 | 하는 일 |
| --- | --- |
| `pyautogui.typewrite("글자", interval=0.1)` | 글자를 한 글자씩 쳐요. `\n`은 Enter 키예요. `write()`도 같은 일을 해요. |
| `pyautogui.press("enter")` | 키 하나를 눌렀다 떼요. 키 이름은 `'enter'`, `'space'`, `'backspace'`처럼 적어요. |
| `pyautogui.hotkey("ctrl", "s")` | 여러 키를 함께 눌러요(단축키). |

`typewrite()`는 키보드의 키 이름으로 글자를 쳐요. 그래서 키 이름이 아닌 한글 글자는 치지 못하고 건너뛰어요(바꿔보기 2).

### 화면 캡처

`pyautogui.screenshot()`은 지금 화면을 그림으로 찍어 돌려줘요. 돌려받은 그림의 `.save("screenshot.png")`를 부르면 파일로 저장돼요. 가상 데스크톱에서는 가상 모니터를 찍고, 저장한 파일은 '내 파일'에 모여요. 3-1-4에서는 손동작을 알아본 순간 이 함수로 화면을 찍어요.

### 조심할 것 두 가지 — 안전장치와 파일 이름

자동화 코드는 사람보다 훨씬 빨리 마우스와 키보드를 움직여요. 잘못 만든 코드가 멈추지 않을 때를 대비해야 해요.

<figure>
<img src="/images/lessons/p1/two-cautions.svg" alt="왼쪽 칸 안전장치(FAILSAFE): 화면의 왼쪽 위 모서리 (0, 0)이 빨갛게 칠해져 있고 커서가 그리로 옮겨 가서, 다음 pyautogui 함수에서 FailSafeException으로 멈춘다. 오른쪽 칸 파일 이름 주의: 내 코드 파일 이름이 pyautogui.py이면 import pyautogui가 자기 자신을 불러와 진짜 PyAutoGUI를 건너뛰고 moveTo가 없다는 오류가 나므로, 이름을 my_mouse.py처럼 바꾼다" width="640" height="310">
<figcaption>왼쪽: 모서리로 밀면 멈춰요. 오른쪽: 코드 파일 이름을 라이브러리 이름과 같게 짓지 않아요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

- **안전장치(FAILSAFE):** PyAutoGUI는 커서가 화면 왼쪽 위 모서리 (0, 0)에 있으면 다음 함수를 부를 때 `FailSafeException`을 내고 멈춰요. 진짜 PC에서는 마우스를 왼쪽 위 모서리로 힘껏 밀면 되고, 가상 데스크톱에는 [모서리로(안전장치)] 단추가 있어요.
- **파일 이름(진짜 PC):** 내 코드 파일 이름을 `pyautogui.py`로 지으면, 파이썬이 설치된 PyAutoGUI 대신 내 파일을 먼저 불러와요. 그러면 `moveTo`가 없다는 오류가 나요. `my_mouse.py`처럼 다른 이름을 써요.

### 실행하고 결과 보기 ① 화면 크기와 커서 옮기기

첫째 예제를 실행하면 콘솔에 이렇게 나와요.

```text
Screen size:Size(width=1920, height=1080)
Mouse Position :Point(x=960, y=540)
```

둘째 예제를 실행하면 커서가 (300, 300)으로 갔다가 (50, 50)으로 간 뒤, 다시 (300, 300)을 눌러요. 마지막 오른쪽 클릭으로 바탕 화면 메뉴(새 메모장 열기, 새 그림판 열기 …)가 열려요. 가상 데스크톱의 [커서가 지나간 길 보기]를 켜 두면 커서가 지나간 길이 점으로 남아요.

:::왜그럴까
가상 모니터는 가로 1920, 세로 1080이라 `size()`가 그 크기를 알려 주고, 처음 커서는 가운데인 (960, 540)에 있어요. 수업 슬라이드에 실린 진짜 PC 실행 결과에서는 커서 자리가 다르게 나와요. 코드를 실행한 순간 진짜 마우스가 있던 자리를 알려 주기 때문이에요. `moveTo(300, 300)`은 커서가 어디에 있든 늘 (0, 0)에서 잰 같은 자리로 가요.
:::

### 실행하고 결과 보기 ② 드래그와 글자 치기

셋째 예제를 실행하면 커서가 가운데 (960, 540)에서 (400, 400)까지 2초 동안 움직이며, 처음부터 열려 있던 그림판에 선이 그어져요.

넷째 예제를 실행하면 5초 뒤 메모장이 열리고 `hello, world!`가 한 줄씩 10줄 쳐져요. 끝까지 30초쯤 걸리니, 기다리기 어려우면 [정지]를 눌러도 돼요. 마지막에 Ctrl+S가 눌려 저장 창이 열려요. 쳐진 글은 가상 데스크톱 아래 [메모장 글·내 파일 보기]를 펼쳐도 볼 수 있어요.

:::왜그럴까
셋째 예제의 `dragTo()`는 왼쪽 버튼을 누른 채 옮겨서 그림판에 선이 남아요. 둘째 예제의 `moveTo()`는 버튼을 누르지 않으니 선이 남지 않아요.

넷째 예제의 5초 기다리기는, 진짜 PC에서 사람이 그동안 메모장을 눌러 글자가 들어갈 자리를 정해 두라는 뜻이에요. 가상 데스크톱은 글자가 들어갈 창이 없으면 메모장을 저절로 열어 줘요.
:::

### 실행하고 결과 보기 ③ 화면 캡처

다섯째 예제를 실행하면 콘솔에 이렇게 나와요. 처음 한 번은 그림을 다루는 도구(Pillow)를 받는 줄이 먼저 나와요.

```text
Screenshot saved as screenshot.png!
```

가상 데스크톱 아래 [메모장 글·내 파일 보기]를 펼치면 '내 파일'에 `screenshot.png`(1920×1080)가 있어요. [내려받기]를 누르면 내 컴퓨터로 가져올 수 있어요.

여러 장을 이어 찍을 수도 있어요. [화면 주기적으로 캡처하기 예제](/labs/vision/?example=desktop%2F10-screenshot-loop.py)는 2초마다 한 장씩 모두 5장을 `screenshots` 폴더에 저장해요. 끝까지 10초쯤 걸리고, 다섯 장 모두 '내 파일'에 쌓여요.

:::확인
- 첫째 예제의 콘솔에 화면 크기 `Size(width=1920, height=1080)`가 나와요.
- 둘째 예제에서 커서가 옮겨 다니고, 오른쪽 클릭으로 메뉴가 열려요.
- 셋째 예제에서 그림판에 선이 그어지고, 넷째 예제에서 메모장에 `hello, world!`가 쳐져요.
- 다섯째 예제에서 '내 파일'에 `screenshot.png`가 생겨요.
:::

:::왜그럴까
`screenshot()`은 그 순간의 화면을 그림 한 장으로 찍어요. 가상 데스크톱에서는 진짜 컴퓨터 화면이 아니라 이 페이지 안의 가상 모니터를 찍어서, 다른 사람에게 보여도 괜찮은 그림만 남아요. 진짜 PC에서 찍은 화면에는 열려 있던 창과 파일 이름이 모두 담기니, 올리거나 보내기 전에 꼭 살펴봐요.
:::

## 바꿔보기

:::바꿔보기
1. 둘째 예제 5번 줄의 `moveTo(50,50,duration=1)`을 `moveRel(50,50,duration=1)`로 바꿔 실행해 보세요. [커서가 지나간 길 보기]로 보면 커서가 어디로 갈까요?
2. 넷째 예제 7번 줄의 `"hello, world!\n"`을 `"안녕하세요\n"`로 바꿔 실행해 보세요. 메모장에 무엇이 쳐질까요? 4번 줄을 `time.sleep(1)`로 바꾸면 덜 기다려요.
3. 넷째 예제가 글자를 치는 동안 가상 데스크톱의 [모서리로(안전장치)]를 눌러 보세요. 무슨 일이 생기나요?
:::

:::왜그럴까[moveRel은 왜 (350, 350)으로 갈까?]
`moveTo(50, 50)`은 (0, 0)에서 잰 자리 (50, 50)으로 가지만, `moveRel(50, 50)`은 지금 자리에서 오른쪽으로 50, 아래로 50만큼 더 가요. 바로 앞 4번 줄에서 (300, 300)에 왔으니 (350, 350)으로 가요. 그다음 8번 줄 `click(300,300)`이 커서를 다시 (300, 300)으로 옮겨 눌러요.
:::

:::왜그럴까[한글은 왜 쳐지지 않을까?]
`typewrite()`는 글자마다 그 글자 이름의 키를 눌러요. '안'이나 '녕'은 키 이름이 아니라서 건너뛰고, 줄바꿈(`\n`)만 Enter 키로 눌려요. 그래서 메모장에는 빈 줄만 생기고, 콘솔에 "[알림] '안'은(는) PyAutoGUI 키 이름이 아니어서 무시했어요"처럼 적혀요. 진짜 PC의 PyAutoGUI도 한글 글자를 건너뛰어요.
:::

:::오류
- [모서리로(안전장치)]를 누르면 `pyautogui.FailSafeException`으로 멈추고, 메모장에는 그때까지 친 글자만 남아요. 고장이 아니라 안전장치가 제대로 작동한 거예요([오류 사전](/help/errors/#failsafe)).
- `AttributeError: module 'pyautogui' has no attribute 'enter'`처럼 없는 함수를 부르면 멈춰요. 수업 슬라이드의 웹 검색 자동화 예제가 그 경우라, [웹 검색 자동으로 하기 예제](/labs/vision/?example=desktop%2F08-web-search.py)를 실행하면 9번 줄에서 이 오류가 나요. 키를 누르는 함수는 `pyautogui.press('enter')`예요([오류 사전](/help/errors/#attribute-error-module)).
:::

## 도전 과제

::::도전[도전 과제 1: 그림판에 원과 별 그리기]
수업 슬라이드의 "창의적인 마우스 사용"이에요. [커서로 원 그리기 예제](/labs/vision/?example=desktop%2F05-draw-circle.py)는 각도를 5도씩 바꾸며 커서를 원 둘레로 옮기지만, 버튼을 누르지 않아서 그림판에 원이 남지 않아요. 그림판에 원이 그려지도록 고쳐 보세요. 더 해 보고 싶다면 [드래그로 별 그리기 예제](/labs/vision/?example=desktop%2F06-draw-star.py)가 왜 별이 아니라 삼각형을 그리는지도 찾아봐요.

:::힌트
원의 시작점으로 먼저 옮긴 뒤 `pyautogui.mouseDown()`으로 왼쪽 버튼을 누르고, 둘레를 다 돈 뒤 `pyautogui.mouseUp()`으로 떼요.

```python
def draw_circle(radius, center_x=500, center_y=500):
    pyautogui.moveTo(center_x + radius, center_y)  # 원의 시작점으로 먼저 가요.
    pyautogui.mouseDown()                          # 왼쪽 버튼을 눌러요.
    for angle in range(0, 361, 5):                 # 361까지 돌아야 원이 닫혀요.
        x = center_x + radius * math.cos(math.radians(angle))
        y = center_y + radius * math.sin(math.radians(angle))
        pyautogui.moveTo(x, y, duration=0.01)
    pyautogui.mouseUp()                            # 버튼을 떼요.
```

별 예제는 세 번 옮긴 거리를 모두 더하면 (0, 0)이라 커서가 늘 제자리로 돌아와요. 한 변을 그을 때마다 144도씩 돌아야 별이 돼요. 고친 판은 [진짜 별 그리기(사이트판)](/labs/vision/?example=desktop%2F06-draw-star-site.py)에 있어요.
:::
::::

::::도전[도전 과제 2: 메모장 자동화 — 열고, 쓰고, 저장하기]
수업 슬라이드의 "작업 자동화"예요. Windows 키와 R 키를 함께 누르면 실행 창이 열리고, `notepad`를 치고 Enter를 누르면 메모장이 열려요. 이 방법으로 메모장을 열고, 글을 쓰고, `example.txt`라는 이름으로 저장하는 코드를 만들어 보세요. 가상 데스크톱의 실행 창도 `notepad`로 메모장을 열어요.

:::힌트
수업 슬라이드 17의 코드에 줄 끝 설명만 더했어요. 저장 창은 파일 이름 칸의 기본 이름이 골라진(파랗게 칠해진) 채 열려서, 바로 새 이름을 치면 기본 이름이 바뀌어요.

```python
import pyautogui

pyautogui.hotkey('win', 'r')                    # 실행 창 열기
pyautogui.typewrite("notepad\n", interval=0.1)  # 메모장 열기
pyautogui.typewrite("Hello, automated text input!\n", interval=0.1)
pyautogui.hotkey('ctrl', 's')                   # 저장 창 열기(기본 이름이 골라져 있어요)
pyautogui.typewrite("example.txt\n")            # 새 이름을 치고 Enter
```

실행한 뒤 [메모장 글·내 파일 보기]의 '내 파일'에 `example.txt`가 생겼는지 봐요. 같은 글을 여러 번 쳐야 한다면 `for` 반복문으로 감싸요(수업 슬라이드 18).
:::
::::

한 차시에 끝낼 때는 예제 5와 바꿔보기 2를 과제로 돌려요(학생 본문의 따라하기 첫머리에 적어 두었어요). 두 차시로 운영할 때: 1차시는 좌표와 마우스 함수, 예제 1\~3, 바꿔보기 1(40분 안팎). 2차시는 키보드 함수와 안전장치, 화면 캡처, 예제 4·5, 바꿔보기 2·3, 도전 과제, 확인 퀴즈예요. 3-1-4 바로 앞 시간에 2차시를 두면 캡처 함수를 곧바로 이어 쓸 수 있어요.

### 평가 포인트

PyAutoGUI 수업 슬라이드에는 자기 평가 문항이 없어요. 학습 목표를 자기 평가 문항으로 바꿔 쓸 수 있어요(사이트가 만든 문항).

- 화면 좌표를 이해하고 PyAutoGUI로 커서를 원하는 자리로 옮기고 누를 수 있는가?
- 글자 입력과 단축키로 간단한 작업을 자동화할 수 있는가?
- 자동화 프로그램을 멈추는 안전장치(FAILSAFE)를 설명할 수 있는가?

관찰할 곳: moveTo와 moveRel의 차이를 숫자 예로 설명하는지, 그림판에 선이 그려지려면 버튼을 누른 채 옮겨야 한다는 것을 도전 과제 1에서 스스로 찾는지 봐요. 성취기준은 따로 붙이지 않았어요(3-1-4의 사전 학습이에요).

### 자주 막히는 곳

- 진짜 마우스가 움직이지 않는다고 해요. 이 사이트는 가상 데스크톱의 커서를 움직여요. 같은 코드를 진짜 PC에서 돌리면 진짜 마우스가 움직여요(설치와 실행은 교사용 자료실의 ["진짜 PC에서 돌리기"](/teacher/real-pc/#pyautogui보충-p1-3-1-4-iv단원)).
- 진짜 PC에서 자동화 코드를 돌릴 때는 코드가 마우스와 키보드를 차지해요. 멈추는 방법(마우스를 왼쪽 위 모서리로 밀기)을 먼저 알려 주고 돌리게 해요.
- 넷째 예제의 5초는 진짜 PC에서 메모장을 눌러 둘 시간이에요. 가상 데스크톱은 메모장을 저절로 열어 주지만, 진짜 PC에서는 그 시간에 메모장을 누르지 않으면 글자가 엉뚱한 창에 들어가요.
- `typewrite()`로 한글을 치려고 해요. 한글 글자는 키 이름이 아니라서 건너뛰어요(바꿔보기 2). 자동화 예제의 글은 영어와 숫자로 적게 해요.
- 진짜 PC에서 파일 이름을 `pyautogui.py`로 짓는 실수가 잦아요(수업 슬라이드 5).
- 가상 데스크톱의 저장 창도 진짜 Windows처럼 파일 이름 칸의 기본 이름(`제목 없음.txt`)을 골라 둔 채 열려서, 바로 친 이름으로 바뀌어요. 이름을 치기 전에 방향키를 누르면 고름이 풀려 기본 이름 뒤에 이어지니, 그때는 Ctrl+A로 다시 골라요.

### 수업 슬라이드에서 바꾼 곳

- PyAutoGUI 수업 슬라이드(4\~23쪽)의 차례(소개, 마우스와 키보드 기초, 창의적인 마우스 사용, 자동화, 화면 캡처)를 차시 틀에 맞게 옮겼어요. 슬라이드 6의 `pip install pyautogui` 설치 화면은 설치 없이 가상 데스크톱에서 돌리는 흐름으로 바꿨어요.
- 예제 코드는 슬라이드 그림이 아니라 함께 받은 코드 파일(10개)을 따랐어요. 슬라이드 9(`moveRel(50, 50)`)와 파일(`moveTo(50,50,duration=1)`)이 다른 곳은 바꿔보기 1로 견줘 보게 했어요.
- 슬라이드 10에만 있는 `dragRel(-50, -50, duration=1)` 줄은 파일에 없어요. `dragRel`은 도전 과제 1의 별 예제로 다뤄요.
