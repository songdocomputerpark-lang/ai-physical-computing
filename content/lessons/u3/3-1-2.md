## 학습목표

- 시리얼 통신이 무엇인지 알고, USB-UART 변환기로 컴퓨터와 ESP32를 이어 글자를 주고받을 수 있어요.
- 얼굴 인식(MediaPipe) 결과를 글자로 바꿔 시리얼로 보내고, ESP32에서 그 글자를 받아 레이저를 켜고 끌 수 있어요.
- 카메라가 달린 컴퓨터와 보드를 이어 얼굴 인식 알림 장치 같은 작은 프로젝트를 만들 수 있어요.

## 왜 배울까

3-1-1에서 글자가 바이트로 바뀌어 오가는 원리를 배웠어요. 이번에는 진짜 선으로 컴퓨터와 보드를 이어, 카메라에 얼굴이 보이면 보드의 레이저가 켜지는 알림 장치를 만들어요. 인공지능이 본 것을 장치가 행동으로 알려 주는 첫 프로젝트예요.

## 핵심 개념

### 시리얼 통신과 USB-UART 변환기

:용어[시리얼 통신]은 데이터를 한 비트씩 순서대로 보내는 방식이에요. 마이크로컨트롤러와 컴퓨터, 또는 센서 같은 장치끼리 정보를 주고받을 때 써요. 보내는 쪽의 **TX**(송신, 보내기) 선을 받는 쪽의 **RX**(수신, 받기) 선에 이어 데이터를 주고받아요. 구조가 간단하고 처리 방식이 알기 쉬워서 센서 값 모으기, 명령 전하기, 바깥 장치 제어 같은 여러 프로젝트에 널리 쓰여요.

<figure>
<img src="/images/lessons/3-1-2/third-party/kit-vendor/usb-uart-converter.webp" alt="USB-C 단자와 GND, VCC, TX, RX 네 핀이 달린 파란 기판의 USB-UART 변환기 사진" width="313" height="282">
<figcaption>교과서 키트의 USB-UART 변환기예요(원고 189쪽, 키트 업체의 제품 사진 — 사이트 라이선스 밖이에요).</figcaption>
</figure>

**USB-UART 변환기**는 컴퓨터(USB)와 마이크로컨트롤러 사이에서 데이터를 주고받게 도와주는 통신 장치예요. 컴퓨터의 USB 신호를 보드가 알아듣는 TX·RX 신호로 바꿔 줘요.

두 기기는 1초에 몇 비트를 보낼지도 미리 똑같이 맞춰야 해요. 이 빠르기를 **통신 속도**(:용어[보드레이트], baudrate)라고 하고, 이 차시에서는 양쪽 모두 115200bps(1초에 115,200비트)로 맞춰요. 속도가 다르면 받는 쪽이 비트를 엉뚱하게 끊어 읽어 글자가 깨져요.

### 연결 구성 — USB 케이블이 두 개예요

원고의 회로예요. 레이저 모듈은 GND, VCC, GPIO 18번 핀에, USB-UART 변환기는 GND, VCC, GPIO 16번 핀, GPIO 17번 핀에 이어요. 변환기에도 USB-C 케이블을 꽂아 노트북에 연결해야 해요.

<figure>
<img src="/images/lessons/3-1-2/third-party/kit-vendor/wiring-laser-uart.webp" alt="레이저 모듈을 GND, VCC, GPIO 18번 핀에, USB-UART 변환기를 GND, VCC, GPIO 16번 핀과 GPIO 17번 핀에 이은 ESP32 확장 보드 배선 그림" width="960" height="380">
<figcaption>원고 190쪽 배선 그림이에요(키트 업체의 제품 그림으로 그림 — 사이트 라이선스 밖이에요). 가상 보드의 배선도는 사이트가 따로 그려요.</figcaption>
</figure>

그래서 컴퓨터와 보드 사이에는 USB 케이블이 두 개 있어요. 하나는 보드에 코드를 보내고 결과를 보는 길이고, 다른 하나는 변환기를 거쳐 데이터만 오가는 길이에요.

<figure>
<img src="/images/lessons/3-1-2/serial-connection.svg" alt="컴퓨터에서 USB 케이블 두 개가 나가는 연결 그림. 첫째 케이블은 ESP32 보드에 꽂혀 코드를 보내고 결과를 보는 UART0 통로가 되고, 둘째 케이블은 USB-UART 변환기에 꽂힌다. 변환기 TX는 보드 GPIO16(RX, 받기)으로, 보드 GPIO17(TX, 보내기)은 변환기 RX로 이어지고 GND끼리 잇는다. 이것이 보드의 UART2 통로이고 양쪽 속도는 115200bps로 맞춘다" width="640" height="392">
<figcaption>화살표 방향으로 글자가 가요. 보내는 쪽 TX는 늘 받는 쪽 RX에 이어요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

:::참고[왜 UART2를 쓸까?]
ESP32에는 :용어[UART] 통신 통로가 여러 개 있어요. 그중 기본 통로인 UART0은 이미 컴퓨터와 이어져 코드를 보내고 실행 결과를 보는 길로 쓰여요(교과서의 Thonny, 이 사이트의 [실제 보드] 연결). 여기에 다른 장치를 함께 이으면 신호가 섞이거나 부딪칠 수 있어서, 완전히 따로 떨어진 UART2를 써요. UART2는 `UART(2, baudrate=115200, tx=17, rx=16)`처럼 쓸 핀을 정해 줄 수 있어요.
:::

### 보드 쪽 코드 — 글자를 받아 레이저 켜고 끄기

보드는 받은 글자가 있는지 계속 살피다가, `'a'`가 오면 레이저를 켜고 `'b'`가 오면 꺼요.

| 코드 | 하는 일 |
| --- | --- |
| `UART(번호, baudrate=속도, tx=핀 번호, rx=핀 번호)` | ESP32에서 시리얼 통신 통로를 열어요. |
| `uart.any()` | 받은 데이터가 있는지 확인해요(있으면 True). |
| `uart.readline()` | 받은 데이터를 한 줄 단위로 읽어요(바이트 모양). |
| `.decode().strip()` | 바이트를 글자로 되돌리고(디코딩), 앞뒤의 줄바꿈과 빈칸을 떼요. |

### 보드에 저장하면 전원만 켜도 돌아요

마이크로파이썬 보드는 전원이 들어오거나 리셋(다시 시작)될 때 정해진 파일을 먼저 저절로 실행해요. 교과서는 Thonny로 코드를 **boot.py**에 저장해, 보드에 전원만 들어오면 통신을 받을 준비가 끝나게 해요. 그래서 컴퓨터에서 인공지능 코드를 실행할 때 보드는 이미 글자를 기다리고 있어요.

이 사이트는 ESP32 실습실 [실제 보드] 탭의 [보드에 저장]으로 **main.py**에 저장해요. main.py도 전원을 켜면 boot.py 다음에 저절로 실행되니, 하는 일은 같아요. 가상 보드로 실습할 때는 저장하지 않고 보드 쪽 [실행]만 누르면 돼요.

### 얼굴이 보일 때만 보내기 — 상태가 바뀔 때만

심화 실습에서는 사람이 키보드를 치는 대신, 인공지능이 카메라 영상에서 얼굴을 찾아 결과를 보내요. 영상 처리 코드는 1초에도 여러 장면(:용어[프레임])을 처리해요. 장면마다 글자를 보내면 3-1-1에서 본 것처럼 보드의 버퍼에 글자가 쌓여 반응이 늦어져요. 그래서 얼굴이 **보이다가 사라지거나, 없다가 새로 보일 때만** 한 글자씩 보내요.

### 코드 읽기 — 보드 쪽(받는 쪽)

아래 첫째 예제예요. 교과서 코드 자료(원본 파일)를 바탕으로 `# [사이트판]`이 붙은 두 줄만 고쳤어요(교사용 칸에 까닭이 있어요). 원본 파일에는 빈 줄이 있어서 교과서 190쪽과 줄 번호가 1\~2줄씩 달라요. 예를 들어 교과서 3번 줄(레이저 핀)이 여기서는 4번 줄, 교과서 4번 줄(UART2)이 5번 줄이에요. 아래 줄 번호는 실습실에 보이는 이 파일의 번호예요.

- 1\~2번 줄: `Pin`, `UART`와 `sleep`을 불러와요.
- 4번 줄: 18번 핀을 출력으로 정해 레이저를 연결해요.
- 5번 줄: UART2를 통신 속도 115200bps, TX 17번 핀, RX 16번 핀으로 열어요.
- 7\~15번 줄: 끝없이 되풀이하며 받은 글자가 있으면(`uart.any()`) 한 줄 읽어 글자로 되돌려요. `'a'`면 레이저를 켜고, `'b'`면 꺼요.

### 코드 읽기 — 컴퓨터 쪽(보내는 쪽)

둘째 예제(기본 실습)는 키보드로 친 글자를, 셋째 예제(심화 실습)는 얼굴 인식 결과를 보내요.

- 기본 실습 1\~5번 줄: `serial`(pyserial) 모듈을 불러와 시리얼 포트를 통신 속도 115200bps로 열고, 연결이 안정되도록 2초 기다려요. `"COM10"`은 변환기가 꽂힌 포트 이름이라 컴퓨터마다 달라요. 브라우저에서는 이 이름을 쓰지 않고 [보내기] 패널에서 고른 통로가 상대가 돼요.
- 기본 실습 8번 줄: 입력한 글자의 앞뒤 빈칸을 떼고(`strip()`) 모두 소문자로 바꿔요(`lower()`).
- 기본 실습 11번 줄: `key.encode('utf-8')`로 글자를 바이트로 바꿔 `uart.write()`로 보내요. `q`를 치면 반복을 끝내고 포트를 닫아요.
- 심화 실습 9\~10번 줄: MediaPipe의 얼굴 인식(Face Detection) 모델을 준비해요. 50% 넘게 확실할 때만 얼굴로 봐요.
- 심화 실습 24번 줄: 얼굴을 찾았으면 `detected`가 참(True)이에요.
- 심화 실습 26\~33번 줄: 앞 상태(`face_present`)와 달라졌을 때만 `b'a'`나 `b'b'`를 보내고, 상태를 새로 적어 둬요.
- 심화 실습 35\~40번 줄: 찾은 얼굴 둘레에 초록 네모를 그려요.

::예제[2,3]

### 실행하고 결과 보기 — 기본 실습

1. 둘째 예제(기본 실습)의 [이 자리에서 실습실 열기]를 눌러요. 처음 한 번은 파이썬을 받느라 조금 걸려요.
2. 실습실 아래쪽 [보내기] 패널에서 "보드에서 열 예제"가 "3-1-2 기본 — UART로 받은 a·b로 레이저 켜고 끄기(사이트판)"인지 보고 [한 화면에 가상 보드 열기]를 눌러요. 입력·출력 칸 아래에 ESP32 실습실(보드 쪽)이 열려요.
3. 보드 쪽 [실행]을 **먼저** 눌러요. 보드가 글자를 기다려요(아무 일도 일어나지 않는 것이 정상이에요).
4. 컴퓨터 쪽 [실행]을 누르고, 콘솔 아래 입력줄에 `a`를 적어 Enter를 눌러요. 보드 그림의 레이저가 켜져요. `b`를 보내면 꺼지고, `q`를 보내면 끝나요.

컴퓨터 쪽 콘솔에는 이렇게 나와요. `Sent: a`는 가상 변환기로 실제로 보낸 글자를 사이트가 알려 주는 줄이에요.

```text
입력 (a, b, q): a
Sent: a
a 문자를 시리얼로 전송했습니다.
입력 (a, b, q): b
Sent: b
b 문자를 시리얼로 전송했습니다.
입력 (a, b, q): q
프로그램을 종료합니다.
```

실물 보드에서는 이렇게 보여요(원고 192쪽).

![같은 ESP32 보드, USB-UART 변환기, 레이저 모듈 연결에서 레이저 빛이 꺼진 사진](/images/lessons/3-1-2/result-laser-off.webp)

:::확인
- 보드 쪽을 먼저 [실행]했어요. [보내기] 패널에 "가상 ESP32 보드와 이어졌어요"가 보여요.
- `a`를 보내면 보드 그림의 레이저가 켜지고, `b`를 보내면 꺼져요.
- 보드 그림의 USB-UART 변환기에 115200bps가 적혀 있고, 보낸 바이트 수가 늘어나요.
:::

:::왜그럴까
입력한 `a`는 `encode()`로 바이트 97이 되어 변환기의 TX 선을 타고 보드의 RX 핀(GPIO16)으로 들어가요. 보드는 `uart.any()`로 도착한 것을 알아채고 `readline()`으로 읽은 뒤 `decode()`로 글자 `'a'`로 되돌려요. 조건문이 `'a'`와 같은지 견줘 레이저를 켜요. 3-1-1에서 배운 "글자 → 바이트 → 글자" 과정이 진짜 선을 탄 거예요.
:::

### 실행하고 결과 보기 — 심화 실습

1. 셋째 예제(심화 실습)의 [이 자리에서 실습실 열기]를 누르고, 기본 실습과 같이 [한 화면에 가상 보드 열기] → 보드 쪽 [실행]을 눌러요.
2. 웹캠이 없으면 "입력 소스"에서 **재생 입력**(합성 좌표)을 골라요. 사람을 찍은 영상이 아니라 실습실이 계산으로 만든 얼굴 점이에요.
3. 컴퓨터 쪽 [실행]을 누르면 얼굴이 보이는 순간 `a`가 한 번 가서 레이저가 켜져요.
4. 얼굴을 사라지게 해 봐요. 웹캠이면 카메라 밖으로 비켜서고, 재생 입력이면 "재생 동작"을 손 동작(예: 손가락 0\~5개 펴기)으로 바꿔요. `b`가 한 번 가서 레이저가 꺼져요.

```text
Sent: a
Face detected → a 전송
Sent: b
Face lost → b 전송
```

:::확인
- 출력 창에서 얼굴 둘레에 초록 네모가 그려져요.
- 얼굴이 계속 보이는 동안에는 콘솔에 `Face detected → a 전송`이 한 번만 나와요.
- 얼굴이 사라지면 `Face lost → b 전송`이 나오고 레이저가 꺼져요.
:::

:::왜그럴까
심화 실습 코드는 장면마다 얼굴을 찾지만, 26번 줄 `if detected != face_present:`가 앞 장면의 상태와 달라졌을 때만 글자를 보내요. 얼굴이 계속 보이면 `detected`와 `face_present`가 둘 다 참이라 아무것도 보내지 않아요. 그래서 보드의 버퍼에 글자가 쌓이지 않고, 레이저가 바로바로 반응해요.
:::

## 바꿔보기

:::바꿔보기
1. 기본 실습 4번 줄의 통신 속도를 `9600`으로 바꾸고 `a`를 보내 보세요. 레이저가 켜질까요? 보드 쪽은 그대로 115200이에요.
2. 보드 쪽 12번 줄의 `sleep(1)`을 `sleep(5)`로 바꿔 보드 쪽을 다시 [실행]해요. `a`를 보내 레이저가 켜진 5초 안에 `b`와 `a`를 잇달아 보내 보세요. 레이저는 어떻게 될까요?
3. 심화 실습 26번 줄의 `if detected != face_present:`를 `if True:`로 바꿔(앞의 들여쓰기는 그대로) 실행해 보세요. 콘솔의 `Face detected → a 전송` 줄이 어떻게 달라지나요?
:::

:::왜그럴까[왜 레이저가 꺼지지 않을까? — 글자가 붙어 버렸어요]
보드가 5초 쉬는 동안 도착한 `b`와 `a`는 버퍼에 차례로 쌓여요. 보드가 깨어나 `readline()`을 부르면 쌓인 글자를 한꺼번에 읽어 `'ba'`가 돼요. `'ba'`는 `'a'`도 `'b'`도 아니라서 아무 일도 하지 않아요. 원고 187쪽의 말처럼 보낼 때 끝에 줄바꿈 문자를 붙이면(기본 실습 11번 줄을 `uart.write((key + '\n').encode('utf-8'))`로) 보드가 한 줄씩 끊어 읽어서 `b`와 `a`를 따로 알아봐요.
:::

:::왜그럴까[속도를 9600으로 바꾸면 왜 켜지지 않을까?]
보드는 1초에 115,200비트 빠르기로 신호를 끊어 읽는데, 컴퓨터는 9,600비트 빠르기로 천천히 보내요. 보드는 한 비트를 여러 번 읽게 되어 `'a'`가 아닌 엉뚱한 바이트를 받아요. 오류는 나지 않고 레이저만 켜지지 않아서, 통신이 안 될 때는 양쪽 속도부터 확인해요.
:::

:::오류
- `SerialException`이 나면 보드 화면을 열지 않고 컴퓨터 쪽만 [실행]한 거예요. [보내기] 패널의 [한 화면에 가상 보드 열기]를 먼저 눌러요([오류 사전](/help/errors/#comm-serial-no-peer)).
- 심화 실습을 `q`로 끝내면 48번 줄에서 `NameError: name 'ser' is not defined`가 나요. 원고 코드의 오타예요. 포트를 연 변수 이름은 `uart`이니 `uart.close()`로 고쳐요([오류 사전](/help/errors/#name-error)).
:::

### 지도안 요약(50분, 사이트가 제안하는 흐름)

1. 도입(5분): 3-1-1의 "글자 → 바이트 → 글자"를 떠올리고, "왜 배울까" 그림으로 오늘 만들 얼굴 인식 알림 장치를 보여 줘요.
2. 전개 1(10분): 시리얼 통신, TX와 RX를 엇갈려 잇기, USB-UART 변환기, 통신 속도, UART2를 쓰는 까닭을 그림으로 짚어요. 실물 키트가 있으면 원고 배선 그림대로 보여 줘요.
3. 전개 2(15분): 보드 쪽 코드를 함께 읽고, 한 화면에 두 실습실을 열어 기본 실습(a·b로 레이저 켜고 끄기)을 해요.
4. 전개 3(13분): 심화 실습을 재생 입력(또는 웹캠)으로 돌려 얼굴이 보일 때 a, 사라질 때 b가 한 번씩 가는지 보고, 바꿔보기 1·2를 해요.
5. 정리(7분): 확인 퀴즈를 풀고, 도전 과제(원고의 "해 보기")는 모둠 과제로 내요. 실물 보드는 [보드에 저장] 단추(main.py로 저장)를 안내해요.

### 평가 포인트

3단원 원고에는 차시별 자기 평가 표가 없어요. 원고 184쪽 단원 성취 계획 가운데 이 차시와 이어지는 문항이에요.

- 시리얼 통신의 개념을 설명할 수 있는가?
- 다양한 출력 장치를 연결할 수 있는가?
- 프로그래밍을 통해 출력 장치를 제어할 수 있는가?

학습 목표를 자기 평가 문항으로 바꿔 쓸 수도 있어요(사이트가 만든 문항): "USB-UART 변환기로 컴퓨터와 보드를 잇고 TX와 RX를 설명할 수 있는가?", "얼굴 인식 결과를 글자로 보내 보드의 출력 장치를 제어할 수 있는가?"

관찰할 곳: TX와 RX를 왜 엇갈려 잇는지, 속도를 왜 맞추는지 자기 말로 설명하는지 봐요. 바꿔보기 2에서 글자가 붙는 까닭을 "버퍼"와 "줄바꿈"으로 설명하면 3-1-1과 이어서 이해한 거예요. 도전 과제에서는 부품, 라이브러리, 주고받을 글자, 보드 쪽 동작을 빠짐없이 정리했는지 봐요.

### 자주 막히는 곳

- 보드 쪽 [실행]을 잊어요. 보드가 돌지 않을 때 온 글자는 실물처럼 사라지고, 컴퓨터 쪽 콘솔에 "가상 보드가 돌고 있지 않아요" 안내가 나와요.
- 컴퓨터 쪽만 열고 [실행]하면 4번 줄에서 `SerialException`이 나요. [한 화면에 가상 보드 열기]로 보드 쪽을 먼저 열게 해요.
- `"COM10"`을 고쳐야 하냐고 물어요. 브라우저에서는 포트 이름을 쓰지 않아요. 진짜 PC에서는 장치 관리자에 보이는 변환기의 COM 번호를 적어요(보드용 포트와 다른 번호예요).
- 자료의 보드 코드 파일(원본 f082)은 `import time`만 하고 `sleep(1)`을 불러서, `a`를 받는 순간 12번 줄에서 `NameError`로 멈춰요(원고 190쪽 인쇄본은 `from time import sleep`이라 괜찮지만, 191쪽 boot.py 저장 화면의 코드는 파일처럼 `import time`이에요). boot.py판 원본(f083)은 4번 줄 `PinOUT` 오타로 실행하자마자 멈춰요. [보내기] 패널의 "보드에서 열 예제"에서 원본 파일을 골라 오류를 찾아 고치는 활동으로 써도 좋아요.
- 재생 입력에서는 얼굴이 늘 보여 `b`가 가지 않아요. "재생 동작"을 손 동작으로 바꾸면 얼굴이 사라진 것과 같아요.
- 실물 연결에서는 USB가 두 개(보드용, 변환기용)예요. ESP32 실습실 [실제 보드] 탭에서는 USB 데이터 포트 칸에서 변환기 포트를 따로 열어요.
- ESP32 실습실의 변환기 조작 칸 아래 "실물 연결" 안내는 "변환기는 자기 USB로 전원을 받으니 VCC는 잇지 않아요"라고 해서, VCC도 잇는 원고 배선과 달라요. 키트로 아직 확인하지 못해 본문은 원고를 따랐어요. 실물로 할 때는 키트 설명서를 먼저 확인해요.

### 원고에서 바꾼 곳

- 원고 189\~194쪽(학습 목표, 본문, 회로 구성, 기본·심화 실습, 해 보기)을 차시 틀에 맞게 옮기고 문장을 다듬었어요. 해 보기 1·2는 도전 과제 1·2로 옮겼어요.

- 190쪽 코드는 `UART(2, baudrate=115200, tx=16, rx=17)`인데 주석(TX 17번, RX 16번)과 배선 그림(변환기 TX → GPIO 16)과 방향이 반대예요. 사이트판은 주석과 그림에 맞춰 `tx=17, rx=16`으로 고쳤어요(실물 확인 전). 자료의 코드 파일(f082)은 `import time`만 하고 `sleep(1)`을 불러 `NameError`가 나서, 원고 190쪽처럼 `from time import sleep`으로 고쳤어요. 두 줄 모두 줄 끝에 `# [사이트판]`이 있어 줄 번호는 원본과 같아요.
- 191쪽 Thonny의 boot.py 저장 절차는 사이트의 [보드에 저장] 단추(main.py로 저장)로 바꿨어요. 원래 설치·저장 절차는 교사용 자료실의 ["진짜 PC에서 돌리기"](/teacher/real-pc/#시리얼-통신3-1-2)로 옮겼어요. Thonny 저장 창 캡처는 쓰지 않았어요.
- 192쪽 "Local Python으로 변경하여 실행하기"는 브라우저의 영상처리 실습실에서 실행하는 흐름으로 바꿨어요. 193쪽 원고의 포트 이름은 `COM5`, 코드 파일은 `COM10`이에요(브라우저에서는 쓰지 않아요).
- 194쪽 결과 화면은 사람 얼굴 사진이라 쓰지 않고, 재생 입력(합성 얼굴 점)으로 직접 확인하게 했어요. 원고 49번 줄(코드 파일 48번 줄)의 `ser.close()` 오타는 원본 그대로 두고 오류 고치기 활동으로 썼어요.
- 바꿔보기의 줄바꿈 이야기는 원고 187쪽(3-1-1)의 "메시지 끝에 줄바꿈 문자를 붙인다"를 이 차시 코드로 확인하게 한 거예요. 자료의 컴퓨터 쪽 코드는 줄바꿈 없이 보내고, 보드의 `readline()`은 잠깐 기다려도 줄바꿈이 오지 않으면 그때까지 온 것을 돌려줘요.
