## 학습목표

- 영상 처리로 찾은 손끝 좌표(x, y)를 블루투스(BLE)로 ESP32에 보낼 수 있어요.
- ESP32가 받은 글자 데이터를 숫자로 바꿔 RGB LED 같은 출력 장치를 제어할 수 있어요.
- 블루투스 기기가 광고 이름을 알리고, 컴퓨터가 그 이름을 골라 연결하는 과정을 설명할 수 있어요.

## 왜 배울까

3-1-2에서는 USB 선으로 컴퓨터와 보드를 이었어요. 무선 이어폰이나 스마트워치처럼, 선 없이 가까운 기기끼리 데이터를 주고받는 기술이 블루투스예요. 이번에는 카메라로 찾은 손가락 위치를 블루투스로 보내, 선 없이 보드의 LED 색을 바꿔요.

## 핵심 개념

### 블루투스 통신

:용어[블루투스]{항목=ble}(Bluetooth)는 짧은 거리에서 무선으로 데이터를 주고받는 기술이에요. 블루투스 통신은 보통 글자(문자열)나 바이트 단위로 데이터를 주고받아요. 보내는 쪽은 값을 글자로 바꿔 보내고, 받는 쪽은 이를 다시 숫자 데이터로 바꿔 써요.

특히 BLE(Bluetooth Low Energy, 저전력 블루투스)는 전기를 적게 쓰며 통신할 수 있어서 웨어러블 기기(스마트워치처럼 몸에 차는 기기)나 스마트 가전제품에 널리 쓰여요. 한 번에 보내는 글자는 20바이트 정도로 짧아서, 좌표나 명령 같은 짧은 메시지를 보내기에 알맞아요.

### 광고와 연결 — 기기를 이름으로 찾아요

블루투스 보드는 주변에 "나는 ESP32예요"처럼 자기 이름을 알리는 신호를 계속 보내요. 이것을 :용어[광고](advertising)라고 해요. 컴퓨터나 스마트폰은 광고를 듣고, 목록에 뜬 이름 가운데 내 보드를 골라 연결해요.

<figure>
<img src="/images/lessons/3-1-3/ble-advertise.svg" alt="ESP32 보드가 전파로 나는 ESP32-07이에요라고 이름을 알리고, 컴퓨터의 기기 고르기 목록에 ESP32-03, ESP32-07, ESP32-12가 보여 그 가운데 ESP32-07을 골라 연결하는 그림. 아래에 1 보드가 ESP32BLE.init으로 이름을 알리고 2 컴퓨터가 이름을 보고 골라 연결하고 3 이어지면 보드가 ble.read로 글자를 읽는 차례가 적혀 있다" width="640" height="356">
<figcaption>교실에 보드가 여러 대면 모두 "ESP32"로 보여서, 이름에 자리 번호를 붙여 구별해요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

| 코드 | 어느 쪽 | 하는 일 |
| --- | --- | --- |
| `import ESP32BLE` | 보드 | ESP32에서 블루투스로 값을 받고 읽는 기능을 주는 보드 라이브러리를 불러와요. |
| `ble = ESP32BLE.init("ESP32")` | 보드 | 보드를 블루투스 기기로 켜고 "ESP32"라는 이름으로 광고해요. |
| `ble.read()` | 보드 | 새 데이터가 도착했으면 글자를 돌려주고, 없으면 `None`을 돌려줘요. |
| `import bluetooth` | 컴퓨터 | 컴퓨터에서 블루투스 연결과 데이터 보내기를 쉽게 하는 모듈이에요. |
| `b.send("355,152")` | 컴퓨터 | 연결된 보드로 글자를 보내요. |

교과서는 보드가 알려 준 :용어[기기 주소]를 컴퓨터 쪽 코드 `bluetooth.init('주소')`에 붙여 넣어 연결해요. 기기 주소는 기기마다 다른 고유 번호라 개인정보처럼 조심해서 다뤄야 해요. 브라우저는 보안 때문에 기기 주소를 알려 주지도, 주소로 연결하지도 않아요. 그래서 이 사이트는 **광고 이름**을 보고 골라요. 이름에는 `ESP32-07`처럼 자리 번호만 붙이고, 이름이나 학번, 전화번호는 넣지 않아요(주변 사람 누구에게나 보여요).

### 좌표가 보드까지 가는 길

카메라로 손가락 위치를 찾은 뒤, 블루투스로 ESP32에 전해요. 데이터의 흐름은 다음과 같아요.

| 단계 | 하는 일 |
| --- | --- |
| 카메라 입력 | OpenCV와 MediaPipe로 검지 끝의 좌표(x, y)를 찾아요. |
| 데이터 보내기 | `b.send("120,200")` 모양의 글자로 블루투스를 통해 보내요. |
| 데이터 받기 | ESP32가 글자를 읽고, 쉼표(,)를 기준으로 값을 나눠요. |
| 데이터 쓰기 | 좌표 값에 따라 LED 색을 골라 켜요. |

받은 글자는 3-1-1에서 배운 대로 나누고 바꿔서 써요(:용어[파싱]).

| 처리 단계 | 코드 예 | 설명 |
| --- | --- | --- |
| 글자 나누기 | `data.split(',')` → `['120', '200']` | 쉼표를 기준으로 글자를 나눠 목록으로 만들어요. |
| 정수로 바꾸기 | `finger_x = int('120')` | 숫자 모양 글자를 정수로 바꿔요. |
| 값 쓰기 | `if finger_x < 100:` 빨간 LED 켜기 | 바꾼 좌표를 조건문으로 판단해 LED 색을 골라요. |

### 좌표로 색 정하기

보드는 받은 좌표로 켤 색을 골라요. x가 100보다 작으면 빨강, 그렇지 않고 y가 100보다 작으면 초록, 둘 다 아니면 파랑이에요. 카메라 화면의 좌표는 왼쪽 위가 (0, 0)이고, y는 아래로 갈수록 커져요.

<figcaption>조건은 위에서부터 차례로 봐요. 왼쪽 위 구석은 두 조건이 다 맞지만 x를 먼저 보니 빨강이에요. 사이트가 직접 그린 그림이에요.</figcaption>

원고의 도우미 로봇이 짚은 세 가지도 기억해요.

- 기준값(:용어[임곗값] 100)은 화면 해상도와 활동 목표에 맞게 고쳐야 해요.
- 프로토콜 약속에 따라 보내는 쪽과 받는 쪽은 `x,y` 모양을 똑같이 써야 해요. 모양을 바꾸면 두 쪽 코드를 함께 고쳐요.
- 예외 처리(`try`, `except`)로 잘못된 모양이나 일부만 받은 값이 와도 프로그램이 멈추지 않게 해요.

### 받은 값은 한 칸 우편함에

3-1-2의 UART는 도착한 글자가 차례로 쌓이는 "줄 서는 우편함"이었어요. 이번에 쓰는 ESP32BLE 라이브러리는 받은 값을 한 칸에만 두고, 새 값이 오면 앞 값을 덮어써요.

<img src="/images/lessons/3-1-3/mailbox.svg" alt="두 우편함 비교 그림. 왼쪽 3-1-2 UART는 도착한 a, b, a가 줄 서서 쌓이고 보드가 차례대로 모두 읽는다. 오른쪽 3-1-3 ESP32BLE는 한 칸 우편함이라 350,150과 352,151 위에 355,152가 덮어써져 ble.read가 마지막 값 하나만 받는다. 아래에 보드가 LED를 켜고 끄느라 약 2초에 한 번 read를 부르므로 그사이 온 좌표 가운데 마지막 것만 읽는다고 적혀 있다" width="640" height="318">

### 코드 읽기 — 보드 쪽(받는 쪽)

아래 첫째 예제예요. 교과서 196\~197쪽 코드에 설명 주석을 단 파일이라 줄 번호가 교과서보다 길어요.

- 1\~3번 줄: 블루투스 라이브러리(ESP32BLE), `Pin`, `sleep`을 불러와요.
- 6번 줄: 보드를 블루투스 기기로 켜고 "ESP32"라는 이름으로 광고를 시작해요.
- 9\~14번 줄: 25, 26, 27번 핀에 빨강, 초록, 파랑 LED를 연결하고 `led` 목록으로 묶어요. 주석에 적힌 핀 번호(27, 32, 33)는 코드와 달라요. 교과서 회로(196쪽)와 같은 코드의 25, 26, 27이 맞아요.
- 17번 줄: 블루투스로 받은 데이터를 읽어요. 새 데이터가 없으면 `None`이에요.
- 22\~24번 줄: 받은 글자를 쉼표로 나누고 두 값을 정수로 바꿔요.
- 31\~45번 줄: x가 100보다 작으면 빨강, 아니고 y가 100보다 작으면 초록, 둘 다 아니면 파랑 LED를 1초 켰다가 끄고 1초 기다려요.
- 47\~48번 줄: 값을 바꾸다가 오류가 나면 멈추지 않고 오류 내용을 찍어요(예외 처리).
- 49\~54번 줄: 받은 데이터가 없으면 LED를 모두 끄고 1초 기다려요.

### 코드 읽기 — 컴퓨터 쪽(보내는 쪽)

둘째 예제예요.

- 3, 6번 줄: 컴퓨터용 `bluetooth` 모듈을 불러와 보드와 연결해요. 교과서는 괄호 안에 보드의 기기 주소를 적지만, 이 파일은 주소를 `XX:XX:XX:XX:XX:XX`로 가렸어요. 브라우저는 주소를 쓰지 않고 연결된 보드로 보내요.
- 9\~24번 줄: 손을 하나만 찾도록 MediaPipe Hands를 준비하고, 관절 선과 점의 색과 굵기를 정해요.
- 27\~30번 줄: 카메라를 열고 가로 1080을 부탁한 뒤, 실제로 받은 가로·세로 크기를 `width`, `height`에 담아요. 카메라마다 줄 수 있는 크기가 달라서 실제 크기로 계산해야 해요.
- 44\~46번 줄: 검지 끝(8번 점)의 :용어[정규화 좌표](0\~1)에 화면 크기를 곱해 픽셀 좌표로 바꿔요.
- 49번 줄: 두 값을 쉼표로 이은 글자 `"355,152"`를 블루투스로 보내요.

### 실행하고 결과 보기 ① 보드 쪽만 — 광고 이름 확인하기

1. 첫째 예제(보드 쪽)의 [이 자리에서 실습실 열기]를 누르고 [실행]을 눌러요.
2. 보드 그림 아래 **"블루투스(BLE) 조작"** 칸을 봐요. "광고 중(이름 ESP32)"이 보이면 보드가 이름을 알리고 있는 거예요. 보드 그림의 블루투스 부품에도 "이름 ESP32"가 보여요.
3. [연결]을 누르면 "연결됨(ESP32)"으로 바뀌어요. 이 칸이 컴퓨터나 스마트폰 노릇을 해요.
4. "좌표 보내기"에서 x를 50쯤으로 내리고 [좌표 보내기]를 눌러요. 빨간 LED가 1초 켜졌다 꺼져요.

보드 쪽 콘솔에는 이렇게 나와요. 첫 줄의 주소는 가상 보드가 실행할 때마다 지어내는 값이에요(실물 보드의 주소가 아니에요).

```text
ESP32 블루투스 주소: XX:XX:XX:XX:XX:XX
Received finger_x: 50, finger_y: 240
```

:::확인
- "블루투스(BLE) 조작" 칸에 "광고 중(이름 ESP32)"이 보였어요.
- [연결] 뒤 좌표를 보내면 콘솔에 `Received finger_x: …`가 찍혀요.
- x가 100보다 작으면 빨강, x와 y가 모두 100보다 크면 파랑 LED가 켜져요.
:::

:::왜그럴까
보낸 좌표는 `"50,240"`이라는 글자예요. 보드는 22\~24번 줄에서 쉼표로 나눠 `['50', '240']`을 만들고 `int()`로 50과 240이라는 정수로 바꿔요. 31번 줄에서 50 < 100이 참이라 빨간 LED를 켜요. y는 x 조건이 거짓일 때만 보므로 여기서는 쓰지 않아요.
:::

### 실행하고 결과 보기 ② 컴퓨터와 짝으로 — 4단원 통합 실습실

1. [4단원 통합 실습실](/labs/unit4/)을 열고 두 칸이 준비될 때까지 기다려요(파이썬을 두 벌 받아요).
2. [짝 예제 바꾸기]를 펼쳐 "(3단원) 3-1-3 — 손끝 좌표로 RGB LED"의 [이 짝 불러오기]를 눌러요.
3. "카메라 입력"에서 **재생 입력**(합성 좌표)을 골라요. 웹캠이 있으면 웹캠으로 해도 돼요.
4. [함께 실행]을 눌러요. 보드 코드 → 블루투스 연결 → 컴퓨터 코드 차례로 돌아가요.

컴퓨터 칸과 보드 칸의 콘솔에는 이런 줄이 이어져요(숫자는 손의 위치에 따라 달라요).

```text
컴퓨터 칸   Sent: 475, 286
보드 칸     Received finger_x: 475, finger_y: 286
```

:::확인
- 컴퓨터 칸의 출력 창에 손 관절 점과 선이 그려져요.
- 컴퓨터 칸 콘솔에 `Sent: …`가 장면마다 나오고, 보드 칸 콘솔에 `Received finger_x: …`가 2초쯤에 한 번씩 나와요.
- 재생 입력의 손은 화면 가운데쯤이라 주로 파란 LED가 켜져요. 웹캠이라면 손을 화면 왼쪽 끝으로 옮겨 빨강을 켜 봐요.
:::

:::왜그럴까
컴퓨터는 장면마다 좌표를 보내지만, 보드는 LED를 켜고 끄는 2초 동안 `ble.read()`를 부르지 않아요. 그사이 온 좌표는 한 칸 우편함에 계속 덮어써져서, 보드는 다음에 읽을 때 마지막 좌표 하나만 받아요. 그래서 보드 칸의 `Received` 줄이 컴퓨터 칸의 `Sent` 줄보다 훨씬 적어요.
:::

## 바꿔보기

:::바꿔보기
1. 보드 쪽 31번 줄의 `100`을 `300`으로 바꿔 다시 [실행]하고, 블루투스 조작 칸에서 x를 200쯤으로 보내 보세요. 어떤 LED가 켜질까요?
2. 블루투스 조작 칸의 "글자 보내기"에 쉼표 대신 빗금을 넣은 `120/200`을 적어 보내 보세요. 보드 프로그램이 멈출까요?
3. 보드 쪽 6번 줄의 이름을 `"ESP32-07"`처럼 자리 번호를 붙여 바꾸고 다시 [실행]해 보세요. 블루투스 조작 칸의 광고 이름이 어떻게 바뀌나요?
:::

:::왜그럴까[왜 빗금으로 보내도 멈추지 않을까?]
`'120/200'`은 쉼표가 없어서 나누면 조각이 하나뿐이고, `int('120/200')`에서 오류가 나요. 하지만 이 코드는 20번 줄 `try:`로 감싸 두었다가 47번 줄 `except`에서 오류를 잡아 `Error processing data: 120/200, …`만 찍고 다음 반복으로 넘어가요. 원고의 말처럼, 무선 통신에서는 잘못된 모양이나 일부만 도착한 값이 올 수 있어서 예외 처리가 꼭 필요해요.
:::

:::오류
컴퓨터 쪽 예제를 영상처리 실습실에서만 [실행]하면 콘솔에 "블루투스로 이을 보드가 아직 없어요"가 나오고 좌표를 보내지 않아요. 컴퓨터 쪽 블루투스 코드는 같은 화면의 가상 보드나, 블루투스 칸에서 이은 실제 보드에만 닿아요. 가상 보드로 하려면 [4단원 통합 실습실](/labs/unit4/)에서 짝으로 돌려요.
:::

3-1-1에서 배운 "결괏값만 보내기"로 바꿔 보세요. 컴퓨터가 검지 x 위치를 보고 왼쪽이면 `a`, 오른쪽이면 `b`, 가운데면 `c`만 보내고, 보드는 받은 글자로 색을 골라 켜게 해요.

| 바꿀 곳 | 생각할 내용 |
| --- | --- |
| 컴퓨터 쪽 49번 줄 | 좌표 대신 어떤 조건으로 `a`, `b`, `c`를 골라 보낼까요? |
| 보드 쪽 22\~45번 줄 | 글자를 나누거나 정수로 바꿀 필요가 있을까요? 조건문을 어떻게 바꿀까요? |
| 좋은 점과 아쉬운 점 | 좌표를 보낼 때와 무엇이 달라지나요? |

:::힌트
컴퓨터 쪽은 `if finger_x < 100: b.send('a')`, `elif finger_x > width - 100: b.send('b')`, `else: b.send('c')`처럼 쓸 수 있어요. 보드 쪽은 `if data == 'a': led[0].on()`처럼 받은 글자를 바로 견주면 돼요. 블루투스 교안의 손가락 제어 실습이 이 방식이에요. 보드 코드가 간단해지는 대신, 보드가 더 자세한 위치를 알 수는 없어요.
:::

::::도전[도전 과제 2: 보내는 횟수 줄이기]

:::힌트
반복문 앞에 `last = None`을 두고, 보낼 글자를 `message = f"{finger_x},{finger_y}"`로 만든 뒤 `if message != last:`일 때만 `b.send(message)` 하고 `last = message`로 적어 둬요. 좌표는 손이 조금만 떨려도 바뀌니, 좌표를 10으로 나눈 몫(`finger_x // 10`)을 견주거나 도전 과제 1처럼 구역이 바뀔 때만 보내면 훨씬 줄어요(3-1-1의 "값이 바뀔 때만 보내기").

### 지도안 요약(50분, 사이트가 제안하는 흐름)

1. 도입(5분): 무선 이어폰, 스마트워치 같은 블루투스 기기 경험을 나누고, 3-1-2의 선 연결과 견줘요.
2. 전개 1(12분): 블루투스와 BLE, 광고와 이름으로 연결하기, 좌표가 보드까지 가는 길과 변환 표를 짚어요.
3. 전개 2(13분): 보드 쪽만 돌려 광고 이름을 확인하고, 블루투스 조작 칸에서 좌표를 보내 색 지도대로 켜지는지 확인해요.
4. 전개 3(13분): 4단원 통합 실습실에서 짝으로 돌려 한 칸 우편함을 관찰하고, 바꿔보기를 해요.
5. 정리(7분): 확인 퀴즈를 풀고, 도전 과제는 과제로 내요.

### 평가 포인트

3단원 원고에는 차시별 자기 평가 표가 없어요. 원고 184쪽 단원 성취 계획 가운데 이 차시와 이어지는 문항이에요.

- 블루투스를 활용해 출력 장치를 제어할 수 있는가?
- 프로그래밍을 통해 출력 장치를 제어할 수 있는가?

학습 목표를 자기 평가 문항으로 바꿔 쓸 수도 있어요(사이트가 만든 문항): "손끝 좌표를 블루투스로 보내고 보드에서 숫자로 바꿔 쓸 수 있는가?", "광고 이름으로 블루투스 기기를 찾아 연결하는 과정을 설명할 수 있는가?"

관찰할 곳: 받은 글자를 나누고 정수로 바꾸는 까닭을 말하는지, 좌표 지도에서 조건문의 차례(왼쪽 위 구석)를 설명하는지 봐요. 도전 과제 1에서 좌표 보내기와 결괏값 보내기의 좋은 점과 아쉬운 점을 견주면 3-1-1의 내용과 이어서 이해한 거예요.

### 자주 막히는 곳

- 영상처리 실습실에서 컴퓨터 쪽만 돌리고 좌표가 가지 않는다고 해요. 컴퓨터 쪽 블루투스 흉내는 같은 화면의 가상 보드에만 닿으니 4단원 통합 실습실로 안내해요.
- 보드 쪽 [실행] 전에는 [연결]을 누를 수 없어요(보드가 광고를 시작해야 이어져요).
- 재생 입력의 손은 화면 가운데쯤에 있어 파란 LED가 주로 켜져요. 빨강과 초록은 보드 쪽 블루투스 조작 칸의 [좌표 보내기]로 확인하게 해요.
- 컴퓨터 칸 콘솔에 `Sent: 475,286`과 `Sent: 475, 286`처럼 비슷한 줄이 두 가지 보여요. 빈칸 없는 줄은 흉내 모듈이 실제로 보낸 글자, 빈칸 있는 줄은 코드 51번 줄의 `print`예요.
- 기준값 100은 카메라 크기에 따라 뜻이 달라요. 코드는 가로 1080을 부탁하지만 브라우저 카메라는 보통 640×480으로 와요.
- 실제 보드로 할 때는 ESP32 실습실의 블루투스 칸 [블루투스 보드 연결]로 이름을 골라요(컴퓨터용 Chrome이나 Edge). 보드에는 ESP32BLE.py가 있어야 하는데, [보드에 저장]이 함께 올려 줘요. 교실에서는 보드 이름에 자리 번호를 붙이게 해요.
- ESP32BLE 라이브러리는 GPIO12에 연결 상태 LED를 켜요. GPIO12에 다른 부품을 달면 겹쳐요(블루투스 교안의 손가락 RGB 예제가 그 경우예요).

### 원고에서 바꾼 곳

- 원고 195\~200쪽(학습 목표, 본문, 회로 구성, 기본 실습)을 차시 틀에 맞게 옮기고 문장을 다듬었어요. 3-1-3 원고에는 해 보기나 학습 활동이 없어서 도전 과제는 사이트가 만들었어요.
- 197쪽 결과 "ESP32 주소값 확인하기"와 198쪽 코드에 실제 기기 주소가 적혀 있어요. 기기 주소는 공개하지 않고, 브라우저에서는 주소로 연결하지 않으므로 "광고 이름 확인하기"로 바꿨어요(PLAN §7.3). 컴퓨터 쪽 예제 파일의 주소는 `XX:XX:XX:XX:XX:XX`로 가렸어요. 주소를 붙여 넣는 원래 방식은 교사용 자료실의 ["진짜 PC에서 돌리기"](/teacher/real-pc/#블루투스-통신3-1-3-iv단원)에 남겨 두었어요.
- 198쪽 bleak 라이브러리 설치 캡처(설치 대상이 MicroPython 장치로 보이는 화면)와 200쪽 "Local Python 3로 변경하여 실행하기"는 브라우저 실습실 흐름으로 바꿨어요.
- 196\~197쪽 인쇄 코드의 조판 오류(`Pin(25, Pin, OUT)`, 초록·파랑 핀 변수 이름 `e`, 세 핀 모두 "빨간 LED"라고 적힌 주석, 초록 분기의 `led[0].off()`)와 198\~200쪽의 오타(`firger_point`, `resulte`, `cv2.cvtcolor`, `cv2.waitkey`, `{finger_y]`)는 사이트 예제 파일(자료의 코드 파일)에서는 바르게 되어 있어요. 본문은 파일의 줄 번호를 따라요.
- 195쪽 흐름의 `b.send('120, 200')`은 쉼표 뒤에 빈칸이 있지만 코드는 빈칸 없이 보내요. `int()`는 앞뒤 빈칸을 무시해서 둘 다 돼요.
- 200쪽 결과 화면은 사람 얼굴 사진이라 쓰지 않고, 재생 입력(합성 손 좌표)으로 직접 확인하게 했어요.
- "받은 값은 한 칸 우편함에"는 원고에 없는 설명이에요. 보드가 2초에 좌표 하나만 처리하는 까닭을 ESP32BLE.py의 동작(받은 글자를 한 칸에 덮어씀)으로 사이트가 풀어 썼어요.
:::
