## 학습목표

- MediaPipe와 PyAutoGUI를 활용해 손가락 동작을 알아볼 수 있어요.
- MediaPipe와 PyAutoGUI를 활용해 마우스 커서를 제어할 수 있어요.
- 손가락 좌표를 실제 화면 해상도에 맞게 바꿔 마우스 커서를 제어할 수 있어요.

## 왜 배울까

우리는 보통 마우스와 키보드로 컴퓨터를 조작해요. 손가락 끝의 움직임만으로 컴퓨터를 조작할 수 있다면 어떨까요? 이번 차시에서는 손 인식 기술과 좌표 매핑으로, 손대지 않고 컴퓨터를 조작하는 새로운 방식을 직접 만들어요.

## 핵심 개념

### 손 인식과 화면 제어의 원리

MediaPipe는 웹캠 영상에서 손을 알아보고, 손가락 끝과 관절을 포함한 21개의 :용어[특징점]{항목=landmark}(랜드마크) 좌표를 실시간으로 알려 줘요. 엄지와 검지의 상대 위치로 동작을 알아보거나, 검지의 위치로 마우스 커서를 제어할 수 있어요.

단, MediaPipe의 좌표는 :용어[정규화 좌표]예요. 정규화는 데이터를 일정한 범위로 맞추는 일로, 보통 0과 1 사이 값으로 바꿔요. 그래서 모니터 해상도에 맞는 실제 좌표로 바꿔야 해요. 이때 **PyAutoGUI** 라이브러리를 쓰면 화면 크기를 불러와 손 좌표를 바꾸고 마우스 커서를 옮길 수 있어요. PyAutoGUI는 파이썬 코드로 마우스와 키보드를 조작하는 라이브러리예요.

| 이 차시에서 쓰는 PyAutoGUI 함수 | 하는 일 |
| --- | --- |
| `pyautogui.size()` | 지금 모니터의 가로, 세로 해상도(픽셀 수)를 알려 줘요. |
| `pyautogui.moveTo(x, y)` | 마우스 커서를 화면의 (x, y) 자리로 옮겨요. |
| `pyautogui.screenshot("파일 이름")` | 지금 화면을 찍어 그림 파일로 저장해요. |

### 좌표를 화면 해상도에 맞게 바꾸기(좌표 매핑)

검지의 위치는 영상 안의 상대 좌표라서, 모니터 해상도를 곱해 실제 픽셀 좌표로 바꾼 뒤 커서를 옮겨요. 컴퓨터마다 모니터 크기와 해상도가 다르니, 해상도를 숫자로 정해 두지 않고 실행하는 컴퓨터에서 불러와요.

<figcaption>정규화 좌표 × 화면 크기 = 커서 자리예요. 사이트가 직접 그린 그림이에요.</figcaption>

### 동작 판별 — 엄지가 검지보다 위에 있을까?

영상의 y 좌표는 화면 위쪽이 작고 아래쪽이 커요. 그래서 엄지 끝(4번 점)의 y가 검지 끝(8번 점)의 y보다 작으면, 엄지가 검지보다 위에 있다는 뜻이에요. 이때 화면을 캡처해요.

<figure>
<img src="/images/lessons/3-1-4/thumb-above.svg" alt="y 좌표는 위가 0, 아래가 1이라는 세로 화살표와 두 손 그림. 왼쪽 손은 엄지 끝 4번 점 y가 0.30, 검지 끝 8번 점 y가 0.45라 0.30이 더 작아 엄지가 위이므로 캡처하고, 오른쪽 손은 검지를 위로 펴서 검지 끝 y가 0.35, 엄지 끝 y가 0.60이라 캡처하지 않는다" width="640" height="330">

### 프로그램 구조

원고 202쪽의 프로그램 구조예요. 웹캠 영상에서 손을 찾아 동작을 판별하고, 좌표를 바꿔 커서를 옮기거나 화면을 찍어요.

| 차례 | 단계 | 하는 일 |
| --- | --- | --- |
| 1 | 입력 | 웹캠으로 실시간 영상을 받아요. |
| 2 | :용어[프레임] 캡처 | 실시간 영상에서 한 장씩 이미지를 꺼내요. |
| 3 | 손 특징점 찾기 | MediaPipe로 손을 알아보고 손가락 특징점 21개의 좌표를 찾아요. |
| 4 | 동작 판별 | 엄지와 검지의 위치를 견줘 캡처할 동작인지 판단해요. |
| 5 | 커서 위치 매핑 | 검지 끝 좌표를 모니터 해상도에 맞게 바꿔요. |
| 6 | 출력 | 커서를 손가락 위치로 옮기고, 화면을 찍고 알림 글자를 띄워요. |

이 사이트에서는 진짜 마우스 대신 실습실의 **가상 데스크톱**(1920×1080 가상 모니터)이 움직여요. 캡처도 진짜 화면이 아니라 가상 데스크톱을 찍어요. 같은 코드를 진짜 PC에서 돌리면 진짜 마우스가 움직여요.

## 따라하기

카메라가 없어도 실습실의 재생 입력(계산으로 만든 손 좌표)으로 끝까지 할 수 있어요. 기본 실습은 재생 동작 "손가락 0\~5개 펴기", 심화 실습은 "검지로 그리기"가 알맞아요.

### 코드 읽기 — 기본 실습(화면 캡처)

- 2\~4번 줄: OpenCV, MediaPipe, PyAutoGUI를 불러와요.
- 7\~9번 줄: 손 인식 모델을 준비해요. `max_num_hands=1`은 손이 여럿 보여도 한 손만 처리하고, `min_detection_confidence=0.7`은 손이라고 70% 이상 확실할 때만 인정해 잘못 알아보는 일을 줄여요.
- 15\~21번 줄: 웹캠이 열려 있는 동안 한 장씩 읽어 거울처럼 좌우를 뒤집고, MediaPipe가 쓰는 RGB로 바꿔요.
- 24\~29번 줄: 손 특징점을 찾고, 손이 보이면 특징점과 연결선을 그려요.
- 32\~33번 줄: 엄지 끝(`THUMB_TIP`, 4번)과 검지 끝(`INDEX_FINGER_TIP`, 8번)의 좌표를 꺼내요.
- 36\~39번 줄: 엄지 끝이 검지 끝보다 위에 있으면 화면을 찍어 `screenshot.png`로 저장하고, 영상에 "Screenshot Captured!"를 초록 글자로 써요.
- 42\~43번 줄: 결과 영상을 보여 주고, 5밀리초 기다리는 동안 `q` 키가 눌리면 끝내요.

### 코드 읽기 — 심화 실습(마우스 커서)

- 12번 줄: `pyautogui.size()`로 모니터의 가로, 세로 해상도를 불러와요.
- 36번 줄: 검지 끝(`INDEX_FINGER_TIP`)의 좌표를 꺼내요.
- 40\~41번 줄: 검지의 정규화 좌표(0.0\~1.0)에 화면 너비와 높이를 곱해 실제 픽셀 좌표로 바꿔요.
- 44번 줄: `pyautogui.moveTo()`로 계산한 자리로 커서를 옮겨요.

1. 둘째 예제의 [이 자리에서 실습실 열기]를 누르고, 웹캠이 없으면 재생 입력의 재생 동작을 "검지로 그리기"로 골라요.

:::확인
- 손을 비추면 실시간으로 손의 특징점이 화면에 그려져요.
- 검지 끝 위치를 따라 가상 데스크톱의 마우스 커서가 움직여요.
- 커서 글의 숫자가 1920×1080 화면 안에서 바뀌어요.
:::

:::왜그럴까
40\~41번 줄이 검지의 정규화 좌표에 화면 크기(1920, 1080)를 곱하기 때문에, 영상 속 손의 위치가 화면 전체 크기로 늘어나 커서가 움직여요. 그런데 카메라 영상 전체를 화면 전체에 1:1로 맞췄기 때문에, 손을 영상 끝까지 뻗기 어려운 만큼 커서도 화면 가장자리에는 잘 닿지 않아요. 손이 조금만 떨려도 커서가 크게 떨리는 것도 같은 까닭이에요.
:::

:::왜그럴까[640과 480을 곱하면 왜 왼쪽 위에만 머물까?]
검지 좌표는 0\~1 사이라서 640을 곱하면 x는 많아야 640, 480을 곱하면 y는 많아야 480이에요. 1920×1080 화면에서 왼쪽 위 3분의 1쯤만 쓰는 셈이에요. 커서를 화면 전체에서 움직이려면 곱하는 수가 화면 크기와 같아야 해서, 12번 줄에서 `pyautogui.size()`로 화면 크기를 불러와요.
:::

:::왜그럴까[왜 한글이 물음표로 나올까?]
이 실습실의 OpenCV(4.11판)가 `cv2.putText()`로 쓰는 글꼴에는 영어 글자, 숫자, 기호만 있어요. 한글 한 글자는 UTF-8로 바이트 3개(3-1-1)라서, 글자마다 `???`처럼 물음표 세 개로 나와요. 한글 알림은 `print()`로 콘솔에 쓰거나, Pillow(PIL) 라이브러리로 한글 글꼴을 써서 그려요.
:::

:::오류
커서가 화면 왼쪽 위 모서리 (0, 0)에 닿으면 `FailSafeException`으로 멈춰요. PyAutoGUI가 마우스를 마구 움직이는 프로그램을 사람이 멈출 수 있게 둔 안전장치예요. 좌표가 화면 안에 머물게 `x = max(1, min(x, screen_width - 2))`처럼 제한해요([오류 사전](/help/errors/#failsafe)).
:::

::::도전[도전 과제 1: 손동작으로 캡처하고 알려 주기]
원고 207쪽 학습 활동 1·2번이에요. 손가락 동작을 알아본 뒤 자동으로 화면을 캡처하고, 캡처가 끝나면 "화면 캡처가 완료되었습니다!" 같은 문장을 알려 주도록 기본 실습 코드를 고쳐 보세요.

| 생각할 것 | 적을 내용 |
| --- | --- |
| 어떤 동작일 때 찍을까요? | 예: 엄지와 검지가 특정 위치에 오면 |
| 몇 번 찍을까요? | 동작하는 동안 계속? 동작이 시작될 때 한 번만? |
| 어디에 알릴까요? | 콘솔(`print`)? 영상 위 글자? |

:::힌트
캡처할 때 `print("화면 캡처가 완료되었습니다!")`를 함께 부르면 콘솔에 한글로 알릴 수 있어요. 동작이 시작될 때 한 번만 찍으려면 3-1-2 심화 실습처럼 앞 상태를 담는 변수(예: `captured = False`)를 두고, 상태가 바뀔 때만 찍어요.
:::
::::

::::도전[도전 과제 2: 인공지능을 이용한 스크린 제어 프로그램 만들기]
원고 207쪽 학습 활동 3·4번이에요. 검지 끝 좌표로 마우스 커서를 실제 화면 위치에 맞춰 움직이는 프로그램을 바탕으로, 실생활에 쓸 수 있는 기능을 더해 보세요.

:::생성형AI[생성형 AI와 함께 기능 발전시키기]
완성한 손 동작 인식 프로그램을 바탕으로, 생성형 인공지능의 도움을 받아 실생활에서 쓸 수 있게 기능을 발전시켜 보세요. 예를 들어 손대기 어려운 상황에서 컴퓨터를 멀리서 조작하거나, 손짓만으로 발표 화면을 넘기는 기능을 떠올려 볼 수 있어요. 생성형 AI가 준 코드는 한 줄씩 읽고, 실습실에서 직접 돌려 확인한 뒤 써요.
:::

:::힌트
화면 크기는 `screen_width, screen_height = pyautogui.size()`로 불러와 정규화 좌표를 실제 좌표로 바꿔요. PyAutoGUI에는 키보드 키를 누르는 `pyautogui.press()`도 있어요([보충 P1](/learn/u3/p1/)에서 다뤄요). 얼굴의 코끝으로 커서를 움직이는 [비교 예제(코 끝으로 마우스 조작)](/labs/vision/?example=vision%2Fopmp%2F19-nose-mouse.py)도 참고해요.
:::

### 평가 포인트

3단원 원고에는 차시별 자기 평가 표가 없어요. 원고 184쪽 단원 성취 계획 가운데 "프로그래밍을 통해 출력 장치를 제어할 수 있는가?"와 이어져요. 학습 목표를 자기 평가 문항으로 바꿔 쓸 수도 있어요(사이트가 만든 문항).

- MediaPipe와 PyAutoGUI로 손가락 동작을 알아보고 화면을 캡처할 수 있는가?
- 손가락 좌표를 화면 해상도에 맞게 바꿔 마우스 커서를 제어할 수 있는가?

관찰할 곳: 정규화 좌표에 화면 크기를 곱하는 까닭을 숫자 예(0.5 × 1920 = 960)로 설명하는지, y 좌표의 방향(위가 작음)을 바르게 쓰는지 봐요. 도전 과제 2에서는 생성형 AI의 도움을 받은 부분을 표시했는지, 받은 코드를 직접 실행해 확인했는지 봐요(과목 교육과정 평가 방향).

### 자주 막히는 곳

- 커서가 진짜 마우스처럼 움직이지 않는다고 해요. 이 사이트는 가상 데스크톱의 커서를 움직여요. 같은 코드를 진짜 PC에서 돌리면 진짜 마우스가 움직여요(설치는 교사용 자료실의 ["진짜 PC에서 돌리기"](/teacher/real-pc/#pyautogui보충-p1-3-1-4-iv단원)).
- 원고 204쪽의 "5초 대기"는 `waitKey(5)`로, 실제로는 5밀리초예요.
- 커서가 화면 가장자리에 닿지 않거나 떨려요. 카메라 영상 전체를 화면 전체에 1:1로 맞춘 원고 코드의 특성이에요. 가운데 영역만 쓰거나 앞 좌표와 평균을 내는 방법을 탐구 주제로 쓸 수 있어요.
- 커서가 왼쪽 위 모서리에 닿으면 `FailSafeException`으로 멈춰요. 안전장치를 끄기보다 좌표를 화면 안으로 제한하게 해요.
- `putText`의 한글은 물음표로 나와요. 한글 알림은 `print()`나 Pillow 글꼴로 써요.
- 캡처는 엄지가 위에 있는 동안 계속 덮어써요(실습실은 0.5초에 한 번만 실제로 저장).
