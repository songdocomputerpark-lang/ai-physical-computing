## 학습목표

- 팬 모터의 구조와 원리를 이해할 수 있어요.
- 팬 모터를 회로에 연결해 회전 방향과 속도를 제어할 수 있어요.
- 입력값이나 조건에 따라 팬 모터의 작동 여부와 회전 세기를 제어할 수 있어요.

## 왜 배울까

노트북이나 데스크톱을 쓰다 보면 갑자기 팬 소리가 커질 때가 있어요. 안이 뜨거워지자 팬 모터가 더 빨리 돌며 열을 빨리 식히는 거예요. 요즘 스마트 가전은 센서값에 따라 팬 속도를 스스로 바꾸고, 필요할 때만 빠르게 돌려 전기를 아껴요.

## 핵심 개념

### 팬 모터

팬 모터는 전기를 받아 도는 :용어[DC 모터](직류 모터)에 날개(프로펠러)를 달아 바람을 만드는 장치예요. 컴퓨터뿐 아니라 냉장고, 공기청정기, 자동차처럼 여러 전자 제품에서 안의 온도를 조절하는 데 써요. 교과서 키트의 팬 모터 모듈은 GND, VCC, INA(25번 핀), INB(26번 핀) 네 핀으로 보드에 이어요.

<figcaption>실제 팬 모터로 실습할 때 지키는 세 가지예요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

:::주의[회전 날개를 조심해요]
실제 팬 모터의 날개는 아주 빠르게 돌아서, 손가락이나 머리카락이 닿으면 다치거나 말려 들어갈 수 있어요. 팬을 책상 가장자리 밖으로 내밀지 말고, 날개가 도는 동안에는 얼굴을 가까이 대지 않아요. 가상 보드의 팬은 그림이라 안전해요.
:::

### INA와 INB로 방향 정하기

**INA와 INB**는 두 제어 신호로 팬 모터의 회전 방향(정회전, 역회전)이나 정지를 정하는 방식이에요(원고 167쪽). 모듈 안의 구동 회로(모터 드라이버)가 두 신호대로 모터에 흐르는 전류의 방향을 바꾸고, 전류 방향이 바뀌면 모터가 반대로 돌아요. 둘 다 0이면 전류가 흐르지 않아 멈춰요.

<figure>
<img src="/images/lessons/2-2-3/fan-direction.svg" alt="세 줄 표: INA 1, INB 0이면 모터에 전류가 A에서 B로 흘러 팬이 시계 방향으로 도는 정회전, INA 0, INB 1이면 전류가 B에서 A로 흘러 반시계 방향으로 도는 역회전, 둘 다 0이면 전류가 흐르지 않아 멈춤" width="640" height="372">
<figcaption>빨간 화살표는 전류의 방향이에요. 모듈 안의 회로 모양은 키트마다 달라서, 전류 방향이 바뀐다는 생각만 그린 그림이에요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

| 동작 | INA | INB | 설명 |
| --- | --- | --- | --- |
| 정회전 | 1 | 0 | 시계 방향으로 돌아요. |
| 역회전 | 0 | 1 | 반시계 방향으로 돌아요. |
| 정지 | 0 | 0 | 멈춰요. |

### PWM으로 속도 정하기

켜고 끄기만 하면 팬은 가장 빠르게 돌거나 멈추기만 해요. 한쪽 핀에 :용어[PWM] 신호를 주면 켜진 시간의 비율(duty)만큼 모터가 받는 힘이 달라져 빠르기를 바꿀 수 있어요. 교과서 라이브러리의 `rotate('cw', speed=30)`은 speed(0\~100%)를 `duty = int(1023 × speed ÷ 100)`으로 바꿔 보내요.

<figure>
<img src="/images/lessons/2-2-3/fan-speed-duty.svg" alt="네 줄 그림: speed=0은 duty 0이라 신호가 늘 꺼져 팬이 멈추고, speed=30은 duty 306이라 짧게 켜져 천천히, speed=70은 duty 716이라 길게 켜져 빠르게, speed=100은 duty 1023이라 늘 켜져 가장 빠르게 돈다" width="640" height="380">
<figcaption>켜진 시간이 길수록 팬이 빨리 돌아요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

### 라이브러리와 input()

`gorillacell_dcmotors` :용어[라이브러리]를 쓰면 `fan = GORILLACELL_DCMOTORS(25, 26)`으로 INA, INB 핀을 한 번 알려 준 뒤 `fan.rotate('cw')`(시계 방향), `fan.rotate('ccw')`(반시계 방향), `fan.stop()`(멈춤)으로 다뤄요. cw는 clockwise(시계 방향), ccw는 counterclockwise(반시계 방향)의 줄임말이에요. 이 라이브러리 파일은 가상 보드에 미리 들어 있고, 실제 보드에서 [실행]할 때도 사이트가 보드에 먼저 올려 줘요.

심화 실습은 `input()`으로 키보드 입력을 받아요. `input()`은 콘솔 아래 입력줄에 글자를 적고 Enter를 누를 때까지 기다렸다가, 적은 것을 돌려줘요. 숫자를 적어도 늘 글자(문자열)로 돌려주니 `cmd == '1'`처럼 따옴표를 붙여 비교해요.

## 따라하기

팬 모터를 두 핀 신호로 직접 돌려 보고(동작 테스트), 라이브러리로 같은 일을 짧게 쓰고, PWM으로 속도를 바꾸고(기본 실습), 키보드 입력으로 켜고 끄고 세기를 골라요(심화 실습). 가상 보드의 팬 그림은 방향과 속도를 "정회전 30%"처럼 글로도 보여 줘요. 컴퓨터에서 움직임 줄이기를 켜 두었으면 날개는 돌지 않고 글만 바뀌어요.

:::참고[이 시간의 기본과 심화]
예제 1\~3(동작 테스트, 라이브러리, 기본 실습 — 회전 속도)과 바꿔보기 1·2가 이 시간의 기본이에요. 예제 4·5(심화 실습 — 키보드로 켜고 끄기, 세기 고르기)와 바꿔보기 3은 시간이 남으면 하거나 다음 시간 앞부분에 이어서 해요.
:::

### 코드 읽기

**예제 1(동작 테스트)**

- 6\~7번 줄: 25번 핀(INA)과 26번 핀(INB)을 출력으로 정해요.

- 17\~19번 줄: INA 0, INB 1로 2초 동안 역회전해요.
- 22\~24번 줄: 둘 다 0으로 2초 동안 멈춰요. 10번 줄 `while True`라 이 세 동작을 되풀이해요.

:::왜그럴까[왜 두 핀의 값으로 방향이 바뀔까?]
INA와 INB 가운데 어느 쪽이 1인지에 따라 모터에 흐르는 전류의 방향이 바뀌어요. 예제 1의 12\~13번 줄은 전류를 한쪽으로, 17\~18번 줄은 반대쪽으로 보내서 팬이 반대로 돌아요. 22\~23번 줄처럼 둘 다 0이면 전류가 흐르지 않아 멈춰요.
:::

:::왜그럴까[왜 라이브러리를 쓰면 코드가 짧아질까?]
`fan.rotate('cw')` 한 줄 안에서 라이브러리가 두 핀의 값을 알맞게 정해 줘요. 예제 1에서 두 줄로 쓰던 일을 한 줄로 쓰고, "시계 방향으로 돌아"처럼 뜻도 바로 읽혀요.
:::

:::왜그럴까[왜 speed가 클수록 빨리 돌까?]
예제 3의 speed 30은 duty 306(켜진 시간 약 30%), speed 70은 duty 716(약 70%)이에요. 켜진 시간이 길수록 모터가 평균적으로 더 센 힘을 받아 빨리 돌아요. 한쪽 핀만 PWM이고 다른 핀은 0이라 방향은 그대로 정회전이에요.
:::

:::왜그럴까[왜 q를 입력하면 프로그램이 끝날까?]
예제 4의 18번 줄 `cmd.lower() == 'q'`가 참이면 19번 줄에서 팬을 먼저 멈추고, 21번 줄 `break`로 `while True` 반복을 빠져나가요. 반복 뒤에 남은 줄이 없어서 프로그램이 끝나요.
:::

:::왜그럴까[왜 예제 5는 끝나지 않고, 3을 적으면 안내만 나올까?]
예제 5에는 `break`가 없어서 `while True` 반복이 끝나지 않고, 한 번 처리할 때마다 7번 줄에서 다음 입력을 기다려요. 그래서 [정지]를 눌러야 멈춰요. 3은 8, 11, 14번 줄의 '1', '2', '0' 가운데 어느 것과도 같지 않아서 17번 줄 `else`로 가 안내만 보여요. 팬을 다루는 줄이 없으니 팬은 바로 전의 세기 그대로 돌아요.
:::

## 바꿔보기

:::바꿔보기
1. 예제 1의 12번 줄을 `ina.value(0)`, 13번 줄을 `inb.value(1)`로 바꿔 보세요. 처음 2초 동안 팬은 어느 쪽으로 도나요?
2. 예제 3의 13번 줄 `speed=70`을 `speed=150`으로 바꿔 보세요. 팬 그림의 속도 글은 몇 %가 되나요?
3. 예제 5의 8번 줄 `if cmd == '1':`을 `if cmd == 1:`로 바꾸고, 입력줄에 1을 적어 보세요.
:::

:::왜그럴까[왜 방향, 속도, 반응이 이렇게 될까?]
바꿔보기 1에서는 12\~13번 줄도 INA 0, INB 1이 되어 처음 2초도 역회전이에요. 그래서 4초 동안 역회전한 뒤 2초 멈춰요.

바꿔보기 2의 speed 150은 100%와 같이 가장 빠르게 돌고 "정회전"으로만 보여요. 라이브러리가 speed를 0\~100 사이로 잘라서 duty가 1023을 넘지 않게 막기 때문이에요. 그래서 오류도 나지 않아요.

바꿔보기 3에서는 1을 적어도 "잘못된 입력입니다"가 나와요. `input()`이 돌려준 것은 글자 '1'이고, 숫자 1과 글자 '1'은 서로 다른 값이라 조건이 거짓이기 때문이에요.
:::

:::오류
- 교과서 코드 자료의 [원본 파일 예제](/labs/esp32/?example=esp32/u2/2-2-3-fan-library.py)를 실행하면 1번 줄에서 `SyntaxError: invalid syntax`가 나요. 줄마다 맨 앞에 원고 그림의 줄 번호(1, 2, 3 …)가 글자로 들어 있기 때문이에요. 줄 번호와 빈칸을 지우면 예제 2와 같아져요([오류 사전 풀이](/help/errors/#syntax-error)).
- `GORILLACELL_DEMOTORS`처럼 이름을 잘못 적으면 `ImportError: cannot import name 'GORILLACELL_DEMOTORS'`가 나요. 라이브러리 안의 이름은 `GORILLACELL_DCMOTORS`예요([오류 사전 풀이](/help/errors/#import-error)).
- `fan.rotate('CW')`처럼 방향을 대문자로 적으면 오류 없이 팬이 그대로 멈춰 있어요. 라이브러리는 소문자 'cw'와 'ccw'만 알아들어요.
:::

## 도전 과제

::::도전[도전 과제 1: 강풍 더하기]
예제 5에 3을 입력하면 강풍(속도 100)으로 도는 기능을 더해 보세요. 5번 줄의 안내 글에도 "3 = 강풍"을 더해요.

:::힌트
14번 줄 `elif cmd == '0':` 앞에 `elif cmd == '3':`을 넣고, 그 아래에 `fan.rotate('cw', 100)`과 `print("[Fan] 강풍 (speed=100)")`을 적어요. 들여쓰기를 위의 `elif`와 맞춰요.
:::
::::

::::도전[도전 과제 2: 터치할 때마다 세기가 바뀌는 선풍기]
디지털 터치 센서를 누를 때마다 멈춤 → 약풍 → 중풍 → 강풍 → 멈춤 순서로 세기가 바뀌는 선풍기를 만들어 보세요. 코드 맨 위에 아래 두 줄을 적으면 가상 보드에 터치 센서(17번 핀)와 팬 모터가 그려져요.

```python
# @part touch-digital 17
# @part fan-motor ina=25 inb=26
```

:::힌트
세기를 `speeds = [0, 40, 70, 100]`처럼 목록에 두고, 누른 순간(지금 값 1, 바로 전 값 0)마다 `step = (step + 1) % 4`로 번호를 하나씩 올려요. 속도가 0이면 `fan.stop()`, 아니면 `fan.rotate('cw', speeds[step])`을 불러요. 누른 순간을 찾는 방법은 2-2-1 심화 실습과 같아요.
:::
::::

### 지도안 요약(50분, 사이트가 제안하는 흐름)

1. 도입(3분): "왜 배울까" 그림으로 팬 소리가 커지는 까닭을 이야기해요.
2. 전개 1(7분): 팬 모터와 안전 수칙을 먼저 읽고, INA와 INB 그림과 표로 방향 정하기를 익혀요.
3. 전개 2(10분): 예제 1과 예제 2를 실행하고 바꿔보기 1을 해요.
4. 전개 3(10분): PWM 그림을 보고 예제 3과 바꿔보기 2를 해요.
5. 전개 4(12분): input() 순서도를 보고 예제 4, 5와 바꿔보기 3을 해요.
6. 정리(8분): 확인 퀴즈를 풀고, 도전 과제를 안내해요.

실제 팬 모터를 쓰는 반은 실습 전에 안전 수칙을 먼저 읽게 하고, 날개를 끼운 팬이 책상 가장자리나 사람 쪽을 향하지 않게 놓아요.

두 차시로 운영할 때: 1차시는 안전 수칙, 방향(INA, INB), PWM과 예제 1\~3, 바꿔보기 1·2(40분 안팎). 2차시는 input() 순서도와 예제 4·5, 바꿔보기 3, 확인 퀴즈, 도전 과제예요.

### 평가 포인트

원고 167\~172쪽에는 이 차시의 학습 활동과 자기 평가가 없어요. 아래는 사이트가 학습 목표로 만든 점검 문항이에요.

- INA, INB 값의 조합으로 정회전, 역회전, 정지를 설명할 수 있는가?
- speed(0\~100)와 duty(0\~1023)의 관계로 팬의 빠르기가 바뀌는 까닭을 설명할 수 있는가?
- input()으로 받은 글자에 따라 팬의 작동과 세기를 바꾸는 프로그램을 만들 수 있는가?

원고 154쪽 중단원 성취 계획의 "출력 장치가 동작하는 원리와 이를 적용할 수 있는 분야를 설명할 수 있는가?"와 "마이크로파이썬과 ESP32, 아두이노 등을 활용하여 출력 장치를 제어할 수 있는가?"와 이어져요.

관찰할 곳: 두 핀 값을 표로 정리하고 방향과 짝짓는지, 바꿔보기 3의 결과를 "글자와 숫자는 다른 값"으로 설명하는지 봐요. 도전 과제 2에서 누른 순간만 세는 조건을 스스로 쓰는지도 봐요.

### 자주 막히는 곳

- 방향 글자를 'CW'처럼 대문자로 적거나 'cw '처럼 빈칸을 넣어 "팬이 안 돌아요"라고 해요. 라이브러리는 'cw', 'ccw'만 알아들어요.
- `cmd == 1`처럼 숫자와 비교해 "1을 넣어도 안 돼요"라고 해요. 바꿔보기 3으로 input()이 글자를 돌려준다는 것을 확인하게 해요.
- 예제 5에는 끝내는 입력이 없어서 [정지]로 멈춰요. 예제 4의 `break`와 견주게 해요.
- 가상 팬은 speed 5처럼 아주 작은 값도 천천히 돌지만, 실물 팬은 힘이 모자라 멈춰 있을 수 있어요. 실물로 할 때는 약풍을 30\~50에서 실험해 정하라는 원고 172쪽 설명대로 해요.
- INA와 INB를 모두 1로 두면 가상 보드는 "멈춤(둘 다 1)"으로 보여 줘요. 실물 모듈이 어떻게 되는지는 확인 전이라, 두 핀을 함께 1로 두지 않게 해요([실물 점검 도우미](/labs/esp32/check/)).
- 25번, 26번 핀은 2-2-4에서 서보모터 두 개를 잇는 핀과 같아요. 팬과 서보를 한 회로에 함께 꽂지 않아요.

### 원고에서 바꾼 곳

- 원고 167\~172쪽(학습 목표, 본문, 코드, 에러 체크 포인트)을 차시 틀에 맞게 옮기고 문장을 다듬었어요. 원고에 학습 활동과 자기 평가가 없어서, 도전 과제 두 개와 평가 포인트의 점검 문항은 사이트가 학습 목표와 프로그램 개요("약하게, 중간으로, 강하게", "버튼이나 터치센서 등 다양한 입력 장치와 연계")를 살려 만들었어요.
- 167쪽 선풍기, 쿨링 팬 사진은 출처 표기가 없는 판매용 사진으로 보여 권리를 확인할 수 없어서 쓰지 않고 사이트가 그린 그림으로 바꿨어요. 170쪽 결과 사진은 도는 날개 가까이 손을 둔 모습이라 싣지 않고, 가상 보드의 팬 그림이 대신 보여 줘요(돌아가는 날개 가까이에 손을 두지 않게 하려는 것이에요). 168쪽 연결 그림은 가상 보드의 배선도가 대신해요.
- 169쪽 "라이브러리 사용하기"의 Thonny 저장 단계는 설치 절차라 뺐어요. 사이트는 라이브러리 파일을 가상 보드와 실제 보드에 저절로 넣어 줘요. 원고 스크린숏의 라이브러리는 PWM판(`rotate(direction, speed=100)`, 1000Hz)인데 교과서 키트 자료의 라이브러리(Library-6.20)는 속도 인자가 없는 판이라, 사이트는 스크린숏대로 PWM판을 복원했어요(잘린 'ccw' 부분과 `stop()`은 'cw'와 같은 규칙으로 채움).
- 169쪽 코드의 `GORILLACELL_DEMOTORS`와 저장 파일 이름 `gorillacell_dcmotor.py`는 s와 C가 빠진 오타라 `GORILLACELL_DCMOTORS`, `gorillacell_dcmotors.py`로 바로잡았어요(교사용 자료실 원고 정정 목록). 파일 이름이 다르면 실제 보드에서 `ImportError: no module named 'gorillacell_dcmotors'`가 나요.
- 169쪽 코드의 교과서 코드 자료는 줄마다 원고 줄 번호가 글자로 섞여 1번 줄에서 `SyntaxError`가 나요. 사이트판(예제 2)은 줄 번호만 떼었고, 원본은 오류 상자에서 오류 읽기 연습용으로 이어 두었어요.
- 171쪽 코드의 `else: cmd == '0':`과 23번 줄 `else`의 콜론 빠짐, `print('[Fan] on (CW, speed =)')`은 원고 조판 오류라 파일(`elif cmd == '0':`, `speed = 100`)대로 옮겼어요. 172쪽 제목 "키도드로"는 "키보드로"로, 단계 3 제목의 "터치 센서"는 이 코드에 없어 본문에서 뺐어요. 코드 파일 18번 줄의 "선책하세요"는 원고(172쪽)에서 "선택하세요"예요.
- 172쪽 결과 화면은 첫 안내 줄과 입력줄까지만 보여서, 본문은 실습실에서 1, 2, 3, 0을 차례로 입력한 콘솔을 실었어요.
