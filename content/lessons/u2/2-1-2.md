## 핵심 개념

### LCD는 어떻게 글자를 보여 줄까

:용어[LCD](Liquid Crystal Display, 액정 화면)는 액정이라는 물질로 문자, 숫자, 그림, 동영상 같은 정보를 보여 주는 장치예요. 전기 신호에 따라 빛이 액정을 지나가는 정도(**투과율**)를 조절해 화면을 만들어요. LCD는 스스로 빛을 내지 않아서, 화면 뒤에서 빛을 비추는 조명(**백라이트**)이 있어야 눈으로 볼 수 있어요.

LCD는 여러 줄의 정보를 한꺼번에 보여 줄 수 있어 기계를 다루는 화면(사용자 :용어[인터페이스])을 만들기 좋아요. 크기와 해상도를 여러 가지로 만들 수 있고, 전기를 적게 쓰며 얇고 가벼워서 휴대용 기기에 널리 쓰여요.

이번에 쓰는 문자 LCD는 2줄, 한 줄에 16칸이에요(16×2). 칸 하나에 글자 하나가 들어가고, 칸의 자리는 (열, 행) 좌표로 가리켜요. 번호는 0부터 시작해요.

<figure>
<img src="/images/lessons/2-1-2/lcd-grid.svg" alt="두 줄, 한 줄에 16칸인 문자 LCD에 열 번호 0~15와 행 번호 0~1이 적혀 있고, 첫 줄에 Hello LCD!가 한 칸에 한 글자씩 들어 있으며 둘째 줄 넷째 칸(3, 1)에 커서가 있는 그림. 아래에 lcd.move_to(0, 0), lcd.putstr('Hello LCD!'), lcd.move_to(3, 1)이 하는 일이 적혀 있다" width="640" height="300">
<figcaption>왼쪽 위 칸이 (0, 0), 오른쪽 아래 칸이 (15, 1)이에요. move_to(x, y)로 커서를 옮기고, putstr()로 커서 자리부터 글자를 써요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

문자 LCD에는 한글 글꼴이 없어요. 글자는 영어, 숫자, 기호로 적어요.

### I2C 통신 — 선 두 개로 주고받기

ESP32는 :용어[I2C] 통신으로 LCD에 글자를 보내요. I2C는 선 두 개로 여러 장치와 데이터를 주고받는 방법이에요. **SDA**는 데이터를 싣는 선(21번 핀)이고, **SCL**은 주고받는 박자(클럭)를 맞추는 선(22번 핀)이에요. 여기에 전원선 GND와 VCC를 더해 LCD의 4핀을 연결해요.

<figure>
<img src="/images/lessons/2-1-2/i2c-bus.svg" alt="ESP32의 SDA(21번 핀)와 SCL(22번 핀)에서 뻗은 선 두 개에 문자 LCD(주소 0x20)와 OLED(주소 0x3C)가 함께 이어져 있고, 보드가 주소로 장치를 골라 부른다는 것을 보여 주는 그림" width="640" height="296">
<figcaption>같은 선 두 개에 장치를 여러 개 이을 수 있어요. 보드는 장치마다 다른 주소로 부를 장치를 골라요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

장치마다 정해진 **주소**가 있어요. 교과서 키트의 문자 LCD는 주소가 `0x20`이에요. 같은 복도에 집이 여러 채 있어도 호수로 찾아가듯, 보드는 주소로 대답할 장치를 골라요. `0x20`처럼 앞에 `0x`가 붙은 수는 :용어[16진수](0\~9와 A\~F, 16개 숫자로 세는 수)로 적은 수이고, 우리가 쓰는 10진수로는 32예요.

### 라이브러리 i2c_lcd — LCD를 다루는 함수 모음

LCD에 글자를 쓰려면 정해진 명령 바이트를 차례로 보내야 해요. 이 일을 대신해 주는 :용어[라이브러리]가 `i2c_lcd.py`예요. `from i2c_lcd import I2cLcd`는 이 파일에서 LCD를 다루는 도구(`I2cLcd`)를 불러온다는 뜻이에요.

| 함수 | 하는 일 |
| --- | --- |
| `lcd.putstr('글자')` | 커서 자리부터 글자를 써요. 16칸을 넘으면 다음 줄로 이어져요. |
| `lcd.clear()` | 화면을 모두 지우고 커서를 (0, 0)으로 돌려요. |
| `lcd.move_to(x, y)` | 커서를 x열 y행으로 옮겨요(번호는 0부터). |
| `lcd.show_cursor()`, `lcd.hide_cursor()` | 커서(밑줄)를 보이거나 숨겨요. |
| `lcd.blink_cursor_on()`, `lcd.blink_cursor_off()` | 커서 깜빡이기를 켜거나 멈춰요. |
| `lcd.display_off()`, `lcd.display_on()` | 지금 글자를 숨기거나 다시 보여요. |
| `lcd.backlight_off()`, `lcd.backlight_on()` | 백라이트를 끄거나 켜요. |

실습실의 가상 보드에는 이 라이브러리가 미리 들어 있어요. 실제 보드에서는 교과서처럼 파일을 따로 올리지 않아도 돼요. 실습실이 [실행]할 때 보드에 이 파일이 없으면 함께 올려 줘요.

### 보드 안의 시계 RTC

ESP32 안에는 날짜와 시각을 세는 시계, :용어[RTC](Real Time Clock, 실시간 시계)가 있어요. `rtc.datetime()`은 날짜와 시각을 값 여덟 개가 든 튜플(값을 차례로 묶은 것)로 돌려줘요.

### 누른 순간만 세기

터치 센서는 누르고 있는 동안 1, 떼면 0을 보내요. 보드는 0.05초마다 값을 읽기 때문에, 한 번 누르는 동안에도 1을 여러 번 읽어요. 그래서 "지금 값이 1이고 바로 전 값이 0인 순간", 곧 0에서 1로 바뀐 순간에만 수를 세요.

<figure>
<img src="/images/lessons/2-1-2/touch-edge.svg" alt="0.05초마다 읽은 값을 세 줄로 적은 그림: 지금 값(touch_state)은 0, 0, 1, 1, 1, 1, 0, 0, 0, 1, 1, 0, 0, 0이고 이전 값(prev_touch)은 한 칸씩 늦게 따라온다. 지금 값이 1이고 이전 값이 0인 두 칸에서만 셈(counter)이 1과 2로 늘고, 누르고 있는 동안에는 늘지 않는다" width="640" height="312">
<figcaption>파랗게 강조한 두 칸이 0에서 1로 바뀐 순간이에요. 이때만 셈이 1씩 늘어요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

실제 버튼이나 센서는 누르는 순간 값이 아주 짧게 0과 1을 오가며 떨릴 수 있어요. 한 번 센 뒤 잠깐(0.3초) 기다려 이 떨림을 한 번으로 치는 것을 :용어[디바운싱](debouncing)이라고 해요.

## 따라하기

LCD가 잘 연결됐는지 글자를 써 보고(출력 테스트), 숫자와 시각을 띄운 뒤(기본 실습), 터치 센서로 숫자를 올려요(심화 실습). 가상 보드에는 LCD와 터치 센서가 예제마다 배선되어 있어요.

### 코드 읽기

**예제 1(출력 테스트)**

- 1\~4번 줄: 핀(`Pin`), I2C 통신(`SoftI2C`), LCD 라이브러리(`I2cLcd`), 밀리초 기다리기(`sleep_ms`)를 불러와요.
- 6\~7번 줄: SCL을 22번 핀, SDA를 21번 핀에 두고 I2C 통신 속도를 400kHz(1초에 40만 번 박자)로 정해요. 6번 줄 끝의 `\`는 "다음 줄에 이어져요"라는 뜻이에요.
- 8번 줄: 주소가 `0x20`이고 2행 16열인 LCD를 `lcd`라는 이름으로 준비해요.
- 9번 줄: 화면을 지우고 커서를 (0, 0)으로 돌려요. 11번 줄: `Hello LCD!`를 써요.
- 13\~40번 줄: `'''`로 감싼 부분은 실행되지 않는 글이에요. LCD 함수의 쓰임새를 적어 두었어요.

**예제 2(기본 실습 1: 0부터 5까지 세기)**

- 10번 줄: `i`가 0부터 5까지 하나씩 바뀌며 11\~14번 줄을 여섯 번 되풀이해요.
- 11\~13번 줄: 화면을 지우고 커서를 (0, 0)에 둔 뒤 `"Count: "`와 숫자를 이어 써요. `str(i)`는 숫자를 글자로 바꿔 이어 붙일 수 있게 해요.
- 14번 줄: 1초 기다려요.

**예제 3(기본 실습 2: 보드 시계)**

- 12\~13번 줄: RTC를 준비하고 2025년 6월 21일 11시 0분 0초로 맞춰요.
- 17번 줄: 지금 날짜와 시각을 `t`에 받아요.
- 18\~19번 줄: `t[4]`(시), `t[5]`(분), `t[6]`(초)을 두 자리씩 `:`로 이어 `time_str`을 만들어요.
- 20\~22번 줄: 화면을 지우고 `Time: 11:00:00` 모양으로 쓴 뒤 1초 기다려요.

**예제 4(심화 실습 1단계: 터치 센서 값 읽기)**

- 4번 줄: 터치 센서가 이어진 17번 핀을 입력으로 정해요.
- 7번 줄: 터치 값을 콘솔에 보여요. 누르지 않으면 0, 누르면 1이에요.

**예제 5(심화 실습: 터치 카운터)**

- 13\~14번 줄: 누른 횟수 `counter`와 바로 전 터치 값 `prev_touch`를 0으로 두어요.
- 20번 줄: 지금 터치 값을 읽어요. 23번 줄: 지금 값이 1이고 전 값이 0일 때만 24\~27번 줄을 해요.
- 24\~26번 줄: 횟수를 1 늘리고 `Counter: 횟수` 모양으로 다시 써요. 27번 줄: 0.3초 기다려 떨림을 한 번으로 쳐요(디바운싱).
- 29번 줄: 지금 값을 "바로 전 값"으로 기억해 다음 비교에 써요.

:::왜그럴까[왜 숫자를 쓸 때마다 화면을 지울까?]
LCD 라이브러리는 커서 자리를 기억해요. `putstr()`는 커서 자리부터 글자를 쓰고, 커서를 쓴 글자 수만큼 오른쪽으로 옮겨요. 예제 2가 숫자를 쓸 때마다 11번 줄에서 `lcd.clear()`로 화면을 지우는 까닭은, 앞 글자를 지우고 커서를 (0, 0)으로 되돌려 같은 자리에 새 숫자를 쓰기 위해서예요.
:::

:::왜그럴까[왜 [실행]할 때마다 11:00:00부터 다시 셀까?]
예제 3의 13번 줄이 [실행]할 때마다 시계를 2025년 6월 21일 11시 0분 0초로 맞추기 때문이에요. 가상 보드는 [실행]할 때마다 보드를 새로 켜는 것처럼 시작해요. 지금 시각을 보이고 싶으면 13번 줄의 11(시)과 0(분)을 지금 시각으로 바꿔 실행해요.
:::

:::왜그럴까[왜 누르고 있어도 한 번만 셀까?]
예제 5는 0.05초마다 터치 값을 읽어요. 한 번 누르는 동안 1을 여러 번 읽지만, 23번 줄은 "지금 1이고 바로 전이 0"인 순간만 참이에요. 누르고 있는 동안에는 29번 줄 때문에 바로 전 값도 1이 되어 조건이 거짓이 돼요. 그래서 누른 순간에만 1씩 늘어요.
:::

## 바꿔보기

:::바꿔보기
1. 예제 1의 11번 줄 글자를 `'Hello LCD! Nice to meet you'`처럼 16글자보다 길게 바꿔 실행해 보세요. 17번째 글자는 어디에 나오나요?
2. 예제 2의 11번 줄과 12번 줄 앞에 `#`을 붙여 실행하지 않게 한 뒤 실행해 보세요. 숫자가 어떻게 쌓이나요?
3. 예제 5의 23번 줄을 `if touch_state == 1:`로 바꾸고, 터치 센서를 1초쯤 누르고 있어 보세요. 숫자가 어떻게 올라가나요?
:::

:::왜그럴까[왜 17번째 글자는 둘째 줄에 나올까?]
한 줄에는 16칸(0열\~15열)만 있어요. `putstr()`는 한 칸에 한 글자씩 쓰다가 커서가 15열을 넘으면 다음 줄 첫 칸으로 커서를 옮겨 이어 써요. 그래서 17번째 글자는 둘째 줄 첫 칸 (0, 1)에 나와요.
:::

:::왜그럴까[왜 clear()를 빼면 글자가 이어서 쌓일까?]
화면을 지우지 않고 커서도 돌려놓지 않으면, `putstr()`가 앞 글자가 끝난 자리부터 이어 써요. 그래서 첫 줄에 `Count: 0Count: 1`이 붙어 나오고, 16칸이 차면 둘째 줄로 넘어가 `Count: 2Count: 3`이 이어져요. 둘째 줄도 차면 다시 첫 줄로 돌아가 앞 글자 위에 덮어써요.
:::

:::왜그럴까[왜 누르고 있으면 숫자가 계속 올라갈까?]
바꿔보기 3처럼 바로 전 값을 확인하지 않으면, 누르고 있는 동안에는 23번 줄의 조건이 매번 참이에요. 한 번 셀 때마다 0.35초(27번 줄 0.3초 + 30번 줄 0.05초)씩 기다리니, 1초 남짓 누르고 있으면 4쯤까지 올라가요.
:::

:::참고[교과서 127쪽의 다른 출력 테스트와 블루투스 교안의 카운터]
교과서 127쪽은 같은 LCD에 숫자와 키보드로 받은 글자도 써 봐요. [숫자 쓰기 예제](/labs/esp32/?example=esp32/u2/2-1-2-lcd-number-check.py)는 `str(x)`로 숫자를 글자로 바꿔 쓰고, [키보드로 받은 이름 쓰기 예제](/labs/esp32/?example=esp32/u2/2-1-2-lcd-keyboard-check.py)는 콘솔 아래 입력줄에 적은 영어 이름을 LCD에 써요.

블루투스 교안 59쪽의 "LCD 카운트 값 증가" 코드는 멈추지 않고 1초마다 1씩 세요. 예제 2의 편집칸에 붙여 넣고 실행해 보세요. 콘솔(`print`)과 LCD에 같은 숫자가 함께 나와요.

```python
from machine import Pin
from machine import SoftI2C
from i2c_lcd import I2cLcd
from time import sleep_ms

i2c = SoftI2C(scl=Pin(22), sda=Pin(21), freq=400000)
lcd = I2cLcd(i2c, 0x20, 2, 16)
lcd.clear()
count = 0
while True:
    print('Counter: ', count)
    lcd.clear()
    lcd.putstr(f'Counter: {count}')
    count = count + 1
    sleep_ms(1000)
```

`f'Counter: {count}'`처럼 따옴표 앞에 `f`를 붙이면 `{ }` 안의 변수 값이 글자 속에 들어가요.
:::

:::오류
`OSError: [Errno 19] ENODEV`는 I2C 주소에서 대답하는 장치가 없다는 뜻이에요. 8번 줄의 주소가 `0x20`인지, 6번 줄의 `scl=Pin(22)`와 `sda=Pin(21)`이 서로 바뀌지 않았는지 확인해요. 실제 보드라면 LCD의 전원선(VCC, GND)이 빠지지 않았는지도 봐요. 실제 보드에서 `ImportError: no module named 'i2c_lcd'`가 나면 보드에 라이브러리 파일이 없다는 뜻이에요. 풀이는 [오류 사전](/help/errors/#board-i2c-no-device)에 있어요.
:::

원고 116쪽 중단원 성취 계획 가운데 "다양한 디스플레이 장치가 동작하는 원리와 이를 적용할 수 있는 분야를 설명할 수 있는가?"와 "마이크로파이썬과 ESP32, 아두이노 등을 활용하여 디스플레이 장치를 제어하는 프로그램을 구현할 수 있는가?"와 이어져요.

관찰할 곳: 바꿔보기 1, 2의 결과를 "커서가 어디에 있는가"로 설명하는지 봐요. 예제 5에서 `prev_touch`가 하는 일을 "바로 전 값과 비교"로 말하는지, 도전 과제 1에서 `move_to(0, 1)`로 둘째 줄을 쓰는지도 봐요. 생성형 AI를 쓴 학생은 도움 받은 부분을 표시했는지 확인해요.

### 자주 막히는 곳

- 좌표를 (행, 열)로 적는 학생이 많아요. `move_to(x, y)`는 열이 먼저, 행이 나중이고 둘 다 0부터예요.
- 숫자를 글자에 바로 더해 `TypeError`가 나요. `"Count: " + i`가 아니라 `"Count: " + str(i)`로 적게 해요.
- 예제 3의 18번 줄 끝 `\`와 19번 줄 앞의 `format`을 떼어 쓰면 오류가 나요. 원고 129쪽에는 `format` 앞의 `.`이 빠져 있으니 코드 파일을 기준으로 보게 해요.
- RTC에 요일을 6으로 넣어도 `rtc.datetime()`으로 읽으면 5가 나와요. 맞출 때 요일 칸은 쓰이지 않고 보드가 날짜로 요일을 다시 계산하기 때문이에요(월요일이 0, 2025년 6월 21일은 토요일이라 5).
- 한글을 `putstr()`에 넣으면 LCD에 알 수 없는 글자가 나와요. 문자 LCD에는 한글 글꼴이 없어요.
- 가상 보드는 [실행]할 때마다 보드를 새로 켜서 RTC도 코드에 적은 시각부터 세요. 실제 보드는 전원이 켜져 있는 동안 시계가 이어질 수 있어요(실물 확인 전).
