## 학습목표

- 서보모터의 작동 원리와 특징을 이해하고, 실제 상황에 적용할 수 있어요.
- 입력 조건이나 알고리즘에 따라 서보모터의 회전 각도를 조절할 수 있어요.
- 서보모터를 활용한 피지컬 컴퓨팅 시스템을 만들며 하드웨어와 소프트웨어를 이을 수 있어요.

## 왜 배울까

팬 모터는 계속 돌기만 하지만, 로봇 팔의 관절이나 주차장 차단기는 "정확히 90°까지만" 움직이고 멈춰야 해요. 서보모터는 신호로 정한 각도까지 정확히 돌고 그 자리에 머물러요. 그래서 로봇 관절, 자동문, RC카, 카메라 짐벌(흔들려도 카메라를 반듯하게 잡아 주는 받침), 스마트홈 기기처럼 위치를 정확히 맞춰야 하는 곳에 널리 쓰여요.

## 핵심 개념

### 서보모터는 정한 각도로 움직여요

:용어[서보모터]는 전기 신호에 따라 원하는 각도로 정확하게 회전하는 정밀 제어용 모터예요. 안에 기어 박스, 위치 센서, 제어 회로가 함께 들어 있어서 :용어[PWM] 신호의 펄스 폭에 따라 0°부터 180°까지 정해진 각도로 움직여요(원고 173쪽). 위치 센서가 팔의 지금 각도를 재서 제어 회로에 알려 주고, 제어 회로는 목표 각도에 닿으면 모터를 멈춰요.

교과서 키트의 서보모터는 MG90S예요. 센서 연결 레시피는 GND, VCC, 신호(25번 핀)예요. 모터 축에 끼워 돌아가는 팔을 **혼**(horn)이라고 불러요.

:::주의[팔이 움직일 공간을 비워 둬요]
실제 서보모터를 쓸 때는 팔(혼)이 0°부터 180°까지 도는 자리에 손가락, 물건, 선이 없게 비워 둬요. 팔이 무언가에 걸려 움직이지 못하면 서보가 계속 힘을 써서 뜨거워지거나 안의 기어가 상할 수 있어요. 전원이 켜진 서보의 팔을 손으로 억지로 돌리지 않아요. 가상 보드의 서보는 그림이라 안전해요.
:::

### 펄스 폭이 각도를 정해요

서보모터는 1초에 50번(50Hz), 곧 20ms(0.02초)마다 펄스를 받아요. 한 번 켜져 있는 시간(펄스 폭)이 짧으면 0° 쪽, 길면 180° 쪽으로 돌아요. 교과서 라이브러리는 duty 40을 0°, 77을 90°, 115를 180°로 보내요(duty는 0\~1023).

<img src="/images/lessons/2-2-4/pulse-angle.svg" alt="세 줄 그림: rotate(0)은 duty 40으로 펄스가 0.78ms 켜져 팔이 0°(왼쪽), rotate(90)은 duty 77로 1.50ms 켜져 90°(위쪽), rotate(180)은 duty 115로 2.25ms 켜져 180°(오른쪽)를 가리킨다. 20ms마다 한 번씩 펄스를 보낸다" width="640" height="356">
<figcaption>펄스가 길수록 팔이 더 많이 돌아가요(원고 175쪽 혼 각도 그림을 다시 그림). 사이트가 직접 그린 그림이에요.</figcaption>

| 각도 | duty 값 | 펄스 폭 |
| --- | --- | --- |
| 0° | 40 | 약 0.78ms |
| 90° | 77\~78 | 약 1.50ms |
| 180° | 115 | 약 2.25ms |

### servo_library와 rotate()

교과서는 서보모터를 쉽게 다루려고 `servo_library.py` :용어[라이브러리]를 만들어 써요. 아래는 원고 174쪽 화면에 있는 라이브러리 코드예요. `ServoMotor(signal_pin=25)`로 서보를 만들고, `rotate(각도)`로 돌려요.

```python
from machine import Pin, PWM
import time

class ServoMotor:
    def __init__(self, signal_pin, freq=50):
        self.pwm = PWM(Pin(signal_pin), freq=freq)
        self.pwm.duty(0)

    def rotate(self, angle):
        """
        angle: 0 ~ 180 도 범위
        입력 각도에 따라 서보모터 위치 조절
        """
        angle = max(0, min(180, angle))
        duty = int(40 + (angle / 180) * 75)
        self.pwm.duty(duty)
        time.sleep(0.5)

    def stop(self):
        self.pwm.duty(0)
```

`rotate()`는 ① 각도를 0\~180 사이로 자르고(`max`, `min`) ② `duty = int(40 + 각도 ÷ 180 × 75)`로 바꿔 보내고 ③ 팔이 돌 시간을 주려고 0.5초 기다려요. ③의 0.5초는 따라하기 결과에 큰 영향을 주니 꼭 기억해요. 이 파일은 가상 보드에 미리 들어 있고, 실제 보드에서 [실행]할 때도 사이트가 보드에 먼저 올려 줘요.

## 따라하기

서보모터를 0°, 90°, 180°로 돌려 보고(동작 테스트), 1도씩 천천히 왕복시키고(기본 실습), 서보모터 두 개를 함께 움직이고, 키보드로 각도를 골라요(심화 실습). 가상 보드의 서보 그림은 팔의 각도와 펄스 폭을 "약 89° · 1.50ms"처럼 글로도 보여 줘요.

:::왜그럴까[왜 90°가 약 89°로 보일까?]
`rotate(90)`은 duty = int(40 + 90 ÷ 180 × 75) = int(77.5)예요. `int()`가 소수 부분을 버려 77이 되고, 77은 90°보다 조금 작은 약 89°에 해당해요. 원고 174쪽 표도 90°를 "77\~78"로 적었어요.
:::

:::왜그럴까[왜 1도씩 움직이는 데 이렇게 오래 걸릴까?]
원고는 1도씩 짧은 간격으로 움직인다고 설명하지만, `rotate()` 안에서 0.5초를 기다려서 한 걸음이 약 0.51초(0.5초 + 9번 줄의 0.01초)예요. 0°부터 180°까지 181걸음이면 약 92초, 곧 1분 30초쯤 걸려요.
:::

:::왜그럴까[왜 두 서보가 동시에 움직이지 않을까?]
코드는 한 줄씩 차례로 실행돼요. 9번 줄 `servo_1.rotate(0)`이 0.5초를 기다린 뒤에야 10번 줄 `servo_2.rotate(0)`이 실행돼서 서보 2가 0.5초 늦어요. 원고는 "동시에"라고 적었지만, 이 라이브러리로는 두 서보 사이에 0.5초 차이가 나요.
:::

:::왜그럴까[왜 90을 입력하면 90°로 가지 않을까?]
예제 4의 11번, 15번 줄은 글자 '1'과 '2'만 비교해요. '90'은 둘 다 아니라서 19번 줄 `else`로 가요. 적은 숫자만큼 움직이게 하려면 도전 과제 1처럼 `int()`로 숫자로 바꿔 `rotate()`에 넣어요.
:::

바꿔보기 1의 `rotate(45)`는 duty = int(58.75) = 58이라 펄스가 약 1.13ms, 팔은 약 43°예요. duty가 1씩 바뀔 때마다 각도는 약 2.4°(180 ÷ 75)씩 달라져서 45°에 딱 맞는 값이 없어요.

바꿔보기 2는 10°씩 19걸음(0, 10, …, 180)이라 한쪽에 약 10초(19 × 0.51초)가 걸려요. 걸음 수가 줄어 빨라지지만, 한 번에 10°씩 뛰어 움직임이 덜 부드러워요.

바꿔보기 3에서는 서보 1이 0°일 때 서보 2는 180°, 서보 1이 180°일 때 서보 2는 0°라서 두 팔이 엇갈려 움직여요. 0.5초 차이는 그대로예요.
:::

:::오류
- 5번 줄에서 `servo = ServoMotor(…)`로 만들고 7번 줄에서 `servo_1.rotate(0)`을 쓰면 `NameError: name 'servo_1' is not defined`가 나요. 만든 이름과 쓰는 이름이 같아야 해요(원고 175쪽 "서보모터 객체 선언명 오류", [오류 사전 풀이](/help/errors/#name-error)).
- `from servo_libary import ServoMotor`처럼 라이브러리 이름의 철자가 틀리면 `ModuleNotFoundError: No module named 'servo_libary'`가 나요. 불러오는 이름과 라이브러리 파일 이름이 같아야 해요(원고 175쪽 "라이브러리 오류", [오류 사전 풀이](/help/errors/#module-not-found)).
- `ServoMotor(signal_pin=26)`처럼 배선도와 다른 핀을 쓰면 오류 없이 서보가 움직이지 않고, 콘솔에 "26번 핀을 출력으로 정했는데, 이 예제의 배선도에는 26번 핀에 이은 부품이 없어요"가 나와요. 코드의 핀 번호와 연결한 핀이 같은지 확인해요(원고 175쪽 "신호 핀 설정 오류").
:::

- 177, 178쪽 1번 줄 설명 "Pin 모듈과 PWM 모듈 불러오기"는 코드가 `Pin`만 불러와서 본문에 옮기지 않았어요. 173쪽 프로그램 개요의 "터치 센서"는 심화 실습 코드에 없어 뺐어요.
- 175쪽 서보모터 에러 체크 포인트 네 가지 가운데 신호 핀, 라이브러리 이름, 객체 이름 오류는 가상 보드에서 실제로 나는 메시지와 함께 오류 상자로 옮겼어요. 전원 연결 오류는 실물에서만 확인해요.
- 블루투스 교안 61\~68쪽은 같은 서보모터를 32번 핀과 `mg90s_servo` 라이브러리(`MG90S_SERVO`, duty 23\~124)로 다뤄요. 교안의 코드 자료(코드 id f145)는 0°에서 90°로 한 번 움직이고, 65쪽 화면은 0°와 90°를 0.5초씩 되풀이해요. 67쪽 "서보 모터 증가" 화면의 코드를 글자로 옮기면 아래와 같아요. 맨 위에 `# @part servo 32`를 한 줄 더해 ESP32 실습실 편집칸에 붙여 넣으면 가상 보드에서 그대로 돌아요(가상 보드는 이때 mg90s_servo 기준으로 각도를 그려요).

```python
from machine import Pin
from machine import PWM
from time import sleep_ms
from mg90s_servo import MG90S_SERVO

se=MG90S_SERVO(signal_pin=32)

for angle in range(0,181,10):
    se.rotate(angle)
    print(angle)
    sleep_ms(500)

for angle in range(180,-1,-10):
    se.rotate(angle)
    print(angle)
    sleep_ms(500)
```
