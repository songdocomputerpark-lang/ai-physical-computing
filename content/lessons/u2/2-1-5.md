## 학습목표

- ESP32와 네오픽셀을 연결하는 방법과 제어 원리를 이해할 수 있어요.
- MicroPython으로 네오픽셀 LED의 색과 밝기를 정할 수 있어요.
- 센서 입력에 따라 네오픽셀 LED의 상태를 바꿀 수 있어요.

## 왜 배울까

2-1-4의 RGB LED는 핀 세 개로 LED 하나의 색을 정했어요. 그런데 LED가 16개, 100개로 늘어나면 보드의 핀이 모자라요. 네오픽셀은 데이터 선 하나로 LED 여러 개의 색을 하나하나 따로 정할 수 있어요. 그래서 무드등, 빛으로 상태를 알리는 스마트 스피커, LED 띠 장식처럼 색과 움직임으로 알려 주는 장치에 이런 LED가 많이 쓰여요.

## 핵심 개념

### 네오픽셀은 칩이 든 RGB LED

:용어[네오픽셀](NeoPixel)은 작은 제어 칩이 들어 있는 똑똑한 RGB LED예요. LED 하나 안에 빨강(R), 초록(G), 파랑(B) 빛을 내는 소자(전자 제품 안에서 한 가지 일을 하는 부품)가 들어 있고, 색마다 밝기를 0\~255 사이의 값으로 정해요. LED마다 번호(인덱스)가 있어서 코드에서 `np[0]`, `np[1]`, …, `np[15]`로 하나씩 따로 다룰 수 있어요.

<figure>
<img src="/images/lessons/2-1-5/ring-index.svg" alt="왼쪽은 LED 16개가 둥글게 붙은 링으로 12시 자리가 0번이고 시계 방향으로 15번까지 번호가 있으며, 5번 자리의 6번째 LED가 빨갛게 강조되어 가운데에 6번째 LED는 np[5]라고 적혀 있고, 오른쪽은 ESP32의 데이터 선(DIN)이 0번, 1번 … 15번 LED로 이어져 보드가 보낸 색 16개를 LED가 차례로 하나씩 가져간다는 설명이다" width="640" height="372">
<figcaption>번호는 0부터 세요. 16개짜리 링의 번호는 0~15예요. 사이트가 직접 그린 그림이에요(원고 148쪽 그림을 다시 그림).</figcaption>
</figure>

네오픽셀 링의 센서 연결 레시피는 GND, VCC, DIN(23번 핀)이에요. DIN은 "데이터가 들어오는 곳(Data In)"이라는 뜻이에요. 보드가 DIN 선으로 색 16개를 차례로 이어서 보내면, 0번 LED는 첫 번째 색을 갖고 나머지를 1번 LED로 넘겨요. 이렇게 차례로 자기 색을 가져가서 선 하나로 16개를 모두 다룰 수 있어요.

### 색을 숫자로 적는 두 가지 방법

컴퓨터 모니터, LED 조명, 휴대폰 화면은 색을 숫자로 나타내요. `(255, 0, 0)`처럼 빨강, 초록, 파랑의 밝기를 숫자 세 개로 적거나, `#FF0000`처럼 :용어[16진수]로 적어요. 네오픽셀 코드에서는 숫자 세 개를 괄호로 묶은 모양을 써요.

<figure>
<img src="/images/lessons/2-1-5/color-codes.svg" alt="위에는 빨간 네모 옆에 (255, 0, 0) = #FF0000이라고 적혀 빨강 255는 FF, 초록 0은 00, 파랑 0은 00이 된다고 보여 주고, 아래 표에는 빨강 (255, 0, 0) #FF0000, 주황 (255, 94, 0) #FF5E00, 노랑 (255, 228, 0) #FFE400, 초록 (0, 255, 0) #00FF00, 파랑 (0, 0, 255) #0000FF, 남색 (0, 0, 75) #00004B, 보라 (95, 0, 255) #5F00FF가 색 견본과 함께 정리되어 있다" width="640" height="400">
<figcaption>아래 표의 일곱 색은 기본 실습의 무지개 색이에요(원고 150쪽 색상표). 사이트가 직접 그린 그림이에요.</figcaption>

### 색 정하기와 보내기는 따로예요

`np[번호] = (빨강, 초록, 파랑)`은 ESP32 안에 있는 색 목록에 색을 적기만 해요. `np.write()`를 불러야 목록 전체가 데이터 선으로 보내져 링의 불빛이 바뀌어요. 그래서 여러 LED의 색을 먼저 적어 두고 `np.write()`를 한 번 부르면 한꺼번에 바뀌어요.

<figure>
<img src="/images/lessons/2-1-5/buffer-write.svg" alt="두 줄 그림: 위는 np[0] = (255, 0, 0)과 np[1] = (0, 255, 0)을 실행하면 ESP32 안의 색 목록 16칸 가운데 0번이 빨강, 1번이 초록으로 적히지만 링은 꺼진 그대로이고, 아래는 np.write()를 실행하면 목록 전체가 링으로 보내져 0번 LED가 빨강, 1번 LED가 초록으로 켜지는 모습이다" width="640" height="330">
<figcaption>np[번호]로 적고, np.write()로 보내요. 사이트가 직접 그린 그림이에요.</figcaption>

:::왜그럴까[왜 한 칸씩 차례로 켜질까?]
11번 줄 `np.write()`가 반복문 안에 있어서, LED 하나의 색을 적을 때마다 바로 링으로 보내기 때문이에요. `np[i] = …`는 보드 안의 색 목록에 적기만 해요. 원고 149쪽 코드처럼 이 줄이 없으면 첫 반복문 1.6초 동안 링이 그대로이다가, 둘째 반복문의 첫 `np.write()`에서 15개가 한꺼번에 켜져요(15번은 막 끈 뒤라 꺼져 있어요).
:::

:::왜그럴까[왜 무지개가 방향을 바꾸며 채워질까?]
`range(16)`은 번호를 0, 1, …, 15로, `range(15,-1,-1)`은 15, 14, …, 0으로 바꿔요. 앞 색이 16칸을 다 채운 뒤 다음 색이 반대쪽 끝부터 한 칸씩 덮어써서, 두 색의 경계가 링을 따라 움직이는 것처럼 보여요.
:::

:::왜그럴까[왜 손을 떼도 색이 그대로이고, 같은 패드를 다시 눌러도 콘솔이 조용할까?]
손을 떼면 ADC 값이 0이라 `get_button`이 `"None"`을 돌려줘요. `"None"`은 사전 `colors`에 없어서 50번 줄의 조건이 거짓이 되고, 색도 `prev_button`도 그대로예요. 같은 패드를 다시 누르면 `button`과 `prev_button`이 같아서 역시 아무 일도 하지 않아요. 새 버튼을 눌렀을 때만 한 번 바꾸니까 콘솔이 같은 줄로 가득 차지 않아요.
:::

:::왜그럴까[왜 숫자를 바꾸면 밝기와 색이 달라질까?]
바꿔보기 1은 색을 적기만 하고 보내지 않아서, 첫 1.6초 동안 링이 그대로예요. 바꿔보기 2의 `(30,0,0)`은 같은 빨강이지만 값이 작아 어둡게 빛나요. 세 값의 비율은 색을, 값의 크기는 밝기를 정해요. 가상 보드는 어두운 색도 알아보게 LED 가운데는 밝게 칠하고, 실제 밝기는 LED 둘레의 빛 번짐 크기로 보여 줘요. LED 위에 마우스를 올리면 `(30, 0, 0)`처럼 값도 보여요. 바꿔보기 3의 `(255, 255, 255)`는 빨강, 초록, 파랑을 모두 가장 밝게 켜서 흰색이에요(2-1-4의 빛의 삼원색).
:::

:::오류
- `np[16] = (255, 0, 0)`처럼 LED 개수와 같은 번호를 쓰면 `IndexError: bytearray index out of range`가 나요. 16개짜리 링의 번호는 0\~15예요([오류 사전 풀이](/help/errors/#board-neopixel-index)).
- `np[0] = (255, 0)`처럼 색 값을 두 개만 적으면 `IndexError: tuple index out of range`가 나요. 색은 늘 세 값이에요([오류 사전 풀이](/help/errors/#board-neopixel-color-count)).
:::

## 도전 과제

::::도전[도전 과제 1: 빙글빙글 도는 불빛]

:::힌트
지금 켜진 LED를 끄고(`(0, 0, 0)`), 번호를 하나 늘린 다음 LED를 켜고 `np.write()`로 보내요. 15번 다음에 0번으로 돌아가려면 `i = (i + 1) % 16`처럼 16으로 나눈 나머지를 써요.
:::
::::

::::도전[도전 과제 2: 경찰차 사이렌]
링의 오른쪽 반(0\~7번)은 파랑, 왼쪽 반(8\~15번)은 빨강으로 0.3초마다 번갈아 켜지게 해 보세요.

:::힌트
`np.fill((0, 0, 0))`은 16개 모두에 같은 색을 한꺼번에 적어요(보내기는 역시 `np.write()`). `for i in range(8):`로 0\~7번, `for i in range(8, 16):`으로 8\~15번을 칠해요.
:::
::::

- 과제 1: 경찰차 사이렌을 네오픽셀로 나타내기(도전 과제 2)

과제 4는 2-1-2에서 배운 RTC의 `datetime()`으로 시각을 읽고, 초(0\~59)를 `초 * 16 // 60`처럼 16칸 번호로 바꿔 보세요. AI에게 "ESP32 MicroPython, 네오픽셀 16개, DIN 23번 핀"처럼 조건을 알려 주고, 받은 코드는 줄마다 설명할 수 있어야 해요.

### 평가 포인트

원고 153쪽의 자기 평가 문항이에요(학생이 세 단계로 스스로 표시).

- ESP32와 네오픽셀의 3개 핀(VCC, GND, DIN)을 올바르게 연결할 수 있는가?
- 네오픽셀을 제어하는 다양한 함수의 차이점을 이해하고, 사용할 수 있는가?
- 센서 입력에 따라 네오픽셀 LED의 상태를 동적으로 제어할 수 있는가?

원고 116쪽 중단원 성취 계획의 "센서와 출력 장치가 동작하는 원리와 이를 활용할 수 있는 분야를 설명할 수 있는가?"와 "마이크로파이썬과 ESP32, 아두이노 등을 활용하여 디스플레이 장치를 제어하는 프로그램을 구현할 수 있는가?"와 이어져요.

관찰할 곳: `np[번호] = 색`(적기), `np.write()`(보내기), `np.fill()`(모두 적기)의 차이를 말하는지 봐요. 번호를 0부터 세는지, 무드등에서 `prev_button`이 왜 필요한지 설명하는지도 봐요. 생성형 AI를 쓴 학생은 도움 받은 부분을 표시했는지 확인해요.

### 자주 막히는 곳

- 번호를 1부터 세어 16번째 LED를 `np[16]`으로 적어요. 16개면 0\~15이고, 넘으면 `IndexError: bytearray index out of range`가 나요.
- 색을 적고 `np.write()`를 빼먹어 "안 켜져요"라고 해요. 코드를 고치기 전에 write가 있는지부터 찾게 해요.
- 밝기를 줄이려고 `(255 * 0.5, 0, 0)`이나 `255 / 2`처럼 소수를 넣어요. 네오픽셀 색은 0\~255 정수라 `TypeError: can't convert float to int`가 나요. `255 // 2`나 `int(…)`를 쓰게 해요.
- 4채널 터치 센서의 값은 키트마다 조금씩 달라요. 실물에서 버튼을 알아보지 못하면 47번 줄 뒤에 `print(val)`을 잠깐 넣어 값을 보고 30\~40번 줄의 구간을 고치게 해요(2-1-3 심화와 같은 방법).
- 실물 링의 LED 16개를 모두 가장 밝은 흰색으로 켜면 전류가 많이 흘러요(LED 하나에 최대 약 60mA). USB 전원이 모자라면 보드가 멈추거나 다시 시작될 수 있으니 밝기를 낮춰 써요.
- 네오픽셀 칩은 초록, 빨강, 파랑(GRB) 순서로 색을 받지만 `neopixel` 라이브러리가 순서를 바꿔 보내므로 코드에는 (빨강, 초록, 파랑)으로 적어요. 다른 종류의 LED 링에서 빨강과 초록이 바뀌어 보이면 색 순서가 다른 LED예요. 교과서 키트 링은 [실물 점검 도우미](/labs/esp32/check/)의 "네오픽셀 링" 항목으로 확인해요.
