## 학습목표

- ESP32와 버저를 연결하고 제어하는 원리를 이해할 수 있어요.
- MicroPython으로 버저에서 여러 가지 소리를 낼 수 있어요.
- PWM 신호로 음의 높낮이(주파수)와 길이(시간)를 조절할 수 있어요.

## 왜 배울까

비상벨은 불이 나면 크게 울리고, 주방 타이머와 알람 시계는 정한 때가 되면 삐삐 소리로 알려 줘요. 소리는 화면을 보고 있지 않아도 바로 알아챌 수 있어서 경고와 알림에 많이 쓰여요. 버저를 코드로 다룰 수 있으면 내가 만든 장치도 "다 됐어요", "위험해요"를 소리로 알릴 수 있어요.

## 핵심 개념

### 버저는 전기 신호를 소리로 바꿔요

**버저**(Buzzer)는 전기 신호를 소리로 바꾸는 전자 장치로, 경고음이나 알림음을 낼 때 많이 써요. 전류가 흐를 때 생기는 **전자기장**(전기가 흐르는 곳이나 자석 둘레에 생기는, 힘이 미치는 공간)이 버저 안의 얇은 진동판을 떨게 해요. 진동판의 떨림이 공기를 떨게 해서 귀에 들리는 소리(음파)가 돼요.

<figure>
<img src="/images/lessons/2-2-1/buzzer-principle.svg" alt="세 칸 그림: 전기 신호가 켜졌다 꺼졌다를 빠르게 되풀이하면, 버저 안의 코일에 생긴 전자기장이 진동판을 밀었다 놓았다 해서 진동판이 떨리고, 그 떨림이 공기를 흔들어 귀에 소리로 들린다" width="640" height="300">
<figcaption>전기 신호 → 진동판의 떨림 → 공기의 떨림(음파) 차례로 소리가 나요(원고 155쪽 도식을 다시 그림). 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

버저는 짧은 "삐" 소리부터 여러 높이의 음까지 낼 수 있어서, 전자 기기나 피지컬 컴퓨팅 작품에서 상태 표시, 알림, 누른 것을 알려 주는 반응 소리로 써요. 교과서 키트의 버저는 **수동 버저**예요. 수동 버저는 안에 떨림을 만드는 회로가 없어서, 보드가 신호를 빠르게 켰다 껐다 해 줘야 그 빠르기에 맞는 높이의 소리를 내요.

버저 모듈의 센서 연결 레시피는 GND, VCC, SIG(15번 핀)예요.

### 주파수가 소리의 높이를 정해요

:용어[주파수]는 어떤 일이 일정하게 되풀이될 때 1초 동안 몇 번 되풀이되는지를 나타내는 양이에요. 단위는 헤르츠(Hz)이고, 1Hz는 1초에 한 번 되풀이한다는 뜻이에요. 진동판이 1초에 262번 떨면 "도", 523번 떨면 한 옥타브 높은 "도" 소리가 나요.

### PWM의 freq()와 duty()

2-1-4에서 LED 밝기를 바꿀 때 쓴 :용어[PWM]으로 버저 소리도 정해요. `buzzer = PWM(Pin(15))`로 15번 핀을 PWM 출력으로 정한 뒤, `buzzer.freq(262)`로 1초에 켜졌다 꺼지는 횟수(주파수)를 정하면 그 높이의 소리가 나요. `buzzer.duty(512)`는 한 번 켜졌다 꺼지는 동안 켜져 있는 시간의 비율을 정해요(0\~1023, 512는 약 50%).

<figure>
<img src="/images/lessons/2-2-1/freq-duty.svg" alt="세 줄 그림: freq(262)와 duty(512)는 같은 시간에 신호가 3번 켜졌다 꺼지는 기준 도 소리, freq(523)과 duty(512)는 6번으로 2배 떨리는 높은 도, freq(262)와 duty(50)은 3번으로 높이는 같지만 켜진 시간이 아주 짧아 작고 가는 소리다" width="640" height="356">
<figcaption>freq()를 바꾸면 떨리는 횟수가, duty()를 바꾸면 켜진 시간이 달라져요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

| 함수 | 하는 일 | 예 |
| --- | --- | --- |
| `freq(주파수)` | 소리의 높이를 정해요. | `buzzer.freq(262)` → 도 |
| `duty(값)` | 켜진 시간의 비율을 정해요. 0이면 소리가 나지 않아요. | `buzzer.duty(512)` → 약 50% |
| `sleep(초)` | 그 소리를 몇 초 동안 낼지 정해요. | `sleep(0.5)` → 0.5초 |
| `deinit()` | PWM을 멈추고 소리를 꺼요. | `buzzer.deinit()` |

PWM 없이 `Pin(15, Pin.OUT)`으로 핀을 켜기만 하면(`on()`) 소리를 켜고 끌 수만 있고, 높이는 바꿀 수 없어요. 가상 보드는 이때 1000Hz 고정음을 내요.

### 음 이름을 사전으로 정리하기

기본 실습은 음 이름과 주파수를 **사전**(딕셔너리)에 짝지어 둬요. 사전은 이름표(키)와 값을 짝지어 모아 두는 자료라서, `notes["미"]`처럼 이름표로 값(330)을 꺼내요. 주파수 숫자를 외우지 않고 음 이름으로 코드를 읽을 수 있어요.

교과서는 한 걸음 더 나아가, 음 이름(C4 = 262, E4 = 330 등)과 연주 함수(`play()`, `tone()`)를 미리 만들어 둔 `buzzer.py` :용어[라이브러리]를 소개해요(원고 156쪽). 라이브러리를 쓰면 좋은 점은 네 가지예요.

- 재사용성: 음계를 PWM 주파수로 직접 계산하지 않고, 미리 정해 둔 값(C4 = 262, E4 = 330 등)을 쓸 수 있어요.
- 가독성: 코드에 음 이름을 바로 써서 읽기 쉬워요.
- 편리한 함수: `play()`, `tone()` 같은 함수로 멜로디 연주를 쉽게 만들어요.
- 확장성: 자주 쓰는 음이나 다른 음계를 더해 두면 계속 쓸 수 있어요.

사이트의 가상 보드에는 `buzzer.py`가 미리 들어 있어서, 교과서 157쪽처럼 `from buzzer import *`로 불러 `BUZZER(15)`와 `play(jingle, 100)`으로 징글벨을 연주하는 코드를 [ESP32 실습실에서 바로 돌려 볼 수 있어요](/labs/esp32/?example=esp32%2Fu2%2F2-2-1-buzzer-library.py). 실제 보드는 실습실의 [실제 보드]로 실행하면 사이트가 보드에 없는 `buzzer.py`를 먼저 올려 줘요. 따라하기의 예제 세 개는 라이브러리 없이 PWM을 직접 다뤄요.

## 따라하기

버저를 1초마다 울려 보고(동작 테스트), PWM으로 도레미파솔라시도를 연주하고(기본 실습), 터치 센서를 누를 때마다 버저가 짧게 울리게 해요(심화 실습). 소리는 [실행]을 누른 뒤에만 나요. 보드 그림 위 [소리 켜짐] 단추를 누르면 소리를 끄고 켤 수 있어요.

:::참고[배선 확인 칸의 "스트래핑 핀" 주의]
보드 그림 아래 "배선 확인" 칸에 버저의 GPIO15가 스트래핑 핀이라는 주의가 보여요. 스트래핑 핀은 보드가 켜지는 순간 그 핀의 전기 상태를 보고 어떻게 시작할지 정하는 핀이에요. 교과서 배선 그대로 실습해도 돼요. 실물 보드가 켜지지 않거나 코드가 올라가지 않을 때만 그 핀에 이은 선을 잠깐 빼고 켠 뒤 다시 이어요.
:::

:::왜그럴까[왜 예제 1은 on()만 해도 소리가 날까?]
`buzzer.on()`은 15번 핀을 계속 1로 켜 둬요. 수동 버저는 원래 신호가 켜졌다 꺼졌다 해야 떨리지만, 가상 보드는 이 실습을 들을 수 있게 핀이 1인 동안 1000Hz 고정음을 내요. 실제 수동 버저는 켜고 끄는 순간에만 "딱" 하는 짧은 소리가 날 수도 있어요. 그럴 때는 예제 2처럼 PWM으로 주파수를 정해 주면 또렷한 소리가 나요.
:::

:::왜그럴까[왜 음이 한 단계씩 높아질까?]
14번 줄이 음 이름을 사전에서 찾아 주파수로 바꿔 `freq()`에 넣어요. 도 262Hz에서 높은 도 523Hz로 갈수록 진동판이 1초에 더 많이 떨려 높은 소리가 나요. 17번 줄 `sleep(0.5)`가 음마다 0.5초씩 기다려서 한 음의 길이가 0.5초가 돼요.
:::

:::왜그럴까[왜 누르고 있어도 한 번만 울릴까?]
15\~16번 줄의 조건은 "지금 1, 바로 전 0"인 순간에만 참이에요. 누르고 있는 동안에는 22번 줄 때문에 바로 전 값도 1이 되어 조건이 거짓이에요. 그래서 누른 순간에 한 번, 0.5초만 울려요.
:::

## 바꿔보기

:::바꿔보기
1. 예제 2의 7번 줄 `"도": 262`를 `"도": 523`으로 바꿔 보세요. 첫 음이 어떻게 들리나요?
2. 예제 2의 15번 줄 `buzzer.duty(512)`를 `buzzer.duty(50)`으로 바꿔 보세요. 음 높이와 소리는 어떻게 달라지나요?
3. 예제 3의 19번 줄 `sleep(0.5)`를 `sleep(2)`로 바꾸고, 버저가 우는 동안 터치 센서를 한 번 더 눌러 보세요.
:::

:::왜그럴까[왜 높이, 크기, 반응이 달라질까?]
바꿔보기 1의 523Hz는 262Hz의 약 2배라서, 첫 음이 한 옥타브 높은 도로 들려요. 그래서 첫 음과 마지막 음이 같은 높이예요.

바꿔보기 2의 `duty(50)`은 한 번 켜졌다 꺼지는 동안 약 5%만 켜져 있어요. 떨리는 횟수는 그대로라 음 높이는 같지만, 진동판을 미는 시간이 아주 짧아 소리가 작고 가늘어요. 버저 그림의 소리 물결도 흐려져요.

바꿔보기 3에서는 19번 줄이 2초 동안 기다리는 사이에 코드가 터치 센서를 읽지 않아요. 그래서 그동안 누른 것은 알아채지 못해요. 소리를 길게 낼수록 그동안 다른 일을 하지 못해요.
:::

:::오류
- `buzzer.deinit()` 뒤에 `buzzer.duty(512)`처럼 다시 쓰면 `RuntimeError: PWM is inactive`가 나요. 멈춘 PWM은 그대로 다시 쓸 수 없으니 `deinit()`은 연주를 모두 마친 맨 끝에 두어요([오류 사전 풀이](/help/errors/#board-pwm-inactive)).
- `buzzer.freq(0)`처럼 주파수에 0을 넣으면 `ValueError: frequency must be from 1Hz to 40MHz`가 나요. 쉬는 박자에는 주파수 대신 `buzzer.duty(0)`으로 소리를 꺼요([오류 사전 풀이](/help/errors/#board-pwm-freq-range)).
- 실제 보드에서 `from buzzer import *`가 `ImportError: no module named 'buzzer'`로 멈추면 보드에 `buzzer.py` 라이브러리 파일이 없다는 뜻이에요. 교과서 157쪽처럼 파일을 보드에 먼저 저장해요(실습실의 [실제 보드]로 실행하면 사이트가 올려 줘요). 가상 보드에는 `buzzer.py`가 들어 있어서, 이 오류는 `from buzer import *`처럼 이름을 틀리게 적었을 때 `ModuleNotFoundError`로 나요([오류 사전 풀이](/help/errors/#module-not-found)).
:::

### 자주 막히는 곳

- "소리가 안 나요": [소리 켜짐] 단추, 컴퓨터 음량, 브라우저 탭의 음소거를 먼저 확인해요. 소리는 [실행]을 누른 뒤에만 나요.
- duty를 소리의 크기로 알아요. duty는 켜진 시간의 비율이라, 512(약 50%) 근처가 가장 크고 또렷하고 1023(거의 늘 켜짐)에 가까우면 오히려 작아져요.
- 예제 3의 15번 줄 끝 `\` 뒤에 빈칸이 있으면 `SyntaxError`가 나요. `\`는 줄의 맨 끝에 있어야 해요.
- 15번 핀은 보드가 켜질 때 쓰는 스트래핑 핀이라 가상 보드가 "주의"를 보여 줘요. 원고 배선 그대로라 실습에는 문제없어요. 실물 보드가 켜지지 않거나 코드가 올라가지 않으면 버저 선을 잠깐 뽑고 다시 해 봐요.
- 실물 수동 버저에 `on()`만 주면 소리가 작거나 "딱" 소리만 날 수 있어요(키트 실물은 확인 전 — [실물 점검 도우미](/labs/esp32/check/)). 그럴 때는 예제 2의 PWM 코드로 버저가 되는지 확인해요.

- 157쪽 버저 에러 체크 포인트 표의 `ImportError: no module named 'buzzer'`는 오류 상자에 옮겼어요(가상 보드에는 buzzer.py가 있어 이 오류가 나지 않고, 이름을 틀리게 적으면 `ModuleNotFoundError`로 알려요). `OSError: [Errno 5] EIO`(GPIO 핀 번호 오류)는 가상 보드에서 재현되지 않아 뺐어요. 없는 핀 번호는 `ValueError: invalid pin`으로 나와요([오류 사전](/help/errors/#board-invalid-pin)).
- 159쪽 심화 단계 1 "터치 센서 동작 테스트" 코드는 7번 줄 `print`에 닫는 괄호가 없고 8번 줄 들여쓰기가 어긋나 그대로 치면 오류가 나요. 바르게 적으면 아래와 같아요. 예제 3을 연 실습실 편집칸에 붙여 넣으면 가상 터치 센서로 확인할 수 있어요.

```python
from machine import Pin
from time import sleep

touch = Pin(17, Pin.IN)

while True:
    print("touch value:", touch.value())
    sleep(0.2)
```

- 원고 코드에는 `# 라이브러리 불러오기` 같은 주석 줄이 더 있어 원고와 파일의 줄 번호가 달라요(예: 원고 18번 줄 `buzzer.freq(notes[note])` = 파일 14번 줄). 본문은 실습실에서 보이는 파일의 줄 번호를 따랐어요.
