## 학습목표

- 피지컬 컴퓨팅의 뜻과, 입력 장치, 처리 장치, 출력 장치로 움직이는 원리를 설명할 수 있어요.

- 브라우저의 ESP32 실습실에서 MicroPython 코드를 가상 보드나 실제 보드로 실행할 수 있어요.

## 왜 배울까

I단원에서는 인공지능이 카메라 영상을 보고 손과 얼굴을 알아봤어요. 그 결과를 화면 밖 현실 세계로 내보내려면 불을 켜고, 글자를 띄우고, 소리를 내고, 모터를 돌리는 장치가 필요해요. 이 단원에서는 ESP32라는 작은 컴퓨터에 여러 출력 장치를 이어 코드로 움직여 봐요.

## 핵심 개념

### 피지컬 컴퓨팅 — 현실 세계와 컴퓨터를 잇는 기술

:용어[피지컬 컴퓨팅](Physical Computing)은 :용어[센서], :용어[마이크로컨트롤러], :용어[액추에이터] 같은 장치로 현실의 아날로그 세계와 컴퓨터의 디지털 세계를 연결하는 기술이에요. 생활, 의료와 건강, 교육, 교통, 예술 같은 여러 분야에서 쓰여요.

피지컬 컴퓨팅은 **입력 장치**, **처리 장치**, **출력 장치**로 이루어져요.

| 구분 | 하는 일 | 예 |
| --- | --- | --- |
| 입력 장치 | 바깥 환경의 변화나 사용자의 동작을 알아채 데이터를 모아요. | 센서, 버튼, 스위치 |
| 처리 장치 | 입력된 데이터를 마이크로컨트롤러가 처리하고 다른 장치를 제어해요. | 마이크로컨트롤러(ESP32) |
| 출력 장치 | 처리한 결과를 빛, 움직임, 소리, 화면으로 내보내요. | LED, 모터, 스피커, 디스플레이 |

센서는 쓰임에 따라 종류가 많아요. 빛 센서, 온도 센서, 소리 센서, 습도 센서, 압력 센서, 거리 센서, 가속도 센서 등이 있어요.

### 임베디드 시스템

:용어[임베디드 시스템](Embedded System)은 피지컬 컴퓨팅을 만드는 바탕이 되는 시스템이에요. 한 가지 기능이나 몇 가지 기능만 하도록 만든 작은 컴퓨터 시스템으로, 전자레인지나 세탁기처럼 기계 안에 들어가(embedded) 일해요.

| --- | --- |

| 액추에이터(Actuator) | 마이크로컨트롤러의 제어 신호를 받아 실제로 움직이는 동작을 해요. |

### 부품의 핀과 케이블 색

부품(모듈)은 핀 수와 색이 맞는 케이블로 보드에 연결해요. 모든 부품에는 GND와 VCC가 있고, 나머지는 신호를 주고받는 핀이에요.

- **GND(-)**: 접지선이에요. 전기가 돌아오는 길이에요(검은 선).
- **VCC(+)**: 전원을 공급하는 선이에요(빨간 선).
- **SIG(signal)**: 보드의 :용어[GPIO] 핀에 연결하는 신호선이에요(노란 선). GPIO는 코드로 입력과 출력을 정해 쓰는 핀이에요.

<figure>
<img src="/images/lessons/2-1-1/pin-connectors.svg" alt="부품별 핀 구성 표 그림: 3핀 GND, VCC, SIG는 버저, 레이저, 진동 모터, 서보모터, 3핀 GND, VCC, DIN은 네오픽셀, 4핀 GND, VCC, SDA, SCL은 문자 LCD와 OLED, 4핀 GND, VCC, TX, RX는 MP3 플레이어, 4핀 GND, VCC, InA, InB는 팬 모터, 5핀 GND, VCC, R, G, B는 RGB LED" width="640" height="384">
<figcaption>교과서 키트의 주요 부품 핀 구성이에요(원고 119쪽). 검정은 GND, 빨강은 VCC, 노란 칩은 신호 핀이에요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

신호 핀이 여러 개인 부품은 신호마다 이름이 달라요. 예를 들어 화면 부품의 SDA와 SCL은 I2C 통신 선이에요. I2C는 다음 차시인 2-1-2에서 배워요.

### 개발 환경 — 브라우저 실습실과 MicroPython

교과서는 컴퓨터에 편집 프로그램(Thonny)과 USB :용어[드라이버]를 설치하고, 보드에 MicroPython 펌웨어를 넣은 뒤 코드를 올려요. 이 사이트에서는 아무것도 설치하지 않고 브라우저의 **ESP32 실습실**에서 코드를 쓰고 [실행]을 눌러요.

<figure>
<img src="/images/lessons/2-1-1/dev-environment.svg" alt="내 컴퓨터 브라우저의 ESP32 실습실에서 실행을 누르면 1 가상 보드(화면 속 보드가 같은 코드로 움직임)와 2 실제 보드(USB로 연결, 처음 한 번은 보드 준비 페이지에서 MicroPython 펌웨어를 구움) 두 갈래로 가고, 아래에 보드가 켜지면 전원 켜짐, boot.py, main.py 차례로 실행된다는 흐름을 그린 그림" width="640" height="356">
<figcaption>같은 코드가 가상 보드와 실제 보드에서 똑같이 돌아요. 실제 보드는 처음 한 번만 준비하면 돼요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

- **가상 보드:** 실습실 화면 속 보드가 코드대로 움직여요. 보드가 없어도 II단원의 모든 실습을 할 수 있어요.
- **실제 보드:** 데이터 전송이 되는 USB 케이블로 보드를 꽂고 실습실의 [실제 보드] 탭에서 [보드 연결]을 눌러요. 처음 한 번은 [보드 준비하기](/start/board/) 페이지에서 연결을 확인하고 MicroPython 펌웨어를 구워요(보드에 기록해요).

보드를 꽂으면 운영 체제가 드라이버를 저절로 찾아 설치해 줄 때가 많아요(플러그 앤 플레이). 보드가 보이지 않으면 [보드 준비하기의 "연결이 안 될 때"](/start/board/#port-help-title)를 봐요.

보드가 켜질 때는 두 파일이 차례로 실행돼요.

| 파일 | 언제 실행되나요? | 무엇을 적나요? |
| --- | --- | --- |
| boot.py | 보드가 켜지면 가장 먼저 실행돼요. 보드에 기본으로 들어 있어요. | 주로 환경 설정(Wi-Fi, 통신 등) |
| main.py | boot.py가 끝나면 저절로 실행돼요. 사용자가 직접 만들어 저장해요. | 실제 프로그램 코드 |

실습실의 [보드에 저장]은 편집칸의 코드를 보드의 main.py로 저장해요. 그러면 컴퓨터 없이 전원만 넣어도 그 코드가 돌아요.

## 따라하기

보드가 제대로 움직이는지 확인하는 첫 코드예요. 교과서 123쪽의 "동작 테스트"를 실행하고, 이어서 버튼(입력)으로 LED(출력)를 켜 봐요. 보드가 없어도 가상 보드로 똑같이 할 수 있어요.

### 코드 읽기

예제 1(동작 테스트)의 줄 번호예요.

- 1번 줄: ESP32의 핀(Pin)을 다루는 도구를 `machine` 모듈에서 불러와요.
- 2번 줄: 초 단위로 기다리는 함수 `sleep`을 불러와요.
- 4번 줄: GPIO 2번 핀을 출력(`Pin.OUT`)으로 정해 `led`라고 불러요. 교과서 보드에서 "D2"라고 적힌 내장 LED가 이 핀에 붙어 있어요.
- 6\~10번 줄: `while True:` 안의 네 줄을 끝없이 되풀이해요. LED를 켜고(`led.on()`) 0.5초 기다린 뒤, 끄고(`led.off()`) 0.5초 기다려요.

예제 2(BOOT 버튼)는 입력 장치와 출력 장치를 함께 써요.

- 3\~4번 줄: 2번 핀은 LED용 출력으로, 0번 핀(BOOT 버튼)은 입력(`Pin.IN`)으로 정해요.
- 8번 줄: `sw.value()`로 버튼 값을 읽어 0이면(누르고 있으면) 9번 줄에서 LED를 켜고, 아니면 11번 줄에서 꺼요.
- 12\~15번 줄: 줄 앞에 `#`이 있는 주석이라 실행되지 않아요.

### 실행하고 결과 보기

1. 예제 1에서 [이 자리에서 실습실 열기]를 누르고 [실행]을 눌러요. 처음 한 번은 파이썬을 받느라 조금 걸려요.
2. 가상 보드 왼쪽의 내장 LED(IO2)가 0.5초마다 켜졌다 꺼지고, 아래 "핀 상태" 표의 GPIO2 값이 1(HIGH)과 0(LOW)으로 바뀌는지 봐요. 콘솔에는 아무것도 나오지 않아요.
3. [정지]를 누르면 LED가 꺼진 모습으로 돌아가요. 콘솔 위에 파란 안내 카드("[정지] 버튼으로 멈췄어요")가 나오는데, 오류가 아니에요.
4. 예제 2를 열어 [실행]한 뒤, 보드 그림의 BOOT 버튼을 마우스로 누르고 있어요. 키보드로는 Tab 키로 버튼에 간 뒤 Space를 누르고 있으면 돼요.

실제 보드에서 예제 1을 실행하면 보드의 초록색 D2 LED가 깜빡여요. LED가 깜빡이면 ESP32가 정상으로 작동한다는 뜻이에요.

:::확인
- 예제 1: 내장 LED가 0.5초마다 켜졌다 꺼지고, 핀 상태 표의 GPIO2가 1과 0으로 바뀌어요.
- 예제 2: BOOT 버튼을 누르고 있는 동안만 LED가 켜지고, 떼면 꺼져요.
- [정지]를 누르면 보드가 멈추고 LED가 꺼져요.
:::

:::왜그럴까
`Pin(2, Pin.OUT)`은 2번 핀을 전기를 내보내는 출력 핀으로 정해요. `led.on()`은 핀에 3.3V를 내보내 LED를 켜고, `led.off()`는 0V로 바꿔 꺼요. 핀 상태 표의 1(HIGH)과 0(LOW)이 바로 이 두 상태예요.

`sleep(0.5)`가 없으면 켜고 끄는 일이 눈으로 볼 수 없을 만큼 빨리 되풀이돼서 깜빡임이 보이지 않아요. `while True:`는 조건이 늘 참이라 [정지]를 누를 때까지 끝나지 않아요.
:::

:::왜그럴까[왜 BOOT 버튼은 누를 때 0이 될까?]
BOOT 버튼은 누르면 0번 핀을 GND(0V)에 이어요. 누르지 않을 때는 보드가 핀을 3.3V 쪽으로 약하게 끌어올려 두어서 1로 읽혀요. 그래서 예제 2는 `== 0`일 때 LED를 켜요. 반대로 터치 센서처럼 누르면 1이 되는 부품은 `== 1`로 확인해요(2-1-2에서 써요).
:::

## 바꿔보기

:::바꿔보기
1. 예제 1의 8번 줄과 10번 줄 `sleep(0.5)`를 모두 `sleep(0.1)`로 바꿔 보세요. 깜빡임이 어떻게 달라지나요?
2. 켜진 시간과 꺼진 시간을 다르게 해 보세요. 예: 8번 줄은 `sleep(1)`, 10번 줄은 `sleep(0.2)`로 바꾸면 LED가 어떻게 깜빡일까요?
3. 예제 2의 8번 줄 `== 0`을 `== 1`로 바꾸면 LED가 언제 켜질까요? 먼저 짐작해 보고 실행해 보세요.
:::

:::왜그럴까[왜 == 1로 바꾸면 거꾸로 켜질까?]
버튼을 누르지 않을 때 0번 핀은 1이에요. `== 1`로 바꾸면 "누르지 않을 때" 조건이 참이 되어 LED가 켜지고, 누르고 있을 때(0)는 꺼져요. 같은 버튼이라도 코드의 조건에 따라 동작이 거꾸로 바뀌어요.
:::

:::오류
`IndentationError`가 나면 `while True:` 아래 줄의 들여쓰기를 확인해요. 반복할 줄은 모두 같은 칸만큼 들여 써야 해요. `ValueError: invalid pin`은 ESP32에 없는 핀 번호를 적었다는 뜻이에요(예: `Pin(40, Pin.OUT)`). 오류 메시지의 뜻은 [오류 사전](/help/errors/#indentation-expected)에서 찾아볼 수 있어요.
:::

::::도전[도전 과제 1: 생활 속 피지컬 컴퓨팅 장치 나눠 보기]
자동문, 스마트 가로등, 화재 경보기처럼 우리 주변에서 스스로 움직이는 장치를 하나 골라요. 그 장치를 입력 장치, 처리 장치, 출력 장치로 나눠 정리해 보세요.

| 구분 | 적을 내용 |
| --- | --- |
| 장치 이름 | 무엇을 하는 장치인가요? |
| 입력 장치(센서) | 무엇을 알아채나요? |
| 처리 장치 | 알아챈 값으로 무엇을 판단하나요? |
| 출력 장치(액추에이터) | 판단한 결과로 무엇을 움직이거나 보여 주나요? |

:::힌트
자동문이라면 문 위의 센서가 사람이 다가오는 것을 알아채요(입력). 문 안의 마이크로컨트롤러가 "사람이 있다"고 판단하면(처리), 모터가 문을 열어요(출력). 판단하는 규칙은 마이크로컨트롤러 안의 프로그램(펌웨어)에 들어 있어요.
:::
::::

::::도전[도전 과제 2: 내장 LED로 SOS 신호 보내기]
구조 신호 SOS는 짧게 세 번, 길게 세 번, 짧게 세 번 깜빡이는 신호예요. 예제 1을 고쳐 내장 LED로 SOS 신호를 되풀이해 보내 보세요.

:::힌트
짧게는 0.2초, 길게는 0.6초 켜고, 깜빡임 사이는 0.2초 쉬어요. 같은 일을 되풀이할 때는 `for i in range(3):`를 쓰면 코드가 짧아져요.

```python
def blink(on_time):   # on_time초 동안 켰다가 끄는 함수
    led.on()
    sleep(on_time)
    led.off()
    sleep(0.2)
```

`while True:` 안에서 `blink(0.2)`를 세 번, `blink(0.6)`을 세 번, 다시 `blink(0.2)`를 세 번 부르고, 한 번 끝날 때마다 `sleep(1.5)`로 쉬어요.
:::

### 자주 막히는 곳

- 센서와 액추에이터를 헷갈려요. "알아채는 쪽(입력)"과 "움직이는 쪽(출력)"으로 짚어 주세요. 디스플레이와 스피커도 출력 장치예요.
- 펌웨어와 내 코드를 헷갈려요. 펌웨어(MicroPython)는 보드가 파이썬을 알아듣게 하는 바탕 프로그램이고, 내 코드(main.py)는 그 위에서 도는 프로그램이에요.
- BOOT 버튼은 누르면 0이라 "거꾸로" 동작해요. 따라하기의 두 번째 "왜 이런 결과가 나올까" 상자로 설명해요.
- 예제 2(키트 확인 코드)의 들여쓰기는 3칸, 7칸으로 들쭉날쭉해요. 같은 묶음 안의 줄끼리만 칸 수가 같으면 된다는 것을 짚어 주세요. 새로 쓸 때는 4칸씩 들여 쓰게 해요.
- 실제 보드가 컴퓨터에 보이지 않으면 대개 충전 전용 케이블이거나 드라이버 문제예요. 실제 보드 연결은 Chrome이나 Edge 데스크톱에서만 돼요(Web Serial). [보드 준비하기](/start/board/)의 "연결이 안 될 때"를 함께 봐요.
- [정지] 뒤 콘솔 위의 파란 카드는 오류가 아니라 안내예요. 빨간 오류 카드와 색으로 구별하게 해요.

### 원고에서 바꾼 곳

- 원고 117\~123쪽(학습 목표, 본문, 표, 코드, 자기 평가)을 차시 틀에 맞게 옮기고 문장을 다듬었어요. 116쪽 중단원 성취 계획과 123쪽 자기 평가는 위 평가 포인트로 옮겼어요. 원고에 학습 활동이 없어 도전 과제 두 개는 사이트가 만들었어요.
- 120\~122쪽의 설치 절차(CH340 드라이버 내려받기, Thonny 설치와 설정, MicroPython 1.25.0 설치)는 설치 없는 사이트 흐름(ESP32 실습실, 보드 준비 페이지의 연결 확인과 펌웨어 굽기)으로 다시 썼어요. 원래 설치 절차는 교사용 자료실의 ["진짜 PC에서 돌리기"](/teacher/real-pc/#5-esp32-보드를-토니로-쓰기ii단원)로 옮겼어요. 사이트가 굽는 펌웨어는 MicroPython v1.29.0이에요.
- 117쪽 입력, 처리, 출력 그림은 사이트가 그린 임베디드 시스템 그림으로, 119쪽 부품 사진 카드는 핀 구성 표 그림으로 바꿨어요. 118쪽 키트 사진은 원고 그대로 싣고, 다른 키트를 쓰는 학교를 위해 가상 보드와 같은 모양의 보드 그림을 더했어요.
- 117쪽 "소형 컴퓨팀 시스템"은 "소형 컴퓨터 시스템"의 오타라 고쳤어요. 123쪽의 "D2"는 GPIO 2번 핀에 붙은 LED라고 풀어 썼어요.
- 예제 2(BOOT 버튼, 코드 id f015)는 원고에는 없고 교과서 키트 자료의 보드 확인 코드예요. 입력 장치와 출력 장치를 함께 보여 주려고 더했어요.
- 블루투스 교안 41\~42쪽의 "Light turn on off" 코드는 예제 1과 같은 동작이에요. 캡처 화면의 코드를 글자로 옮기면 아래와 같아요(주석은 다듬었어요). 교안 주석처럼 셸(REPL)에 `led.on()`을 한 줄씩 입력해 켜 보는 방법은 가상 보드에는 없어서, 코드로 실행해요.

```python
from machine import Pin
from time import sleep  # 기다리기(delay)를 위한 sleep

led = Pin(2, Pin.OUT)  # 2번 핀을 출력으로 정해요
# 셸 창에 led.on()을 입력하면 보드의 LED가 켜지고,
# led.off()를 입력하면 꺼져요.

# 셸 창이 아니라 코드로 바로 명령하고 싶으면
while True:
    led.on()
    sleep(0.5)
    led.off()
    sleep(0.5)  # LED가 0.5초 간격으로 꺼졌다 켜졌다 해요
```
:::
