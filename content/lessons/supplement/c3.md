## 학습목표

- 카메라가 찾은 :용어[랜드마크]로 편 손가락 개수를 셀 수 있어요.
- 센 값을 통신으로 보내고, 보드가 그 값을 받아 장치를 움직이게 할 수 있어요.
- 상태(지금 값)는 바뀔 때만 보내면 된다는 것을 설명할 수 있어요.

## 왜 배울까

앞 차시에서는 컴퓨터가 손을 "보기"만 했어요. 이제 본 것을 **다른 기계에 알려 주는** 차례예요.

인공지능이 알아본 것을 숫자 하나로 줄여 보내면, 보드는 그 숫자만 보고도 움직일 수 있어요. 카메라가 없는 보드가 "손가락이 세 개 펴졌다"를 아는 방법이 바로 이것이에요. 공장의 검사 장비, 손동작으로 켜는 조명도 같은 구조예요.

## 핵심 개념

### 편 손가락을 어떻게 세나

손 랜드마크는 21개 점이에요. 손가락마다 **끝**과 **뿌리 관절**이 있고, 기준점(손목 0번, 엄지는 소지 뿌리 17번)에서 얼마나 먼지를 재요.

| 손 모양 | 끝과 기준점의 거리 | 판정 |
| --- | --- | --- |
| 손가락을 폈을 때 | 끝이 뿌리 관절보다 **멀다** | 펴짐(1) |
| 손가락을 접었을 때 | 끝이 뿌리 관절보다 **가깝다** | 접힘(0) |

다섯 손가락을 모두 보면 `11000`처럼 0과 1 다섯 글자가 나와요. 여기서 1의 개수가 곧 편 손가락 수예요.

:::참고
교안의 "접혀있는 손가락 감지" 예제는 손가락을 세는 부분이 **손마다 도는 반복문 바깥**에 있어요. 손이 하나일 때는 괜찮지만, 두 개가 보이면 마지막 손의 좌표만 쓰게 돼요. 이 차시의 예제는 세는 부분을 반복문 **안**으로 옮기고 손마다 더해요.
:::

### 무엇을 보낼까 — 숫자 하나

손 전체의 좌표 21개를 다 보낼 필요는 없어요. 보드가 할 일은 "몇 개 켤까"뿐이니 **숫자 하나**면 돼요.

- 보내는 글자: `3` + 줄바꿈 → 모두 2바이트
- 한 번에 보내는 크기는 20바이트 안쪽으로 짧게 — 블루투스로 같은 코드를 옮길 때도 그대로 되도록 맞춘 약속이에요.

### 상태와 이벤트

| 갈래 | 뜻 | 보내는 방법 | 밀리면 |
| --- | --- | --- | --- |
| 상태 | 지금 값(손가락 개수, 좌표) | `bridge.send("3")` | 최신 값만 보내면 돼요 |
| 이벤트 | 한 번 일어난 일(클릭, 윙크) | `bridge.event("CLICK")` | 하나도 빠지면 안 돼요 |

`bridge.send()`는 **앞에 보낸 값과 같으면 보내지 않아요.** 손가락 개수가 그대로면 통신이 한 번도 일어나지 않아요.

## 따라하기

두 화면을 함께 써요. **보드 쪽을 먼저 실행**하고, 그다음 컴퓨터 쪽을 실행해요(보드가 꺼져 있을 때 온 글자는 실물처럼 사라져요).

1. 아래 보드 쪽 예제를 실습실에서 열고 [실행]을 눌러요. 네오픽셀 링이 모두 꺼진 채로 기다려요.
2. 컴퓨터 쪽 예제를 열고, 오른쪽 [보내기] 패널에서 [한 화면에 가상 보드 열기]를 눌러 보드 화면을 같은 화면에 띄워요.
3. [실행]을 눌러요. 웹캠이 없으면 입력 소스를 **재생 입력**으로 골라요(손가락 0~5개 동작이 들어 있어요).

::예제

:::왜그럴까
컴퓨터 쪽은 사진 한 장마다 손가락을 세지만, 통신은 개수가 **바뀔 때만** 일어나요. 그래서 콘솔의 `Sent:` 줄은 손가락을 접거나 펼 때만 늘어나요.

보드 쪽은 `uart.readline()`으로 줄바꿈이 올 때까지 기다렸다가 한 줄을 읽어요. 그 줄이 숫자일 때만 링을 다시 그려요. 숫자가 아닌 글자가 와도 링은 그대로예요 — 통신으로는 엉뚱한 값도 올 수 있으니 받는 쪽이 늘 확인해야 해요.
:::

:::확인
- 보드 쪽 콘솔에 `기다리는 중…`이 보여요.
- 컴퓨터 쪽 화면 왼쪽 위에 편 손가락 수가 큰 글자로 보여요.
- 손가락을 하나씩 펼 때마다 네오픽셀 링의 켜진 LED가 하나씩 늘어나요.
- 주먹을 쥐면 링이 모두 꺼져요.
:::

:::오류
- **`BridgeError: ESP32 실습실 탭을 찾지 못했어요`** — 보드 쪽 화면을 먼저 열어요. [보내기] 패널의 [한 화면에 가상 보드 열기]나 [ESP32 실습실 새 탭에서 열기]를 누른 뒤 다시 [실행]해요.
- **링이 켜지지 않아요** — 보드 쪽이 [실행] 중인지 보고, 보드 아래 변환기 조작 칸에서 `3`을 직접 보내 봐요. 그래도 안 켜지면 배선(변환기 RX 17 · TX 16)을 봐요.
- **글자가 깨져 보여요** — 보내는 쪽과 받는 쪽의 속도(bps)가 달라요. 보드 쪽 `baudrate=9600`을 확인해요.
:::

## 바꿔보기

:::바꿔보기
1. 컴퓨터 쪽 `max_num_hands=2`를 `1`로 바꿔 보세요. 손을 두 개 보여 줘도 한 손만 세는 것을 확인해요.
2. 보드 쪽 `COLOR`를 `(90, 0, 0)`으로 바꿔 빨간 링으로 만들어 보세요.
3. 컴퓨터 쪽에서 `bridge.send(str(total))`을 지우고 `bridge.event(str(total))`로 바꿔 보세요. 같은 값이어도 계속 보내서 콘솔의 `Sent:` 줄이 훨씬 빨리 늘어나요.
:::

## 도전 과제

::::도전[도전 과제: 손가락 개수로 색도 바꾸기]
지금은 켜지는 **개수**만 바뀌어요. 개수에 따라 **색**도 달라지게 만들어 보세요. 예를 들어 1~2개는 파랑, 3~4개는 초록, 5개는 빨강이에요.

:::힌트
보드 쪽 `show(count)` 안에서 색을 먼저 정하면 돼요.

```python
if count >= 5:
    color = (90, 0, 0)
elif count >= 3:
    color = (0, 90, 0)
else:
    color = (0, 0, 90)
```

그다음 `np[i] = color if i < count else (0, 0, 0)`으로 바꿔요.
:::
::::

### 다음은 무엇을 배울까

여기까지는 컴퓨터와 보드를 **선(USB-UART 변환기)**으로 이었어요. 같은 코드를 선 없이 보내려면 통로만 바꾸면 돼요 — 컴퓨터 쪽 코드는 한 글자도 바뀌지 않아요. 블루투스는 3-1-3에서, 와이파이와 MQTT는 보충 C1에서 다뤄요.

### 자주 막히는 곳

- **보드 쪽을 나중에 실행**하면 먼저 보낸 값이 사라져 링이 안 켜져요. 실물 통신과 같아요 — 받는 쪽을 먼저 켜는 습관을 들이게 해요.
- 두 화면의 **통신 접두어**가 달라도 안 이어져요. [보내기] 패널이 열어 준 화면은 접두어가 자동으로 같아요.
- 웹캠이 없는 교실에서는 **재생 입력**(합성 손 좌표)으로 똑같이 끝낼 수 있어요. 사람을 찍은 영상이 아니라 계산으로 만든 좌표예요.
