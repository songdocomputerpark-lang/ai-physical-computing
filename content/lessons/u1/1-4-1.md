## 학습목표

- 포즈 트래킹이 무엇인지 알고, 우리 생활에서 쓰이는 예를 들 수 있어요.
- MediaPipe Pose로 영상 속 사람의 관절 33곳을 찾아 뼈대처럼 그릴 수 있어요.
- 손목의 y 좌표를 기준값과 비교해 손을 들었는지 판단하는 프로그램을 만들 수 있어요.

## 왜 배울까

운동 앱은 카메라로 운동하는 모습을 보고 자세가 바른지 알려 주고, 몸짓 게임은 팔을 휘두르면 화면 속 캐릭터가 따라 움직여요. 이런 프로그램은 카메라 영상에서 사람의 관절 위치를 찾아, 그 위치의 숫자로 자세와 동작을 판단해요. 이번 차시에서는 관절 위치로 손을 들었는지 알아채는 프로그램을 직접 만들어요.

## 핵심 개념

### 포즈 트래킹과 자세 랜드마크

:용어[포즈 트래킹](Pose Tracking)은 카메라 영상 속 사람의 관절 위치를 찾아내고, 그 위치로 자세와 동작을 알아보는 기술이에요. 우리말로 자세 추적이라고도 해요. MediaPipe의 자세 인식 모델인 **MediaPipe Pose**는 영상 속 사람 한 명의 몸에서 :용어[랜드마크] 33곳을 찾아요.

<figure>
<img src="/images/lessons/1-4-1/pose-landmarks-33.svg" alt="우리를 마주 보고 선 사람의 몸에 점 33개가 찍혀 선으로 이어진 그림: 0~10번은 얼굴, 11·12번은 어깨, 13·14번은 팔꿈치, 15·16번은 손목, 17~22번은 손, 23·24번은 엉덩이, 25·26번은 무릎, 27·28번은 발목, 29~32번은 발이고, 홀수 번호인 사람의 왼쪽이 그림의 오른쪽에 있다" width="640" height="610">
<figcaption>점마다 번호가 정해져 있어요. 홀수는 사람의 왼쪽, 짝수는 사람의 오른쪽이에요. 우리를 마주 보는 사람이라서 사람의 왼쪽(LEFT)이 그림의 오른쪽에 있어요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

이 단원의 예제에서 자주 쓰는 점은 다음과 같아요.

| 번호 | 코드에서 부르는 이름 | 부위 |
| --- | --- | --- |
| 0 | `NOSE` | 코 |
| 11, 12 | `LEFT_SHOULDER`, `RIGHT_SHOULDER` | 왼쪽 어깨, 오른쪽 어깨 |
| 13, 14 | `LEFT_ELBOW`, `RIGHT_ELBOW` | 왼쪽 팔꿈치, 오른쪽 팔꿈치 |
| 15, 16 | `LEFT_WRIST`, `RIGHT_WRIST` | 왼쪽 손목, 오른쪽 손목 |
| 23, 24 | `LEFT_HIP`, `RIGHT_HIP` | 왼쪽 엉덩이, 오른쪽 엉덩이 |

코드에서는 `mp_pose.PoseLandmark.LEFT_WRIST.value`처럼 이름으로 번호를 불러요(이 값은 15예요). 왼쪽과 오른쪽은 화면을 보는 내가 아니라 **영상 속 사람**을 기준으로 해요.

### 손목의 y 좌표로 손을 들었는지 알아채기

랜드마크는 점마다 위치와 "보이는 정도"를 숫자로 알려 줘요.

| 값 | 뜻 |
| --- | --- |
| `x` | 가로 위치예요. 영상 왼쪽 끝이 0, 오른쪽 끝이 1이에요. |
| `y` | 세로 위치예요. 영상 맨 위가 0, 맨 아래가 1이에요. |
| `z` | 깊이예요. 엉덩이 한가운데를 0으로 해서, 값이 작을수록 카메라에 가까워요. |
| `visibility` | 그 점이 영상에 보일 가능성이에요(0~1). 가려지거나 화면 밖에 있으면 작아져요. |

x와 y는 :용어[정규화 좌표]예요. 영상의 가로와 세로 길이를 각각 1로 본 값이라서, 영상 크기가 달라도 같은 자리는 같은 숫자예요. 여기서 꼭 기억할 것은 **y가 아래로 갈수록 커진다**는 점이에요. 그래서 손을 번쩍 들수록 손목의 y는 작아져요.

<figure>
<img src="/images/lessons/1-4-1/wrist-y-check.svg" alt="카메라 영상 위에 그린 사람 뼈대 그림: 세로 위치 y는 맨 위가 0, 맨 아래가 1이고 0.3 높이에 기준선 TARGET_Y가 있다. 든 손목인 15번 점은 y가 0.2라서 0.2 < 0.3이 참이 되어 Success!를 쓰고, 손을 내려 y가 0.9일 때는 거짓이라 아무것도 쓰지 않는다" width="640" height="336">
<figcaption>손목이 기준선(TARGET_Y)보다 위에 있으면, 곧 y가 기준값보다 작으면 손을 든 거예요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

이렇게 값을 둘로 나누는 기준이 되는 수를 :용어[임계값]이라고 해요. 심화 실습의 `TARGET_Y = 0.3`이 임계값이에요.

## 따라하기

먼저 기본 실습으로 몸의 뼈대를 그리고, 심화 실습에서 손을 들었는지 알아채요. 카메라가 없어도 실습실이 계산으로 만든 자세 좌표(재생 입력)로 똑같이 할 수 있어요.

### 코드 읽기: 기본 실습(몸의 뼈대 그리기)

- 2~3행: OpenCV(`cv2`)와 MediaPipe(`mp`) :용어[라이브러리]를 불러와요.
- 6~7행: 자세 인식 모듈(`mp.solutions.pose`)과 랜드마크를 그리는 도구(`drawing_utils`)를 준비해요.
- 10~11행: 자세 인식 모델(`Pose()`)을 만들고 웹캠(0번 카메라)에 연결해요.
- 14~17행: 웹캠이 열려 있는 동안 :용어[프레임](영상을 이루는 사진 한 장)을 읽어요. 읽지 못하면 반복을 끝내요.
- 19행: 영상을 좌우로 뒤집어 거울처럼 보이게 해요.
- 20행: 색 순서를 :용어[BGR]에서 RGB로 바꿔요. MediaPipe는 RGB 순서의 사진을 받기 때문이에요.
- 22행: 자세를 찾아 결과(`results`)를 받아요. 24행에서는 화면에 보여 주려고 다시 BGR로 바꿔요.
- 27~32행: 자세를 찾았으면 랜드마크와 연결선(`POSE_CONNECTIONS`)을 영상 위에 그려요.
- 34~37행: 'Pose Tracking' 창에 보여 주고, q 키를 누르면 반복을 끝내요.
- 40~41행: 웹캠을 놓아주고 창을 닫아요.

### 코드 읽기: 심화 실습(왼손 들기 알아채기)

줄 번호는 교과서 코드 파일(파일명 p88)과 같아요. 사이트판은 14~15행만 달라요.

- 14행: 성공 기준 `TARGET_Y = 0.3`을 정해요. 줄 끝의 `@slider`는 실습실 조절 패널에 막대를 만드는 표시예요(사이트판).
- 15행: `left_wrist_y`의 처음 값을 1.0(화면 맨 아래)으로 정해 둬요(사이트판). 교과서 파일에는 이 줄이 없어요. 까닭은 바꿔보기의 "이런 오류가 나면" 상자에 있어요.
- 22~26행: RGB로 바꿔 자세를 찾고, 다시 BGR로 바꿔요. 기본 실습과 달리 인식하기 **전에는 뒤집지 않아요**.
- 29~33행: 자세를 찾았으면 33곳의 좌표 목록(`landmarks`)에서 15번 점(왼쪽 손목)의 y를 꺼내요.
- 36~40행: 뼈대를 그려요. 43행: 다 그린 **뒤에** 좌우로 뒤집어 거울처럼 보이게 해요.
- 46~49행: 왼쪽 손목의 y가 `TARGET_Y`보다 작으면(더 위에 있으면) 초록색 `Success!`를 써요.
- 52~55행: 'Mirror Pose Game' 창에 보여 주고, q 키를 누르면 끝내요.

### 실행하고 결과 보기

1. 기본 실습의 [이 자리에서 실습실 열기]를 누르고 [실행]을 눌러요. 처음 한 번은 파이썬과 OpenCV를 받느라 조금 걸려요. 브라우저가 카메라 사용을 물으면 "허용"을 눌러요. 웹캠으로 할 때는 어깨와 팔이 화면에 다 들어오게 조금 뒤로 물러나요.
2. 카메라가 없으면 입력 소스에서 '재생 입력(합성 좌표)'을 골라요. 자세를 찾는 코드를 실행하면 '인식(mediapipe)' 칸의 재생 동작이 '손 들기'로 바뀌어요. 재생 입력의 사람은 왼손을 천천히 들었다가 내려요.
3. 'Pose Tracking' 창에서 사람 몸 위로 빨간 점과 흰 선이 뼈대처럼 그려지는지 봐요.
4. 심화 실습도 같은 방법으로 실행해요. 'Mirror Pose Game' 창에서 왼손이 기준선보다 높이 올라가면 왼쪽 위에 초록색 `Success!`가 떠요. 조절 패널에는 `TARGET_Y` 막대가 생겨요.

:::확인
- 'Pose Tracking' 창에 몸의 점과 이음선이 보이고, 팔이 움직이면 점도 따라 움직여요.
- 'Mirror Pose Game' 창에서 왼손을 높이 들면 `Success!`가 뜨고, 손을 내리면 사라져요.
- 조절 패널에 `TARGET_Y` 막대가 보여요.
:::

:::왜그럴까[왜 몸 위에 뼈대가 그려질까?]
10행의 `Pose()`는 미리 학습된 자세 인식 모델을 준비해요. 반복문이 프레임을 읽을 때마다 22행의 `pose.process()`가 몸의 랜드마크 33곳을 찾고, 27~32행이 그 점과 이음선을 영상 위에 그려요.

재생 입력이나 책상에 앉은 모습처럼 다리가 화면 밖에 있으면 무릎과 발목의 점은 그려지지 않아요. `draw_landmarks()`는 보이는 정도(`visibility`)가 0.5보다 작은 점을 건너뛰기 때문이에요.
:::

:::왜그럴까[왜 왼손을 높이 들면 Success!가 뜰까?]
33행은 15번 점(왼쪽 손목)의 y 좌표를 꺼내요. y는 영상 맨 위가 0, 맨 아래가 1이라서 손을 높이 들수록 작아져요. 46행은 그 값이 `TARGET_Y`(0.3)보다 작을 때만 `Success!`를 써요.

43행에서 영상을 뒤집는 것은 인식이 **끝난 뒤**예요. 그래서 모델이 찾은 `LEFT_WRIST`는 실제 왼손 손목이고, 화면에서는 거울처럼 왼쪽에 보여요.
:::

:::바꿔보기

3. 기본 실습 19행 맨 앞에 `#`을 붙여 이 줄을 주석으로 만든 뒤 실행해 보세요. 재생 입력에서 올라가는 팔이 창의 어느 쪽에 보이나요?
:::

:::왜그럴까[막대를 옮기면 왜 결과가 달라질까?]
`TARGET_Y`는 화면에 그은 가로 기준선이에요. 값을 크게 하면 선이 아래로 내려가서 손을 조금만 들어도 손목이 선보다 위에 있게 돼요. 반대로 0.2까지 줄이면 선이 위로 올라가요. 재생 입력의 손목은 가장 높이 들어도 y가 0.25쯤이라 한 번도 성공하지 못해요.

`RIGHT_WRIST`(16번)는 오른쪽 손목이에요. 재생 입력의 사람은 왼손만 들기 때문에 `Success!`가 뜨지 않아요. 19행을 주석으로 만들면 영상을 뒤집지 않으니, 사람이 든 왼손이 거울과 반대로 창의 오른쪽에 보여요.
:::

:::오류
교과서 파일 그대로인 예제('1-4-1 심화 실습: 왼손 들기 알아채기')는 첫 장면에 사람이 보이지 않으면 `NameError: name 'left_wrist_y' is not defined`가 나요. [실행]을 누르고 카메라 앞으로 걸어가는 사이에 흔히 나요. `left_wrist_y`는 사람을 찾은 장면(29행의 `if` 안)에서만 값이 정해지는데, 46행은 `if` 밖에서 비교하기 때문이에요. 반복문 앞에 `left_wrist_y = 1.0`을 넣으면 돼요(사이트판 15행). 오류 메시지의 뜻은 [오류 사전](/help/errors/)에서 찾아볼 수 있어요.
:::

지금은 화면에 고정된 선(`TARGET_Y = 0.3`)과 비교해서, 카메라에서 멀리 서거나 가까이 서면 결과가 달라져요. 왼쪽 손목이 **왼쪽 어깨보다 위에** 있을 때 `Success!`를 쓰도록 심화 실습을 바꿔 보세요.

:::힌트
29~33행의 `if` 안에서 11번 점(왼쪽 어깨)의 y도 꺼내요.

```python
left_shoulder_y = landmarks[mp_pose.PoseLandmark.LEFT_SHOULDER.value].y
```

반복문 앞(15행 아래)에는 `left_shoulder_y = 0.0`을 넣어 두고, 46행을 `if left_wrist_y < left_shoulder_y:`로 바꿔요. 대단원 마무리 4번 문제의 풀이와 같은 생각이에요.
:::
::::

::::도전[도전 과제 2: 손을 든 횟수 세기]
손을 들었다 내릴 때마다 횟수를 세어 화면에 `Count: 3`처럼 보여 주세요. 손을 들고 있는 동안 계속 세지 말고, 내렸다가 다시 들 때 한 번만 세야 해요.

:::힌트
반복문 앞에 `count = 0`과 `was_up = False`를 만들어요. 43행 뒤(영상을 뒤집은 다음)에 아래 코드를 넣어요. 뒤집은 다음에 써야 글자가 거울처럼 뒤집히지 않아요.

```python
    is_up = left_wrist_y < TARGET_Y
    if is_up and not was_up:
        count += 1
    was_up = is_up
    cv2.putText(image, f'Count: {count}', (30, 90), cv2.FONT_HERSHEY_SIMPLEX, 1, (0, 255, 255), 2)
```

`was_up`은 바로 앞 장면에서 손을 들고 있었는지를 기억해요. "앞 장면에는 내리고 있었는데 지금은 들었다"일 때만 1을 더해요.
:::

## 교사용

### 지도안 요약(50분, 사이트가 제안하는 흐름)

1. 도입(5분): 몸짓으로 캐릭터를 움직이는 게임이나 운동 앱을 써 본 경험을 나누고 "왜 배울까" 그림을 봐요.
2. 전개 1(10분): 자세 랜드마크 그림에서 11~16번(어깨, 팔꿈치, 손목)을 함께 찾고, 왼쪽과 오른쪽이 영상 속 사람 기준이라는 것을 확인해요.
3. 전개 2(12분): 기본 실습을 실행해 뼈대를 보고, 다리가 그려지지 않는 까닭(보이는 정도)을 이야기해요.
4. 전개 3(15분): 심화 실습을 실행하고 `TARGET_Y` 막대를 바꿔 봐요. 바꿔보기 2·3은 결과를 먼저 예상한 뒤 확인해요.
5. 정리(8분): 확인 퀴즈를 풀고, 대단원 마무리 4·7번 문제로 오늘 내용을 점검해요.

### 평가 포인트

이 차시는 원고가 없어 원고의 자기 평가 문항이 없어요. 아래는 다른 차시와 같은 모양으로 사이트가 제안하는 자기 평가 문항이에요(학생이 세 단계로 스스로 표시).

- 포즈 트래킹의 뜻을 알고, 쓰이는 예를 들 수 있는가?
- 자세 랜드마크의 번호와 좌표로 몸의 특정 부위의 위치를 찾을 수 있는가?
- 손목의 y 좌표와 기준값을 비교해 손을 들었는지 판단하는 프로그램을 만들 수 있는가?

대단원 마무리와 이어지는 문항은 4번(왼손을 들었는지 판단하는 방법), 7번(포즈 트래킹의 뜻), 10번(`pose.process()`에 넘기기 전의 BGR → RGB 변환)이에요.

관찰할 곳: `TARGET_Y`를 바꿨을 때의 결과를 "기준선이 위아래로 움직인다"로 설명하는지, 영상의 y가 아래로 갈수록 커진다는 것을 말하는지 봐요.

### 자주 막히는 곳

- 웹캠 앞에 너무 가까이 앉으면 어깨와 팔이 화면 밖으로 나가 점이 흔들리거나 사라져요. 상반신이 다 들어오게 뒤로 물러나게 해요.
- 영상의 y는 수학 시간의 좌표와 반대로 아래로 갈수록 커져요. 조건을 `>`로 쓰는 학생이 많으니 그림의 기준선으로 짚어 주세요.
- 왼쪽과 오른쪽: 기본 실습처럼 인식하기 **전에** 영상을 뒤집으면(19행) 모델이 거울에 비친 사람을 보고 왼쪽과 오른쪽을 반대로 불러요. 심화 실습은 인식한 **뒤에** 뒤집어서(43행) `LEFT_WRIST`가 실제 왼손이에요. 실습실의 재생 입력도 같은 규칙으로 움직여요.
- 교과서 파일(파일명 p88)은 첫 장면에 사람이 없으면 `NameError`가 나요. 수업에서는 사이트판을 쓰고, 원본은 바꿔보기의 오류 상자로 원인을 함께 읽어요.
- 컴퓨터가 느리면 '인식(mediapipe)' 칸의 "저사양 모드(자세 모델을 가벼운 것으로)"를 켜요.

### 코드 파일과 사이트판

- 원고(교과서 052~111쪽)가 자료에 없어, 코드 파일과 대단원 마무리 문항(4·7·10번)을 근거로 사이트가 본문을 새로 썼어요. 원고를 받으면 원고 문장으로 바꿔요.
- 기본 실습은 코드 파일(파일명 p85, 코드 id f040) 그대로예요.
- 심화 실습(파일명 p88, 코드 id f041)은 사이트판을 따라하기 예제로 썼어요. 원본과 줄 번호가 같고, 14행 끝에 조절 막대 표시(`@slider`)를, 빈 줄이던 15행에 `left_wrist_y = 1.0`을 넣은 것만 달라요(원본 46행의 `NameError` 방지). 교과서 파일 그대로인 판도 실습실 예제 목록에 있어요.
- 함께 쓸 수 있는 교안 예제: OpenCV·MediaPipe 계단 15 '자세 점 그려 보기'(코드 id f123)는 선과 점의 색을 `DrawingSpec`으로 바꿔 그려요. 마지막 줄의 오타(`destoyAllWindows`) 때문에 ESC 키로 끝내면 `AttributeError`가 나서, 오류를 읽는 연습으로 쓸 수 있어요.
