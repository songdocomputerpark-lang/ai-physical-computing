## 학습목표

- :용어[임계값]이 값을 둘로 나누는 기준이라는 것을 설명할 수 있어요.
- `cv2.threshold`의 결과가 0과 255 두 값만 가진 사진(이진 사진)이라는 것을 알아요.
- 기준을 올리고 내릴 때 흰 부분이 어떻게 달라지는지 예상하고 확인할 수 있어요.

## 왜 배울까

물체를 찾으려면 먼저 "여기는 물체, 여기는 배경"으로 사진을 갈라야 해요. 가장 간단한 방법이 밝기 기준 하나로 둘로 나누는 임계값이에요. 흰 종이 위의 검은 글자, 어두운 바탕의 밝은 손처럼 밝기 차이가 큰 것은 이 방법만으로도 갈라져요.

기준 하나로 예·아니오를 정하는 생각은 뒤에도 계속 나와요. V5의 윤곽선 찾기는 이 이진 사진에서 시작하고, 손·얼굴 인식의 "신뢰도 0.5 이상만 믿기"도 같은 임계값이에요.

임계값은 값을 둘로 나누는 기준이에요. 회색 사진의 :용어[픽셀]마다 "기준보다 밝은가?"라고 묻고, 예면 255(흰색), 아니오면 0(검은색)으로 바꿔요. 결과에는 두 값만 남아서 이런 사진을 **이진 사진**이라고 해요.

기준을 내리면 예라고 답하는 픽셀이 늘어 흰 부분이 커지고, 기준을 올리면 줄어요. 그림의 파란 점선을 왼쪽·오른쪽으로 옮긴다고 생각하면 돼요.

### 코드 한 줄

```python
_, binary = cv2.threshold(gray, 128, 255, cv2.THRESH_BINARY)
```

| 자리 | 뜻 |
| --- | --- |
| `gray` | 회색 사진(먼저 `cv2.cvtColor`로 바꿔 둔 것) |
| `128` | 기준(임계값). 이보다 큰 픽셀만 바꿔요 |
| `255` | 예일 때 넣을 값(흰색) |
| `cv2.THRESH_BINARY` | 나누는 방식. `cv2.THRESH_BINARY_INV`는 예·아니오를 뒤집어요 |

앞의 `_`는 함수가 함께 돌려주는 "실제로 쓴 기준값"인데 여기서는 쓰지 않아서 빈 이름에 받아요.

### 뒤집기와 자동 기준

어두운 물체를 흰 덩어리로 잡고 싶으면 `cv2.THRESH_BINARY_INV`로 뒤집어요. 조명이 바뀌어 알맞은 기준이 달라질 때는 `cv2.THRESH_BINARY + cv2.THRESH_OTSU`처럼 적으면 OpenCV가 밝기 분포를 보고 기준을 스스로 정해요(이때 우리가 적은 128은 무시돼요).

## 따라하기

영상처리 실습실에서 예제를 열고 [실행]을 눌러요. `binary` 창에 흰색·검은색만 있는 사진이, `gray` 창에 비교용 회색 사진이 보여요. 조절 패널의 `threshold`를 움직이면 다음 프레임부터 흰 부분이 달라지고, 기준이 바뀔 때마다 콘솔에 흰 픽셀 비율이 찍혀요.

::예제

:::왜그럴까
결과 사진에 흰색과 검은색만 있는 것은 픽셀마다 질문이 하나("기준보다 밝은가?")뿐이기 때문이에요. 기준을 60까지 내리면 어두운 바탕까지 예가 되어 거의 다 하얘지고, 200 넘게 올리면 전등이나 흰 종이처럼 아주 밝은 곳만 남아요. `invert`를 켜면 예·아니오가 바뀌어 흰 부분과 검은 부분이 뒤집혀요.
:::

:::확인
- `binary` 창에는 회색이 없고 흰색과 검은색만 보여요.
- `threshold`를 내리면 흰 부분이 늘고, 올리면 줄어요. 콘솔의 흰 픽셀 비율(%)도 함께 바뀌어요.
- `invert`를 켜면 흰 부분과 검은 부분이 뒤바뀌어요.
:::

### 자주 막히는 곳

- `cv2.threshold`가 값을 두 개 돌려주는 것을 몰라 `binary = cv2.threshold(...)`로 받고 `imshow`에서 오류가 나요. `_, binary = …`처럼 두 이름으로 받아야 해요.
- 기준 "이상"과 "보다 큼"을 헷갈려요. THRESH_BINARY는 기준보다 큰 픽셀만 255가 돼요(퀴즈 1번).
- 교실 조명이 바뀌면 어제 잘 되던 기준이 안 맞아요. 이것이 OTSU·adaptive 같은 방법이 있는 까닭이라고 이어 주세요.
