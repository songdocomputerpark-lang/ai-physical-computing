## 이 프로젝트에서 할 일

IV단원에서 얼굴로 움직이는 마우스를 만들고, 그 신호로 보드의 LCD, 서보모터, LED, 버저를 움직였어요. 이제 모둠이 우리 곁의 불편함을 직접 찾아서, 인공지능이 보고 판단하면 장치가 움직이거나 알려 주는 :용어[지능화 사물]을 만들어요. 예제를 그대로 따라 하는 것이 아니라, 문제를 고르는 일부터 모둠이 함께 정해요.

## 1단계 — 문제 찾고 정의하기

성취기준 [12인피04-02]의 "문제 발견과 정의"와 이어지는 단계예요. 먼저 "누가, 언제, 무엇 때문에 불편한가"를 찾아요. 교실, 집, 동네에서 직접 보고, 그 불편을 겪는 사람에게 물어봐요.

### 관찰하고 물어보기

| 질문 | 우리 모둠의 답 |
| --- | --- |
| 누가 불편한가요? | (예: 손을 다쳐 마우스를 잡기 어려운 친구) |
| 언제, 어디서 불편한가요? | |
| 지금은 어떻게 하고 있나요? | |
| 무엇이 바뀌면 좋을까요? | |
| 카메라로 알아차릴 수 있는 신호는 무엇인가요? | (예: 고개 방향, 눈 깜빡임, 손가락 수) |

### 문제 정의 문장 쓰기

찾은 내용을 아래 틀에 맞춰 한 문장으로 정리해요. 이것이 **문제 정의 문장**이에요.

> [누가]는 [언제] [무엇 때문에] [어떤 어려움]을 겪어요. 우리는 [무엇을 알아차리는 인공지능]과 [어떤 장치]로 [무엇]을 도울 거예요.

예를 들면 이렇게 쓸 수 있어요.

- 침대에 누워 지내는 사람은 스탠드 조명의 방향을 바꿀 때마다 다른 사람을 불러야 해요. 우리는 고개 방향을 알아차리는 인공지능과 서보모터로 조명을 스스로 돌릴 수 있게 도울 거예요.
- 손을 쓰기 어려운 친구는 발표 자료를 넘길 때 도움이 필요해요. 우리는 눈 깜빡임을 알아차리는 인공지능으로 자료를 넘기고, LED와 소리로 넘어갔다고 알려 줄 거예요.

### 주제 점검하기

:::주의[주제를 고를 때 피해야 할 것]
과목 교육과정은 "영상인식에 따른 개인정보 및 윤리적인 문제가 발생하는 주제는 피하도록" 안내해요. 아래 주제는 고르지 않아요.

- 얼굴로 **누구인지** 알아보는 주제(출석 체크, 출입 관리, 사람 찾기)
- 사람을 몰래 찍거나 영상을 저장하고 나누는 주제
- 표정이나 자세로 다른 사람의 기분, 성격, 집중도를 판단해 점수를 매기는 주제
- 다른 모둠이나 다른 사람의 기기와 네트워크(블루투스, 와이파이)에 연결하는 주제
- 레이저나 모터로 사람을 겨누거나 다치게 할 수 있는 주제
:::

피해야 할 주제도 방향을 바꾸면 좋은 주제가 될 수 있어요. 누구인지 알아보지 않고, 쓰는 사람이 스스로 켜고 끄며, 영상을 남기지 않게 바꿔요.

| 피할 주제 | 이렇게 바꿔 봐요 |
| --- | --- |
| 얼굴로 출석을 저절로 체크하기 | 손을 들면 "발표할게요" LED가 켜지는 알림판(누구인지는 알아보지 않아요) |
| 수업 중 조는 친구 찾아내기 | 내가 켰을 때만 도는 "눈 쉬기 알림"(기록을 남기지 않아요) |
| 친구의 표정으로 기분 점수 매기기 | 내가 고른 손 모양으로 기분을 알리는 "기분 신호등" |

## 3단계 — 만들고 시험하기

성취기준 [12인피04-03]과 이어지는 단계예요. 한꺼번에 만들지 말고 작은 부분부터 하나씩 시험해요.

### 작은 것부터 시험하기

1. 컴퓨터 쪽만: 영상처리 실습실에서 카메라(없으면 재생 입력)로 신호가 잘 잡히는지 봐요.
2. 보드 쪽만: ESP32 실습실의 '블루투스(BLE) 조작' 칸에서 약속한 글을 직접 보내 장치가 맞게 움직이는지 봐요.
3. 둘을 함께: 4단원 통합 실습실에서 두 코드를 함께 돌려요.
4. 실물로: 보드와 부품이 있으면 [실제 보드] 탭으로 같은 코드를 올려요. 없으면 가상 보드로 끝까지 해도 돼요.

## 4단계 — 영향 점검하고 고치기

성취기준 [12인피04-04]의 "사회적 영향을 생각한 점검과 개선"과 이어지는 단계예요. 만든 사물을 많은 사람이 쓴다면 누구에게 좋고, 누구에게 불편하거나 위험할지 따져 봐요. "아니오"가 나온 줄은 3단계로 돌아가 고쳐요.

| --- | --- | --- |

| 누구인지 알아보는 기능(얼굴 식별)이 없나요? | | |
| 쓰는 사람이 직접 켜고 끌 수 있고, 카메라가 켜져 있는지 알 수 있나요? | | |
| 블루투스 이름에 이름, 학번 같은 개인정보가 없고, 다른 모둠의 기기에 연결하지 않나요? | | |
| 잘못 알아봤을 때(예: 저절로 깜빡였는데 클릭됨) 곤란한 일이 없나요? 되돌릴 방법이 있나요? | | |

### 주의 문구 만들기

고칠 수 없는 점은 쓰는 사람에게 알릴 주의 문구로 만들어요. 예를 들어 "이 장치는 영상을 저장하지 않아요. 조명이 어두우면 클릭이 잘 안 될 수 있어요."처럼 써요.

## 5단계 — 발표하고 돌아보기

발표는 문제 정의 → 만든 것 시연 → 점검표와 고친 점 → 배운 점과 아쉬운 점 순서로 해요. 실물이 없으면 가상 보드와 4단원 통합 실습실 화면으로 시연해도 돼요.

### 돌아보기

발표가 끝나면 스스로 돌아봐요.

- 모둠에서 내가 맡은 일과 실제로 한 일은 무엇인가요?
- 가장 어려웠던 문제는 무엇이었고, 어떻게 풀었나요?
- 점검에서 찾은 문제를 어떻게 고쳤나요? 다시 만든다면 무엇을 바꾸고 싶나요?

학교의 평가 계획과 시간에 맞춰 줄이거나 늘려요. 4-2-2까지 마친 뒤를 기준으로 했어요.

1. 1차시(문제 찾기): 관찰 과제와 짝 인터뷰로 불편 찾기 → 주제 점검(피할 주제) → 문제 정의 문장 쓰기. 모둠마다 주제를 교사와 한 번 확인해요.
2. 2차시(계획): 역할 나누기, 통신 약속(머리말, 칸 수, 빠르기) 정하기, 계획표 쓰기.
3. 3\~5차시(만들고 시험하기): 컴퓨터 쪽 → 보드 쪽 → 함께 → 실물 차례로. 5차시 끝에 모둠마다 5분 중간 시연을 하고 서로 한 가지씩 제안해요.
4. 6차시(영향 점검): 점검표를 채우고 "아니오"인 줄을 고쳐요. 다른 모둠의 점검표를 한 번 바꿔 읽어요.
5. 7차시(발표와 돌아보기): 모둠 발표, 동료 평가, 돌아보기 글과 기록 제출.

### 자주 막히는 곳

- 주제가 너무 커요. "한 사람, 한 장면, 한 동작"으로 줄이게 해요(예: "모든 장애인을 돕는 로봇" → "손을 다친 친구가 발표 자료를 넘기는 장치").
- 얼굴 인식 주제가 사람 알아보기로 흘러가요. 얼굴의 점(랜드마크)으로 움직임만 쓰고, 누구인지는 알아보지 않게 짚어 줘요.
- 한 학생이 코드를 다 써요. 단계마다 역할을 바꾸고, 기록 담당이 누가 무엇을 했는지 적게 해요.
- 실물 부품이 모자라요. 가상 보드와 4단원 통합 실습실로 끝까지 할 수 있어요. 실물은 발표 시연용으로 한 벌만 써도 돼요.
- 교실에서 블루투스 이름이 겹쳐요. 4-1-4의 이름 규칙(자리 번호, 개인정보 빼기)을 먼저 정하게 해요.
- 4단원 통합 실습실이 느려요. 파이썬을 두 벌 돌리는 화면이라, 다른 탭을 닫거나 한쪽씩 따로 시험하게 해요.
- 생성형 AI로 코드를 통째로 받아 와요. 받은 부분을 표시하고, 줄마다 무슨 뜻인지 모둠이 설명할 수 있어야 쓰게 해요.
