## 학습목표

- 처음 몇 장의 코 위치를 평균 내 기준점을 잡는 까닭(보정)을 설명할 수 있어요.
- 코가 기준점에서 움직인 거리를 비례식으로 화면 좌표로 바꾸고, 화면 밖으로 나가지 않게 제한할 수 있어요.
- PyAutoGUI로 마우스 커서를 옮기는 프로그램을 실행하고 움직임 범위를 바꿔 감도를 조절할 수 있어요.

## 왜 배울까

마우스를 손으로 잡기 어려운 사람도 고개만 조금 돌려 커서를 옮길 수 있다면 컴퓨터를 훨씬 편하게 쓸 수 있어요. 앞 차시에서 찾은 코 점이 움직인 만큼 커서를 옮기면 그런 '손 없는 마우스'가 돼요. 3-1-4에서는 검지 끝의 위치로 커서를 옮겼는데, 이번에는 얼굴의 코가 움직인 거리로 옮겨요.

## 핵심 개념

### 제목은 '눈길'이지만 따라가는 것은 코예요

차시 제목은 "눈길 따라 움직이는 마우스 커서"지만, 이 코드는 눈동자가 어디를 보는지를 재지 않아요. 앞 차시의 6번 점(두 눈 사이 콧등)을 '코'로 부르며 그 위치로 커서를 옮겨요. 보고 싶은 쪽으로 고개를 돌리면 코도 그쪽으로 움직이니, 결과적으로 눈길을 따라가는 것처럼 보여요.

화면은 `cv2.flip(frame, 1)`로 거울처럼 뒤집어요. 그래야 내가 고개를 오른쪽으로 돌렸을 때 화면 속 코도 오른쪽으로 움직이고, 커서도 오른쪽으로 가요.

### 기준점 잡기(보정)

사람마다 카메라 앞에 앉은 자리와 얼굴 위치가 달라요. 그래서 프로그램은 먼저 지금 내 얼굴의 가운데가 어디인지 재요. 이렇게 쓰기 전에 기준값을 재서 맞추는 일을 :용어[보정](캘리브레이션, calibration)이라고 해요.

이 코드는 처음 30장 동안 찾은 코 위치의 평균을 기준점으로 삼아요. 평균은 장마다 새로 고쳐 계산해요. 실습실은 1초에 15장 안팎을 처리해서 30장이면 2초쯤 걸려요(컴퓨터가 느리면 더 걸려요). 기준점을 잡는 동안에는 화면 아래에 `Calibrating... 1/30`부터 `30/30`까지 글자가 올라가요.

<figure>
<img src="/images/lessons/4-1-2/calibration.svg" alt="영상 칸에 장마다 찾은 코 위치가 초록 점으로 조금씩 흩어져 있고 그 평균 자리에 파란 십자(기준점)가 있으며, 오른쪽에 새 평균 = (지금 평균 × 센 장 수 + 새 값) ÷ (센 장 수 + 1) 식과 (300 × 2 + 306) ÷ 3 = 302라는 예가 적힌 그림" width="640" height="320">
<figcaption>코는 가만히 있어도 장마다 조금씩 흔들려요. 여러 장의 평균을 기준점(파란 십자)으로 쓰면 한 장의 흔들림에 덜 휘둘려요. 사이트가 직접 그린 그림이에요.</figcaption>

### 움직인 만큼 옮기기 — 비례식

기준점이 잡히면 장마다 코가 기준점에서 가로, 세로로 얼마나 움직였는지 계산해요(`move_x`, `move_y`). 그다음 이 거리를 화면 좌표로 바꿔요.

```python
mouse_x = move_x / face_move_range_x * screen_width + screen_width // 2
mouse_y = move_y / face_move_range_y * screen_height + screen_height // 2
```

화면 너비가 1920이고 `face_move_range_x`가 60이면 이렇게 돼요.

| 코가 움직인 거리(가로) | 계산 | 커서의 x 좌표 |
| --- | --- | --- |
| 0픽셀(그대로) | 0 ÷ 60 × 1920 + 960 | 960(가운데) |
| 오른쪽으로 15픽셀 | 15 ÷ 60 × 1920 + 960 | 1440 |
| 오른쪽으로 30픽셀 | 30 ÷ 60 × 1920 + 960 | 1920 → 화면 안으로 1919 |
| 왼쪽으로 30픽셀 | -30 ÷ 60 × 1920 + 960 | 0(왼쪽 끝) |

곧 코를 좌우로 30픽셀씩만 움직여도 커서가 화면 끝에서 끝까지 가요. 세로는 `face_move_range_y`가 30이라 위아래로 15픽셀만 움직여도 화면 끝에 닿아요.

<figure>
<img src="/images/lessons/4-1-2/nose-to-cursor.svg" alt="위쪽 눈금은 코가 기준점에서 움직인 거리 -30, -15, 0, +15, +30픽셀이고 아래쪽 눈금은 화면 좌표 0, 480, 960, 1440, 1920이며, 점선이 -30은 0, 0은 960, +15는 1440, +30은 1920에 잇고, 아래에 화면 x = 움직인 거리 ÷ 60 × 1920 + 960 식이 적힌 그림" width="640" height="380">
<figcaption>움직인 거리를 60으로 나눈 비율만큼 화면 너비를 곱하고, 가운데(960)에서 출발해요. 사이트가 직접 그린 그림이에요.</figcaption>
</figure>

### 화면 밖으로 나가지 않게

계산한 좌표가 0보다 작거나 화면 너비(1920) 이상이면 커서를 화면 끝에 붙잡아 둬요. `max(0, min(screen_width - 1, mouse_x))`는 "0과 1919 사이를 벗어나면 가까운 끝값으로 바꾼다"는 뜻이에요. 예를 들어 -200은 0이 되고, 2500은 1919가 되고, 800은 그대로 800이에요.

### PyAutoGUI로 커서 옮기기

PyAutoGUI는 파이썬으로 마우스와 키보드를 움직이는 :용어[라이브러리]예요. 실습실에서는 진짜 마우스 대신 실습실 안의 **가상 데스크톱** 커서가 움직여요(화면 크기 1920×1080).

| 코드 | 뜻 |
| --- | --- |
| `pyautogui.FAILSAFE = False` | 원래는 커서가 화면 왼쪽 위 모서리(0, 0)에 닿으면 프로그램을 멈추는 안전장치가 있어요. 코가 끝까지 가도 멈추지 않게 이 장치를 껐어요. |
| `pyautogui.PAUSE = 0.01` | PyAutoGUI 명령을 한 번 할 때마다 쉬는 시간이에요. 기본값 0.1초면 커서가 뚝뚝 끊겨서 0.01초로 줄였어요. |
| `pyautogui.size()` | 화면의 가로, 세로 크기를 알려 줘요. |
| `pyautogui.moveTo(x, y)` | 커서를 (x, y)로 옮겨요. |

:::주의
안전장치를 끈 코드를 진짜 컴퓨터에서 돌리면 커서가 얼굴을 따라 계속 움직여서 멈추기 어려워요. 진짜 컴퓨터에서 돌릴 때는 OpenCV 창을 눌러 초점을 준 뒤 q 키를 눌러 끝내요.
:::

## 따라하기

코로 가상 데스크톱의 커서를 움직여 봐요. 웹캠이 없거나 얼굴을 비추고 싶지 않으면 입력 소스에서 '재생 입력(합성 좌표)'을 고르고, 재생 동작을 '고개 돌리기'로 골라요. 합성 얼굴이 고개를 천천히 좌우로 돌려요.

### 코드 읽기

코드가 길지만 주석의 큰 번호(1\~5)와 작은 번호(4-1\~4-9)를 따라 읽으면 돼요.

- 10\~11행: 안전장치를 끄고, 명령마다 쉬는 시간을 0.01초로 줄여요.
- 17\~18행: 화면 크기를 읽어 콘솔에 찍어요.
- 21\~22행: 움직임 범위를 가로 60, 세로 30으로 정해요.
- 25\~27행: 기준점(`reference_center`), 기준점을 잡을 장 수(30), 지금까지 센 장 수를 준비해요.
- 34\~39행: 얼굴은 1개만, 눈동자까지 찾는 페이스 메시를 만들어요.
- 57행: 화면을 거울처럼 뒤집어요.
- 74\~76행: 6번(코), 468번, 473번(두 눈동자) 점을 꺼내요. 86\~87행: 코를 픽셀 좌표로 바꿔요.
- 102\~115행: 처음 30장 동안 평균을 고쳐 가며 기준점을 잡고, 화면 아래에 `Calibrating...`을 써요.
- 120\~136행: 기준점에서 움직인 거리를 화면 좌표로 바꾸고, 화면 밖이면 끝값으로 고친 뒤 `pyautogui.moveTo()`로 커서를 옮겨요.
- 139\~140행: 기준점을 파란 십자로 표시해요. 145\~160행: 좌표를 화면 왼쪽 위에 글자로 써요.
- 175\~182행: q 키는 끝내기, r 키는 기준점을 다시 잡기예요.

### 실행하고 결과 보기

1. [이 자리에서 실습실 열기]를 누르고 [실행]을 눌러요.

3. 기준점이 잡히면 파란 십자가 나타나요. 고개를 좌우로 돌리면 실습실 아래 가상 데스크톱의 커서가 같은 쪽으로 움직이고, 지나간 자리가 주황 점으로 남아요.
4. 출력 화면을 누르고 r 키를 누르면 기준점을 다시 잡아요. q 키를 누르면 끝나요.

```text

```

실행 중에 r 키를 누르면 가운데에 `기준점을 다시 설정합니다...`가 한 줄 더 찍혀요.

:::확인
- 콘솔에 화면 크기 `1920 x 1080`이 나와요.
- 처음 약 2초 동안 `Calibrating...` 글자가 30/30까지 올라가고, 그동안 커서는 가운데(960, 540)에 머물러요.
- 기준점이 잡힌 뒤 고개를 돌리면 가상 데스크톱의 커서가 같은 쪽으로 움직여요.
:::

:::왜그럴까
기준점을 잡는 동안에는 120행의 `else` 쪽으로 가지 않아서 `moveTo()`가 한 번도 불리지 않아요. 그래서 커서가 처음 자리인 화면 가운데에 머물러요.

기준점이 잡힌 뒤에는 장마다 `move_x`를 계산해요. 코가 기준점에 있으면 0이라 커서가 가운데(960)에 있고, 오른쪽으로 갈수록 커서도 오른쪽으로 가요. 30픽셀을 넘으면 계산 결과가 화면 밖이라 1919에 붙어 있어요.
:::

:::왜그럴까[왜 숫자를 키우면 커서가 덜 움직일까?]

:::

:::오류
함수 이름을 `pyautogui.moveto()`처럼 소문자로 쓰면 `AttributeError: module 'pyautogui' has no attribute 'moveto'`가 나요. 파이썬은 대소문자를 구별하니 `moveTo`로 고쳐요. 실습실 콘솔도 "함수 이름은 대소문자를 구분해요"라고 알려 줘요. 자세한 풀이는 [오류 사전](/help/errors/#attribute-error-module)에 있어요.
:::

## 도전 과제

::::도전[도전 과제 1: 작은 떨림은 무시하기]
코는 가만히 있어도 조금씩 흔들려서 커서가 떨려요. 기준점에서 3픽셀보다 적게 움직였으면 움직이지 않은 것으로 보도록 코드를 고쳐 보세요. 이렇게 무시하는 좁은 구간을 '데드존'이라고 해요. 고친 뒤 3픽셀이 화면에서는 몇 픽셀인지도 계산해 적어요.

:::힌트
122\~123행 바로 아래에 `if abs(move_x) < 3:`와 `move_x = 0`을 넣고, `move_y`도 같은 모양으로 넣어요. 들여쓰기는 122행과 같게 맞춰요. 화면에서는 3 ÷ 60 × 1920 = 96픽셀이에요.
:::
::::

::::도전[도전 과제 2: 가로와 세로 감도 맞추기]
지금은 가로 범위가 60, 세로 범위가 30이라 위아래로 움직일 때가 더 민감해요. 두 값을 바꿔 가며 내가 쓰기 편한 값을 찾고, 그 값을 고른 까닭을 한 문장으로 적어 보세요. 웹캠이 없으면 재생 입력 '고개 돌리기'로 가로 범위를 맞춰요. 재생 입력에는 고개를 끄덕이는 동작이 없으니, 세로 범위는 식으로 따져 봐요: 코가 기준점에서 10픽셀 내려갈 때 커서가 몇 픽셀 움직이는지 세로 범위 30과 60에서 각각 계산해 적어요.

:::힌트
화면은 가로 1920, 세로 1080이라 가로가 더 넓어요. 고개를 끄덕이는 폭은 좌우로 돌리는 폭보다 작은 경우가 많아요. 커서가 화면 끝에 너무 쉽게 붙으면 범위를 키우고, 끝까지 잘 안 가면 범위를 줄여요. 세로 계산은 127행의 식 `mouse_y = move_y / face_move_range_y * screen_height + screen_height // 2`를 써요. 화면 세로가 1080이면 코가 10픽셀 내려갈 때 범위 30에서는 540에서 900으로, 범위 60에서는 720으로 가요.
:::
::::

### 자주 막히는 곳

- 기준점을 잡는 약 2초 동안 커서가 움직이지 않아 "안 된다"고 생각해요. 화면 아래 `Calibrating... n/30`을 가리켜 주세요.
- 기준점을 잡는 동안 고개를 움직이면 기준점이 틀어져 커서가 한쪽으로 쏠려요. 가만히 있다가 r 키로 다시 잡게 해요.
- r, q 키가 먹지 않으면 출력 화면을 먼저 눌러 초점을 줘요(출력 칸 아래의 [q], [r] 버튼도 돼요).
- 20행 주석("숫자가 클수록 민감함")은 실제 동작과 반대예요. 바꿔보기 1로 직접 확인하게 해요.
- 실습실은 1초에 15장 안팎을 처리해서, 주석의 "30프레임 = 1초 정도"(1초에 30장을 찍는 카메라 기준)보다 기준점을 잡는 시간이 길어요.
- 진짜 컴퓨터에서 원본을 돌릴 때는 `FAILSAFE = False` 때문에 커서가 계속 얼굴을 따라가요. OpenCV 창을 눌러 q로 끝내도록 미리 알려 주세요.
